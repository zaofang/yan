## 11. Yan: numbers, arrays, units and tables

Shape and unit errors are type errors. All shape-label and unit information MUST be erased before code generation.

### 11.1 Floating point and the math library

- **No floating-point environment.** There is no global rounding mode and there are no exception flags. Directed rounding is an explicit argument: libm functions and `add`, `sub`, `mul`, `div`, `sqrt` and `fma` take `round: Round = NearestEven()`; a constant argument is specialized at compile time.
- **libm scope.** The bundled libm covers the full C23 7.12 list and is correctly rounded in all four rounding modes for `f16`, `bf16`, `f32` and `f64`. `f16` and `bf16` results are correctly rounded directly, not by way of `f32`. Arithmetic on `f16` and `bf16` rounds after each operation. `f128` is software (section 3.2).
- **Integer powers (R657).** `x ** n` with `x` a float and `n` of any integer type is C23 `pown(x, n)`, correctly rounded in each binary float format; `x ** y` with two floats is `pow`. `x ** n` with a `bigint` `x` and an `int` `n >= 0` is a `bigint` (R836).
- **Determinism tiers.** Every math API declares a tier. **E**: correctly rounded. **R**: a specified algorithm, bitwise reproducible across platforms, threads, SIMD widths and backends; tier-R algorithms are pinned by `math_edition` in `yan.lock`. **F**: opt-in, through `@fast_math`, `@unordered` or vendor bindings, under `nondet`.
- **Reductions.** `sum` and `dot` use the reduction order of 9.3 (R382). `sum_exact` and `dot_exact` are correctly rounded (superaccumulator). `math.fsum` is the Python name of `sum_exact`, and `sum(exact = true)` gives the exact sum in `ColExpr` reductions and query aggregates (R630). `matmul` accumulates sequential fma chains over a fixed `kc` and splits k only at nodes of a fixed tree.
- **Accuracy lint (R613).** W852 flags a float expression in a pure function whose error, measured on inputs sampled with a seed derived from the item hash and narrowed by `pre` clauses, exceeds the lint threshold. Its fix is the rewrite with the lowest measured error, found by e-graph search.
- **FMA baseline.** Release targets require hardware FMA (x86-64-v3, ARMv8). Other targets use a correctly rounded software fma.
- **Random numbers (R377).** The default seeded generator is ChaCha8 by task path (7.7): `rand = seeded(seed)` gives every task its own stream, so `main` and each `par` branch draw deterministically. `seeded(Pcg64Dxsm, seed)` must be named, gives one stream and is not splittable, so using it in two branches that may run at once is E402. Both algorithms are versioned so seeded streams never change.

### 11.2 Array types

`Array[a1, ..., an, T]` lists axes, then a numeric element type. Each axis is positional (a `Nat`: literal or size variable) or labelled (any type whose values are coordinates, such as `PlainDate` or `Str`).

**Shape checking.**

- Labelled axes match as a set keyed by label; their written order is irrelevant to checking but fixes the memory order.
- Positional axes match as an ordered list and must agree exactly.
- Size variables are solved by unification. Any not solved statically are checked once, at entry to the function that introduces them (panic `shape`).

**Broadcasting by name.** For elementwise operations, the result's labelled axes are the union of the operands' labelled axes, and each operand is broadcast along axes it lacks. Positional axes broadcast only against scalars (E520 otherwise). `positional(x)` drops labels in memory order; `label(x, A, B, ...)` attaches them.

**Indexing.** `x[A: i]` selects along labelled axis `A` by position (integer) or by coordinate (a value of type `A`). Positional axes index by integer. Ranges `a..b` slice. Slices, transposes and broadcasts are strided views (4.5) and never alias mutable data. Indexing follows the rule for undecided goals (8.6): a refuted index is E501, and an index that cannot be proven compiles to a bounds check (with lint W820 in Yan Agent).

**Representation.** `Buffer` pointer, shape and strides, row-major by default. Coordinates of a labelled axis are stored once as an index array beside the buffer.

**Fusion.** Within one statement, elementwise operations and the reductions consuming them MUST be fused into a single loop nest. Loops whose body has no capabilities SHOULD be vectorized.

**Index equations (R263).** `math.ein(eq, operands...)` takes a stage-0 string such as `"C[i, k] = A[i, j] * B[j, k]"`, checks it against the operands' axes, and emits a loop nest, or a call to a matching kernel (GEMM, GEMV, batched dot product, transpose). An index that appears only on the right is summed over, and `max_j`, `min_j` and `prod_j` name the other reductions. Index letters bind labelled axes, and a label mismatch is a stage-0 diagnostic. Sizes the solver cannot prove equal add one `LengthMismatch` check before the loops. `into: c` writes into a destination; otherwise the result allocates, with a `try_ein` sibling. Loop order and tiling are chosen at stage 0 and can be overridden with `@schedule`. Reduction order is fixed, and `par: true` splits only over non-reduced indices, so results are deterministic. **Sparse operands (R615).** `Array` takes a storage format as a type argument, per dimension dense, compressed or singleton (`Sparse[Csr, f64]` and similar). `math.ein` specializes at stage 0 into co-iterating loops over its operands' formats, keeping the reduction order above. The formats may ship first in an `@yan` package.

**Access patterns (R627).** `@access(...)` on an `extern` function, a `@kernel` function or an engine item (R568) states, for each array parameter and the result, the region one output tile reads or writes: `elementwise`, `rows(axis)`, `cols(axis)`, `tile(M, N)` or `whole`. With that alone the optimizer MAY fuse a producer or consumer loop, an `ein` equation or a `ColExpr` into the call without seeing the body, as Fern does (PLDI 2025). When the body is available the checker verifies the claim, and an access outside the declared region is E274. On an `extern` function the claim is trusted, and `yan audit` lists it. **Binding (R952).** `@access(name: region, ...)` has one entry per array parameter, in any order, and the reserved name `out` for a non-unit result; each appears exactly once and no other parameter is named. `rows(axis)` and `cols(axis)` take an integer literal below the operand's rank, `tile(M, N)` positive integer literals. Any other claim is E284, reported before a body is read. **Kernel bodies (R953).** `@kernel(tile: M, N)` declares the tile shape and the function takes one `TileOrigin` parameter, a record with an `int` per tile axis (`at.i0`, `at.i1`) naming the origin of the program instance's output tile; the launch supplies it and user code cannot construct one. A `@kernel` decorator other than `tile:` with positive integer constants, a function without exactly one `TileOrigin` parameter, or one without an `@access` claim is E285; calling a `@kernel` function or building a `TileOrigin` outside `gpu.launch`, or launching anything but a `@kernel` function by name, is E286 (R983). The body reads and writes `Array` elements (`a[at.i0 + i, at.i1 + j]`). **Verification (R954).** The checker proves each access inside the region of its operand, an `out` access in the write region and any other in a read region. An index is provable when it is affine over integer literals, comptime constants, the `TileOrigin` fields and loop variables of `for` loops with affine literal bounds, with `e / c` and `e % c` for a positive literal `c`; the proof uses the 8.6 solver. An access that cannot be proved is E274 and names the reason, and there is no run-time check. An index outside the array is E501. **Regions (R955).** Relative to origin `t` and tile shape `T`: `elementwise` is `t_k + i_k` with `0 <= i_k < T_k` on every axis; `rows(a)` and `cols(a)` bound axis `a` to `[t_a, t_a + T_a)` and leave other axes free; `tile(M, N)` bounds both axes to the `M x N` block containing `t`; `whole` bounds nothing. `rows`, `cols` and `tile` take an optional `halo: h`, a non-negative integer literal, which widens each bounded axis by `h` on each side. `elementwise`, `whole` and `out` take no halo, and a malformed halo is E284. The halo holds on `extern` claims too, and Core spells it as a named argument, `rows(0, halo = 1)` (R982).

### 11.3 SIMD

`Vec[N, S]` is a fixed-width SIMD vector of scalar `S` in `std.simd` (R386). Lane arithmetic, comparisons, masks, `select`, lane reductions, constant shuffles, and loads and stores through a `View` or `MutView` with a checked base are safe and belong to L4 (Yan only). Target-specific intrinsics stay L6 and legal only inside `unsafe`. None is available at stage 0. `@multiversion("x86-64-v4", "x86-64-v3", ...)` compiles a function once per listed target and selects one at process start; all versions MUST give identical results, which strict IEEE lane operations guarantee, and an approximate intrinsic needs `nondet`. W821 flags a `@multiversion` function whose versions compile to the same code. Portable code may still rely on fusion and vectorization (11.2). `@vectorize` (R624) makes lane execution of `par for` bodies a proof obligation.

### 11.4 Units

`Quantity[T, D]` pairs a numeric type with a dimension.

- A dimension is a rational exponent vector over base dimensions: `length`, `mass`, `time`, `current`, `temperature`, `amount`, `luminosity`, `information` (bytes), plus one per declared currency.
- A unit is a dimension plus a compile-time exact rational scale. Units MUST be declared (`unit km = 1000 * m`); std declares SI units, data sizes, `pct` (0.01), `bp` (0.0001) and durations from `ns` to `day`.
- Addition and comparison require equal dimensions (E530). Multiplication and division combine dimensions. Conversion between units of one dimension is explicit (`to(x, km_per_h)`); the scale factor is folded at compile time.
- `QuantityPoint` is an affine quantity (temperatures, positions): point minus point is a quantity, point plus quantity is a point, and point plus point is E530.
- Quantity kinds distinguish quantities of one dimension that must not mix (torque and energy).
- Each currency is its own base dimension; converting between currencies requires an explicit rate of type `Quantity[float, eur / usd]`.

### 11.5 Automatic differentiation

`grad`, `jvp`, `vjp`, `jacobian` and `hessian` apply to pure functions (no capability besides `sched`); differentiating an impure function is E319. `@derivative(f)` defines a custom rule. Forward mode ships first as a dual-number library; reverse mode is a transform on checked Yan Core after monomorphization and inlining, derived as linearize then transpose: forward mode, partial evaluation that splits off the linear part, then transposition of that part (R614). Each primitive needs only its forward rule, which is what `@derivative(f)` defines, and the interpreter, stage 0 and every code generator compute the same gradients. The intrinsics are an M4 preview.

### 11.6 Time

`Instant`, `Duration` and `MonoInstant` are i128 nanoseconds; `Duration` is `Quantity[i128, ns]` and exact. Until units are implemented, `Duration` is an opaque type over i128 nanoseconds with the API of 17.5, which it keeps as a `Quantity` (R593). Every time type covers years -9999 to 9999; leaving the range is overflow and panics with kind `overflow` (operators panic, `checked_` forms return None). `Period` holds only years, months, weeks and days with one sign; calendar differences return `(Period, Duration)`; `Instant + Period` and `PlainDate + Duration` are type errors. `ZonedDateTime` has structural equality (instant and zone) and no ordering; order by `.instant`. Bundled zones and `ZonedDateTime` are in `core`. The full API is section 17.5.

### 11.7 Decimal and money

`dec128` is IEEE 754-2008 decimal128. Rounding defaults to half-even, and division and `quantize` take an explicit `RoundingMode`. Decimal literals are exact, and there is no implicit conversion between floats and decimals. `Money` is `Quantity[dec128, Currency]`: amounts in different currencies do not add, and conversion takes an explicit rate. ISO 4217 minor units come from a table pinned in `yan.lock`. `std.decimal` declares one currency unit per ISO 4217 code, named by the code in lower case (`usd`, `eur`, `jpy`), each its own dimension of type `Currency`. A `Money` value is written as a unit quantity, `12.50usd` in Yan and `12.50 * usd` in Yan Agent, and its number is read exactly as a `dec128`, never through a float; a computed amount is `money(d, c)` for a `dec128` `d` and a `Currency` `c`, and `m.amount` and `m.currency` read it back (R653). The columnar fixed-point type is `Decimal(p, s)` (11.8).

### 11.8 Columnar memory

`alloc` owns `Buffer` and `Bitmap`, shared with `Array`. `std.arrow` is the Arrow columnar format with view, dictionary and run-end encodings and the C Data and C Stream interfaces. `StringView` is the default string column. A field typed `T | None` is a nullable column; other fields carry no validity bitmap, and `is_null` on a non-optional column is E544. Arrow `Timestamp` columns that Yan creates default to microseconds; nanoseconds are opt-in; reads keep the file's unit.

### 11.9 Tables

`Table[R]` stores record type `R` column by column in the Arrow layout. `List[R]` stores the same records row by row, with the same operations as eager functions.

- **std engine.** `Table[R]` operations (`filter`, `select`, `with_columns`, `group_by`, `agg`, `join`, `pivot`, `sort`) are eager vectorized kernels, push-based and morsel-driven (2048-row vectors, 65536-row morsels), executed under `sched`. `pivot` produces a labelled `Array` whose axes are the types of the pivot columns. Lazy plans, the optimizer, streaming, SQL and `explain` live in `@yan/frame`, which adds `.lazy()` through the dot form and the typed `LazyFrame[R]` and `LazyFrame[Dyn]` plans.
- **Deterministic queries.** Query results, including float aggregates and row order, MUST NOT depend on thread count, ISA or memory budget. Morsel boundaries depend only on the input, partials merge in index order, `group_by` emits first-appearance order and `sort` is stable. `@unordered` relaxes order only.
- **Query arithmetic.** Integer overflow and failed strict casts inside a query end it with `fail QueryError`. Wrapping, saturating and widening forms are explicit expressions.
- **Query compilation.** A `LazyFrame[R]` plan whose shape is a stage-0 constant is compiled in release builds by specializing the tier-1 executor on it (first Futamura projection), so its results equal tier-1 execution bit for bit by construction; debug builds interpret it. `LazyFrame[Dyn]` and run-time plans stay on tier 1. No Yan program generates machine code at run time.
- **Limits and windows (R553).** `@yan/frame` adds `head(n)` and window expressions `e.over(partition_by=[...], order_by=[...])` with `row_number`, `rank`, `dense_rank`, `lag(e, k)`, `lead(e, k)`, `cum_sum`, `cum_count`, `cum_min` and `cum_max`. Order within a partition is the stable sort, ties keep input order, and the determinism rule above applies. Top N per group is `filter(row_number().over(...) <= n)`.
- **Incremental views (R625).** `@yan/frame` adds `q.incremental()` on a `LazyFrame[R]` plan whose shape is a stage-0 constant. It returns a `View[R]` whose `apply(delta)` takes inserted and deleted rows for each source and updates the result in time proportional to the change: the plan compiles to a DBSP circuit over Z-sets (VLDB 2023), and every plan operator, joins, `group_by` and windows included, has an incremental form. Float `sum` and `mean` in a view are exact (R630), so deletion is exact. After any sequence of `apply`, `v.result()` MUST equal the plan run on the updated sources with exact sums, and the conformance oracle checks this by rerunning. The engine is the `yan-dbsp-engine` crate beside `yan-rt` (R576).
- **Spilling.** Query spilling uses the `tmp` capability and nothing else.
- **Schema-generated tables.** `yan schema gen data.parquet` writes the row record type as ordinary Yan Agent source plus the schema's hash. The output is checked in, and compilation never reads data files or the network to resolve a type. At run time, a file whose Arrow schema differs from the generated one is `fail SchemaMismatch`, carrying a column-level diff. Parquet I/O lives in `@yan/parquet`; std keeps `read_csv`. **Output (R937).** `yan schema gen <file>` reads only the Parquet footer and prints `# schema blake3:<hash>` then `class <Stem>Row:` with one field per column: `bool`, `int` (INT32, INT64), `float`, `str` (UTF8, ENUM, JSON) or `bytes`, and `T | None` for an optional column. The hash is blake3 of `yan schema 1`, a NUL byte and the field lines. A nested, repeated, INT96 or non-identifier column ends with exit code 1 and a message.
