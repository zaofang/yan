## 17. Standard library

The standard library is written in Yan Agent wherever possible, with intrinsics for the rest, and every unsafe block in it is tested under `yan test --ub` (6.9). Names below are in Yan Agent spelling. This is the normative minimum; the full module list, tiers and milestones are the Yan Core standard library roadmap (https://claude.ai/artifact/HL2DZtHxuCaLofedMN4tT5), whose M1 row is the M1 subset. The implementer MAY add functions but MUST NOT change these signatures without a `SPEC_QUESTIONS.md` entry. Every `pub` std item carries `@since` (20.3).

**Intrinsics (R474).** A std function whose body cannot be written in Yan Agent is declared as `@intrinsic def name(params) -> T: ...`, a full signature with `...` as its body. Each implementation (interpreter, Cranelift, LLVM) supplies the body by the function's Yan Core path. `@intrinsic` is reserved to the `std` package; anywhere else it is an unknown attribute. The intrinsics form a closed list kept in `yan-std`, and the Yan Core scalar intrinsics of section 3 (`add_checked_i64`, `eq_f64`, ...) are part of it.

### 17.1 Tiers and placement

| Tier | Contains | Needs |
| --- | --- | --- |
| `core` | scalars, `Option`, `Result`, traits, `View`, iterators, `core.ffi`, atomics, `math`, units, bundled zones and `ZonedDateTime`, formatting into a buffer | nothing |
| `alloc` | `Str`, `List`, `Map`, `Set`, collections, `Rc`, `Arc`, `Soa`, `Pool`, `Buffer`, `Bitmap`, allocators, `Array`, `Table` kernels | the `alloc` capability |
| `std` | OS handlers for every built-in capability, `fs`, `net`, `proc`, `env`, `signals`, `py`, record and replay | a hosted platform |

**Source layout (R562).** `yan-std/lib/` has one directory per tier, `core/`, `alloc/` and `std/`. A module's tier is the directory its files live in; module paths do not change (`std.list`), and a module that imports from a higher tier is rejected. A module's public API is written in Yan Agent when it is inside the Yan Agent subset, so `yan sig` shows std in the surface agents write; bodies that need L4 to L6 (`unsafe`, `Ptr`, `RawCell`, extern blocks) are written in a `.yn` file of the same module. Each std intrinsic has one entry in the intrinsic registry (22.4, R561).

A module belongs in std only if it is shared vocabulary, a capability handler or needed by the M1 evaluation; if its target is frozen; and if one implementation beats many (security, determinism). Anything else is a first-party `@yan/*` package with its own semver and ceiling, included in ecosystem runs (20.7). First-party packages at 1.0 include `@yan/i18n` (ICU4X), `@yan/parquet`, `@yan/frame`, `@yan/adbc`, `@yan/sql`, `@yan/object_store`, `@yan/ecs`, `@yan/quic`, `@yan/http3`, `@yan/sqlite`, `@yan/postgres`, `@yan/otel`, `@yan/markdown`, `@yan/html`, `@yan/websocket`, `@yan/yaml`, `@yan/cbor`, `@yan/msgpack`, `@yan/protobuf`, `@yan/grpc`, `@yan/fancy_regex`, `@yan/rand_distr`, `@yan/blas`, @yan/rel, @yan/fasthash and the compression codecs.

**Embedded and GPU profiles (R320 to R329).** Accepted 2026-10-31 from the embedded and GPU profiles design (https://claude.ai/artifact/4vauJ4fyd3eUSTWJqXhiTx).

**Profiles (R320).** A profile is a named, closed set of restrictions enforced by the checker over the transitive call graph, like a capability ceiling. A profile MUST NOT change the meaning of any program that passes it. `profile = "embedded"` in `package.yag` applies to the whole program and implies platform `freestanding`, the stack bound of R321, no implicit `alloc` handler and `@forbid(rc)` unless the program binds a heap. `@kernel` on a function applies the `kernel` profile to it and its callees: no capability other than the tile intrinsics, `@forbid(alloc, rc)`, no recursion, no `dyn`, no `extern`, and only GPU-representable types (scalars, `Vec`, records of those, `f16`, `bf16`). A violation is E320, naming the profile and the rule. Profiles add attributes only (`@kernel`, `@interrupt`, `@task`, `@stack`), never keywords. `yan check --profile p` checks a library against a profile without a target.

**Static stack bound (R321).** Under `embedded`, the compiler MUST compute a sound maximum stack depth for every task and report it in `yan build`. The call graph MUST be acyclic except for `become` tail calls (R260). An `extern` function called from embedded code needs `@stack(bytes)`, a trusted claim listed by `yan audit`. A `dyn` call counts the deepest impl that reaches it. Interrupt tasks add their frames only at their own priority level. An unprovable bound is E321; a bound that exceeds the manifest's stack reserve is E322.

**Peripherals and HAL (R322).** A chip package generates its register blocks at stage 0 from the vendor's CMSIS-SVD file read with `embed(path)`. Each register is a `Reg[T, access]` whose operations lower to `read_volatile` and `write_volatile` (6.8). `main` receives one owned `Peripherals` value, and splitting it moves each peripheral out once. Pin modes are typestates. `std.embedded.hal` defines one trait set (digital, SPI with shared-bus devices, I2C, delay, PWM, UART). Its waits go through the bound I/O handler (9.7), so one driver serves blocking and async firmware.

**Embedded scheduling (R323).** `std.embedded` provides two `sched` handlers. `srp` runs hardware tasks bound to interrupt vectors to completion on one stack under the Stack Resource Policy; each `Resource[T]` gets a priority ceiling computed at compile time, and `r.lock()` raises the running priority to that ceiling. `executor` runs `par concurrent` tasks as generator state machines (10.5) in a static arena sized at compile time, idling with WFI or WFE, one instance per priority level. Both may be bound together, with an `executor` as an `srp` task. `@interrupt(VECTOR)` binds a function to a vector and `@task(priority=n)` sets its level. Holding a lock across a suspension point is E323. Accessing a `Resource[T]` from two priority levels shares non-Freeze state between tasks that may run at once and needs `uses nondet` (E709). Under the replay handler, `srp` records task dispatch order with its inputs, so `yan replay` reproduces a firmware trace on the host.

**Abort and logging (R324).** On `freestanding` the program binds an `abort` handler (`reset`, `halt` or `breakpoint`, each optionally logging first); panics still abort (8.3). The `log` capability uses deferred formatting: stage 0 interns each format string into a non-loaded section, the device sends the string's index and binary arguments, and `yan log` decodes them. Transports are RTT, semihosting and UART.

**Embedded atomics (R325).** `Atomic[T]` stays lock-free only (E418). On cores without compare-and-swap, `Atomic[T]` has load and store only. Read-modify-write without hardware support uses the `critical_section` capability, `std.embedded.CsMutex[T]` (interrupt masking on one core, the hardware spinlock across cores) or the explicit type `CsAtomic[T]`.

**Embedded targets (R326).** Tier 1: `thumbv8m.main-none-eabihf` and `riscv32imac-none`. Tier 2: `thumbv7em-none-eabihf` and `thumbv6m-none-eabi`. The reference board is the Raspberry Pi Pico 2 (RP2350, Cortex-M33 and Hazard3 RISC-V). The manifest's `embedded` field gives chip, memory map and stack reserve, and stage 0 generates the linker script. `yan run --target` flashes through a pinned probe-rs and streams `log` over RTT. `--release=size` is the size-optimised release build. CI runs QEMU for both tier-1 targets; hardware-in-the-loop runs are nightly.

**GPU programming model (R327).** A `par for` whose body is `uses none`, and math `Array` operations, run on the device when a `gpu` handler is bound and the data is in a `DeviceArray`. A `@kernel` function computes one output tile per program instance, takes a `TileOrigin` (R953), may read and write `Array` elements under the access proof of 11.2 (R954), and works over `Tile[M, N, T]` values with `load`, `store`, elementwise arithmetic, `dot`, `reduce`, `scan` and `where`; tile shapes are `Nat` parameters, and a shape mismatch is E521. The compiler maps tiles to threads, shared memory and tensor cores. Safe code has no thread indices, shared memory or warp operations. Bounds checks stay on; a failed check traps the kernel and the launch fails with `KernelFault` carrying the program id and span.

**GPU determinism (R328).** Without `@fast_math`, kernels use IEEE arithmetic with subnormals kept, no contraction into FMA unless written, the correctly rounded functions of 11.1, and the fixed reduction tree of 9.3 for `reduce` and `dot`; safe kernels have no float atomics. A kernel MUST then give bit-identical results on every `gpu` handler, including `cpu`. `@fast_math`, which requires `nondet` (7.1), permits tensor-core `dot` (TF32, BF16 and FP8 with FP32 accumulate), flush-to-zero, approximate transcendentals and atomic reductions.

**GPU capability and backends (R329).** `gpu` is a capability written in `uses`. Its handlers are `cpu` (always available; the conformance oracle), `metal`, `cuda`, `rocm` and `vulkan`. `DeviceArray[axes..., T]` is an owned buffer from the bound handler. Moving or viewing an array into a launch makes it unusable on the host until the launch completes. Launches are I/O-handler operations and overlap under `par concurrent`. Lowering goes from Yan IR through MLIR (`linalg`, `vector`, `scf`, `gpu`) to NVVM, ROCDL and SPIR-V; `metal` lowers through LLVM IR to AIR. `metal` is the first hardware backend and `cuda` the second; `rocm` and `vulkan` are tier 2.

### 17.2 Method resolution and prelude

**Method resolution (normative).** `x.f(...)` resolves `f` by looking, in order, in the current module, then the module that declares the type of `x`, then the prelude. For a receiver of type Actor\[S\] or Remote\[Actor\[S\]\], the second step also searches the module that declares S, among functions whose first parameter is var self: S, and the call sends a message (R435). The first step that has `f` wins, and lint W819 flags a match that hides a function of the same name at a later step (R348). Two functions of one name at one step are E250, reported at the second definition (R469). This is how `xs.get(i)` on a list and `d.get(k)` on a dict reach different functions without overloading, and why a dependency that adds a function never changes or breaks a call in another package.

**Declaring modules of built-in types (R475).** For the second step, the built-in types are declared in these std modules: `str` and `char` in `std.text`, `list` in `std.list`, `dict` in `std.dict`, `set` in `std.set`, `bytes` in `std.encoding`, the scalars and `bigint` in `std.num`, and `Result` and `Option` in `std.result`. So `s.partition("=")` is `std.text.partition(s, "=")` and `xs.index(2)` is `std.list.index(xs, 2)`. **Case mapping on `char` (R787).** `c.upper()` and `c.lower()` are `std.text.upper(std.fmt.show(c))` and `std.text.lower(std.fmt.show(c))` and return `str`, because full case mapping can yield several scalars (`'ß'.upper()` is `"SS"`). **Parsing a `char` (R927).** `c.parse_int()` and `c.parse_float()` are `std.text.parse_int(std.fmt.show(c))` and `std.text.parse_float(std.fmt.show(c))`.

**Optional values in Yan Core text (R476).** `T | None` is `Option[T]`, whose variants are spelled `Some { value: v }` and `None` in Yan Core text, as `Result`'s are `Ok { value: v }` and `Err { error: e }`. A nested optional spells the inner value `Some { value: None }` (R793).

**Numeric prelude functions (R801).** The prelude has `ord(c: char) -> int`, the scalar value of `c`, and `chr(n: int) -> char fail EncodingError`, which fails with reason `Scalar()` and `at: 0` when `n` is negative, a surrogate or above `0x10FFFF`. `divmod(a, b)` is `(a // b, a % b)` and `pow(a, b)` is `a ** b`, for the operand types those operators accept and with their result types and panics. All four are free functions and positional-only. The expansion of `divmod` or `pow` carries the `Prelude` spelling mark (16.5, R861).

**List append (R477).** The one operation that adds an element at the end of a list is `append`: Yan Agent and Yan write `xs.append(v)`, and Yan Core text calls `std.list.append[T](inout xs, sink v)`. std has no `push`.

**F-strings in Yan Core text (R478).** An f-string lowers left to right. Each literal part is a `str` literal. Each `{x}` is `std.fmt.show[T](let x)`, or `x` itself when `T` is `str`. Each `{x:fmt}` is `std.fmt.show_spec[T](let x, "fmt")`, where `fmt` is a stage-0 constant checked against `T` at compile time. The parts are joined by a left-nested chain of `std.text.concat`, which in-place concatenation (R388) keeps linear, and an f-string with no parts is `""`. Yan's `\(x)` and `\(x:spec)` interpolation lowers the same way.

**std.regex (R482 to R486).** The API follows Python's `re` within linear-time matching. `compile(pattern: str) -> Regex fail RegexError` and `escape(s: str) -> str` are free functions. `Regex` has `search`, `match` (anchored at the start) and `fullmatch` (anchored at both ends), each returning `Match | None`, plus `find_all -> list[Match]` (non-overlapping, left to right), `split -> list[str]` and `sub(repl, s) -> str`. `Match` has `text`, `group(i)` and `named(name)`, which return `str | None`, and `start` and `end`. `RegexError` holds `pattern` and `reason`. All results are materialized lists. `find_all` returns `Match` values, not Python's group-dependent strings or tuples (R482). `start` and `end` count chars, as `char_count` does (R483). A `compile` whose argument is a string literal is checked at stage 0, and a rejected pattern (syntax, a backreference, a lookaround without `boolean=True`, or over the size limit) is E545. Such a call cannot fail and needs no `?` or `else`; a non-literal pattern fails with `RegexError` at run time (R484). `sub` takes Python's replacement syntax `\1`, `\g<name>` and `\\` (R485). A compiled automaton may take at most 1 MiB; a larger one is E545 for a literal, or `RegexError` with reason `too large` (R486).

**Boolean patterns (R629).** `compile(pattern, boolean=True)` also accepts `&` (both sides match), `~` (complement) and the lookarounds `(?<=A)`, `(?<!A)`, `(?=A)` and `(?!A)` whose bodies contain no lookaround, following RE# (POPL 2025). Matching stays linear in the input. Such a pattern matches leftmost-longest, because leftmost-first is not closed under `&` and `~`; without `boolean=True`, `&` and `~` are literal characters and the order stays Python's (R482). A lookaround nested in a lookaround is rejected like any other pattern: E545 for a literal, `RegexError` otherwise.

**std.collections (R488 to R493).** `deque[T]` has `append`, `appendleft`, `pop`, `popleft`, `first`, `last`, `extend`, `rotate(n)` (right by n, left when negative), `clear`, `maxlen`, indexing, `len`, `in` and front-to-back iteration. `heap[T: Ord]` has `push`, `pop`, `peek`, `pushpop`, `into_sorted` (`take self`, ascending) and `len`. `sorted_dict[K: Ord, V]` and `sorted_set[T: Ord]` have every `dict` and `set` method with the same names, iterate in ascending order, and add `first`, `last`, `pop_first`, `pop_last`, `floor(k)` (greatest key <= k), `ceiling(k)` (least key >= k) and `range(lo, hi)` (lo <= key < hi, a list); a sorted\_dict query returns `tuple[K, V]`. The constructors `deque()`, `deque(xs)`, `deque(xs, maxlen=n)`, `heap()`, `heap(xs)` (heapify, O(n)), `sorted_dict()`, `sorted_dict(d)`, `sorted_set()` and `sorted_set(xs)` are prelude calls like `list(xs)`, with no literal syntax (R488). `pop`, `popleft` and `heap.pop` panic with `bounds` on an empty collection; `first`, `last`, `peek`, `pop_first` and `pop_last` return `T | None` (R489). A deque built with `maxlen` drops one element from the other end when an append would exceed it, as Python's does (R490). A heap is not iterable, and `str(h)` lists its elements in ascending order, so output does not depend on the heap's layout; a max-heap is `heap[cmp.Reverse[T]]` (R491). Sorted types have no positional indexing in 1.0 (R492). Show formats follow CPython's repr: `deque([1, 2])`, `deque([1, 2], maxlen=3)`, `heap([1, 2, 5])`, `sorted_dict({1: 'a'})`, `sorted_set({1, 2})` and `sorted_set()` (R493).

**Static sorted collections (R631).** `frozen_sorted_set(xs)` and `frozen_sorted_dict(d)` build an immutable sorted collection once, stored in a cache-friendly search layout (Eytzinger or S-tree; Khuong and Morin, 2017) that is not observable. They have the read-only methods of `sorted_set` and `sorted_dict`, plus `rank(x)`, the number of elements below `x`; they iterate in ascending order and show as `frozen_sorted_set({1, 2})`.

**Filters and compressed sets (R632).** `fuse_filter(keys)` builds a static binary fuse filter (Graf and Lemire, 2022) with `may_contain(x) -> bool`. It is true for every key in `keys`, and for any other value it is true with probability about 2^-8, or 2^-16 with `bits=16`. It hashes with `std.hash.stable`, so its answers do not depend on the seed. `roaring_set[T]`, for `T` of `u32` or `u64`, is a mutable set with the `set` methods, ascending iteration and `rank`, stored as Roaring containers (Lemire et al.).

**Batch lookups (R626).** `d.get_many(keys)` and `s.contains_many(keys)` on `dict`, `set`, UnorderedMap and UnorderedSet, and `k.index_many(keys)` on `Keyed` (5.6), return a `List` with one result per key in input order, equal to mapping the single lookup over the keys. They SHOULD probe in interleaved groups with prefetching (AMAC, VLDB 2015), and the table hash join (11.9) uses the same kernel.

**List slices and bisect (R494 to R499).** `list[T]` has `insert(i, x)`, `sort()` (stable, ascending, in place, `T: Ord`), `sort_unstable()`, `reverse()` (in place), `bisect_left(x)` and `bisect_right(x)` (each `-> int`), `insort(x)` (inserts at `bisect_right(x)`) and `slice_exact(start, stop) -> list[T]`. They are methods in `std.list`; `std.slices` will carry the same names over `View[T]` and `MutView[T]` when views are implemented (R494). The bisects take Python's names and no `lo` or `hi`; there is no bare `bisect` (R495). `key=` on `sort`, the bisects and `insort` comes with closures, with Python's meaning (R496). Descending order is `sort()` then `reverse()`; `sort` takes no `reverse=` (R497). `insert(i, x)` clamps as Python does: a negative `i` counts from the end, and an index past either end inserts at that end (R498). `slice_exact(start, stop)` panics with `bounds` unless `0 <= start <= stop <= len`, and takes no negative indices (R499).

**std.math (R500 to R507).** The bundled libm is CORE-MATH, whose binary64 functions are proven correctly rounded; `sqrt`, `fma` and the four arithmetic operations are IEEE exact in hardware, and every `std.math` function is tier E (R500). `std.math` covers `float` now: `exp exp2 exp10 expm1 exp2m1 exp10m1 log log2 log10 log1p log2p1 log10p1`, `pow pown powr sqrt cbrt rsqrt hypot`, `sin cos tan sinpi cospi tanpi asin acos atan atan2 asinpi acospi atanpi atan2pi`, `sinh cosh tanh asinh acosh atanh`, `erf erfc lgamma tgamma`, and the exact `add sub mul div fma floor ceil trunc fmod remainder copysign ldexp frexp next_up next_down is_nan is_inf is_finite`. `compound` and `rootn` follow when a correctly rounded binary64 version exists; the C aliases `scalbn`, `nextafter`, `fabs`, `fmin` and `fmax` are left out; the other widths follow their types (R501). Names are the C23 ones, with IEEE 754 `next_up`/`next_down` and snake\_case predicates, called as `math.exp(x)` (R502). On `int`, `gcd lcm isqrt factorial comb perm` follow Python's `math`, except that overflow panics (R834). A domain error or overflow gives the IEEE result, NaN or an infinity, never a panic (R503). `type Round = NearestEven() | Up() | Down() | TowardZero()` is declared in `std.math` and passed as `round=math.Up()`. The exact operations, `sqrt`, `sum_exact` and `dot_exact` honor all four modes in every implementation; the interpreter runs the libm functions in `NearestEven()` only and reports another mode as not supported until codegen (R504). `sum_exact(xs, round)` and `dot_exact(xs, ys, round)` compute the exact sum and round once, with IEEE 754 zero signs and special values and no intermediate overflow; `dot_exact` panics with `value` when the lengths differ (R505). The constants are `pi`, `e`, `inf` and `nan` (R506). The `grad` family is not part of `std.math`'s first release; it gets its own proposal at M4 (R507).

**std.iter (R508 to R515).** Until user `Iterator` impls exist, `std.iter` provides one built-in lazy type `iter[T]`, the `Iterator` with `Item = T`: single pass, and an exhausted one keeps returning `None`; `for` consumes it, indexing one or calling `len` on one is an error that names `.collect()` and `.count()` (R810), except where Yan Agent's lenient reader collects a fresh one (N37, R831), and when associated types arrive `iter[T]` names `dyn Iterator[Item = T]` with no program change (R508). Sources: `xs.iter()` on `list`, `set`, `dict` (keys, insertion order), `str` (chars), `deque` and the sorted types, plus `iter.count(start=0, step=1)`, `iter.repeat(x, n=None)`, `iter.once(x)` and `iter.empty()`; `range` stays a list (R509). Lazy adapters: `map`, `filter`, `take_while`, `drop_while`, `take`, `skip`, `step_by`, `zip` (stops at the shorter), `enumerate`, `flat_map`, `chain`, `windows(n)` and `chunks(n)`, whose items are `list[T]` copies until views exist; `chunks` keeps a short last chunk, and `n < 1` panics with `value` (R510). Consumers: `next`, `collect() -> list[T]`, `fold`, `count`, `any`, `all`, `find`, `min`, `max` (`None` when empty) and `sum` (the reduction order of 9.3); `set`, `dict` and `sorted` take an iterator directly (R511). `list.map`, `list.filter` and `list.fold` stay eager and return lists (R512). `xs.iter()` borrows `xs` and is second-class under the view rule (E414 when stored or returned; mutating `xs` meanwhile is an exclusivity error); the owning sources are first-class; the checks arrive with views (R513). `sorted`, `list.sort`, `sort_unstable`, the bisects, `insort`, `min`, `max` and `iter.min`/`iter.max` take `key: (T) -> K` with `K: Ord`, Python's meaning, calling `key` once per element in the sorts (R514, carrying R496). A pipeline pulls one item at a time from its end, so closure effects interleave per item and a pipeline stops as soon as its consumer is done (R515). **std.itertools (R936).** `permutations(xs, r=None)`, `combinations(xs, r)`, `combinations_with_replacement(xs, r)`, `product(a, b)`, `pairwise(xs)` and `accumulate(xs, f=None, initial=None)` take lists and return lazy `iter` values in Python's order. A selection is a `list[T]` where Python gives a tuple, `product` and `pairwise` give `tuple` items, and `r` greater than `len(xs)` gives an empty iterator. Selections are by position, so equal elements are not merged. `accumulate` without `f` adds `int` (overflow panics) or `float` and panics with `value` for any other `T`, and with `initial` it yields that value first. `list(it)` of an `iter` is read as `it.collect()` (N37).

**Fused iterator chains (R623).** A chain of std adapters (`map`, `filter`, `take`, `skip`, `take_while`, `enumerate`, `zip`, `chain`, `flat_map`, `scan`, `windows`, `chunks`) over a std iterator, consumed by a `for`, a reduction or `collect`, MUST compile to one loop with no allocation beyond `collect`'s result and no indirect call, however the adapters nest, `zip` over `flat_map` included. The normal form follows complete stream fusion (Kiselyov, Kobayashi and Palladinos, 2024). Results cannot change, because allocation is not observable (R385).

**std.meta (R939).** `info(t: Type) -> TypeInfo` is a stage-0 function. `TypeInfo` is `@non_exhaustive`, so a `match` on it outside std needs a wildcard arm (E503 otherwise, W811 exempt): `Record(info: RecordInfo)`, `Sum(info: SumInfo)`, `Newtype(info: NewtypeInfo)`, `Scalar(info: ScalarInfo)`, `Array(info: ArrayInfo)`, `View(info: ViewInfo)`, `Optional(inner: Type)`, `Tuple(elems: list[Type])`, `Fn(info: FnInfo)`, `Builtin(info: BuiltinInfo)` and `Trait(info: TraitInfo)`. `RecordInfo` is `name: str`, `params: list[Type]`, `fields: list[FieldInfo]`, `annotations: list[Annotation]` and `layout: Layout`; `SumInfo` has `variants: list[VariantInfo]` (each `name` and `fields`) in place of `fields`; `NewtypeInfo` is `name`, `inner: Type` and `annotations`; `ScalarInfo` is `name`, `bits: int`, `signed: bool` and `float: bool` (`bool` is 1 bit, `char` 32, both unsigned); `ArrayInfo` is `elem: Type` and `axes: list[Axis]`, where `Axis` is `Positional(size: int)`, `Variable(name: str)` for a size variable or `Labelled(label: Type)`, in written order (11.2), so a labelled array has no static length; `ViewInfo` is `elem: Type` and `mutable: bool`; `FnInfo` is `params: list[Type]`, `ret: Type`, `fails: list[Type]` and `uses: list[str]`; `BuiltinInfo` is `name: str` and `args: list[Type]`, for `str`, `list`, `dict`, `set` and the other std containers; `TraitInfo` is `name: str` and `methods: list[MethodInfo]`, each `name: str` and `sig: FnInfo` (capability parameters are its `uses`). `FieldInfo` is `name: str`, `ty: Type`, `public: bool` and `annotations: list[Annotation]`; `Annotation` is `name: str`; `Layout` is `size: int` and `align: int` under the target's layout. Fields and variants are listed in declaration order, with the type arguments substituted. A field the call site cannot see is left out, so reflection never widens access (E264). Reading a `TypeInfo` field is what R143 tracks. The reifiers are `record_type(r: RecordInfo) -> Type`, `sum_type(s: SumInfo) -> Type` and `newtype(n: NewtypeInfo) -> Type` (R941); a reified `newtype` is the record with the one field `value` that a written one is.

**std.json (R569 to R575).** Besides typed `parse` and `dump`, `json` has `type Value = Null() | Bool(b: bool) | Int(i: int) | Float(f: float) | Str(s: str) | Array(items: list[Value]) | Object(fields: dict[str, Value])`, `parse_value(s, max_depth=128) -> Value fail JsonError` and `dump_value(v, indent=None) -> str`. All of them ship once `derive(Wire)` exists, and `Value` is itself `Wire` (R569). A number with no fraction or exponent is an `Int` when it fits `int`; an integer outside that range fails with reason `Range`; any other number is a correctly rounded `Float`. `-0` is `Int(0)`. A `Float` dumps with the shortest round-trip digits and always with a `.` or an exponent; dumping a non-finite float panics with `value` (R570). Input is strict RFC 8259. Comments, trailing commas, single quotes, `NaN` and `Infinity`, leading zeros, a byte order mark, control characters in strings, unpaired surrogate escapes and trailing content all fail. Whitespace is space, tab, LF and CR. A duplicate key fails with `Duplicate(key)`, and nesting deeper than `max_depth` fails with `Depth` (R571). Output keeps insertion order and takes no `sort_keys`. The compact form has no spaces (`{"a":1}`); `indent=n` puts one member per line with `": "` and no trailing newline. Strings escape only `"`, `\` and control characters (short escapes, else `\u00XX`) and write non-ASCII as UTF-8, so equal values print equal bytes everywhere (R572). `type JsonError = { line: int, col: int, reason: JsonReason }` with `JsonReason = Syntax(msg: str) | Depth() | Duplicate(key: str) | Range()`. `line` and `col` start at 1, and `col` counts chars. `Show` prints `line L, col C: text`, where `text` is the `Syntax` message; `duplicate key "k"` for `Duplicate(k)`; `nesting exceeds max_depth` for `Depth`; `number out of range` for `Range`; and for the typed reasons of R877, `P: expected E, found F` for `Mismatch`, `P: missing field "f"` for `Missing`, `P: unknown field "f"` for `Unknown` and `P: msg` for `Invalid`, with `P` the path. A key or field name is written as a double-quoted string. `dump_value` of an `Int` outside `int` panics with `value`. `JsonError` is the module's only error type (R573). `Value` has total accessors: `get(key)`, `at(i)` (no negative index), `as_bool`, `as_int`, `as_float` (an `Int` widens exactly or gives `None`), `as_str`, `as_list` and `as_dict`, each `-> T | None`, plus `is_null() -> bool` (R574). `parse_float(s, max_depth=128) -> float fail JsonError` parses a document that is exactly one JSON number, with optional surrounding whitespace, under R570 and R571 (`max_depth` is accepted for symmetry with `parse_value`; a bare number nests nothing); an integer widens exactly or fails with `Range` (R575). **Typed shapes (R874 to R877).** A sum is one object with an internal tag: key `tag`, renamed by `@wire(tag: "kind")` on the sum, value the variant name or its `@wire(name: ...)`; decoding checks the tag against the declared variants only (R874). A record is an object in declaration order and `@wire(name: ...)` renames a field (Yan only; Yan Agent uses the item-level map of R886); `T | None` is `null`, or an absent field on input; a nested optional is E330. An `int` field rejects `1.0`; a `float` field widens an integer literal exactly or fails `Range`. `list`, `tuple` and `set` are arrays, a tuple of the wrong length is a mismatch, `dict[str, V]` is an object and any other key type an array of `[key, value]` pairs, `bytes` is base64 (standard alphabet, padded), and a newtype is its inner encoding with refinements checked after construction. A non-finite float panics with `value` on dump (R875). Unknown fields fail unless the record or sum has `@wire(unknown: "ignore")`; duplicate keys always fail (R876). **Item-level `@wire` (R886, R887).** A record or sum takes `@wire(names: {a: "x"}, tag: "kind", unknown: "ignore")`, written `@wire(names={"a": "x"}, tag="kind", unknown="ignore")` in Yan Agent. `names` maps a field or variant name to its wire name: a record's keys are its fields; a sum's keys are its variants or the fields of its variants, a field key renaming every field of that name. It is the only way Yan Agent renames, since a field or variant takes no attribute there, and json keys, csv columns, tag values and field-less csv enum cells all read it (R886). A key that names nothing, a name renamed twice, a key that is both a variant and a field, and two fields of a record or variant, or two variants, with one wire name are E331. `tag` renames a sum's tag key in json and its tag column in csv, and a variant field with that wire name is E330; `unknown: "ignore"` makes decoding skip unknown json members and csv columns, and `"reject"` is the default. Any other key or value in `@wire` is E331 (R887). `JsonReason` also has `Mismatch(path, expected, found)`, `Missing(path, field)`, `Unknown(path, field)` and `Invalid(path, msg)`; `path` is `$` followed by `.name` and `[i]` steps, and `line` and `col` point at the start of the offending value (R877).

**std.csv (R878 to R881).** `csv.parse[T: Wire](s, delimiter=",") -> list[T] fail CsvError` and `csv.dump[T: Wire](rows: list[T], delimiter=",") -> str`; `T` is the row type. The first line is a required header, columns are matched by name (with `@wire(name: ...)` or `@wire(names: ...)`) in any order, a missing column needs a default or an optional field, and an extra column fails unless the record opts in as in R876. Input is RFC 4180: quoted fields, doubled quotes, delimiters and newlines inside quotes, LF or CRLF; a byte order mark, a bare quote in an unquoted field, a short or long row and an unterminated quote fail. Output is a header then one row per element, `\n` after every row, and a field quoted only when it contains the delimiter, a quote, CR or LF or is empty (R878). A cell is a `bool` (`true`, `false`), `int`, `float`, `str`, `T | None` of those, a newtype over them, or a sum whose variants have no fields (the variant name, or its wire name under R886). `None` is an unquoted empty cell and `Some("")` a quoted one. A row type may be a sum: the `tag` column (renamed as in R874 and R887) comes first, then the union of the variants' fields in first-appearance order; a field name shared by variants has one type, and a cell for a field the variant lacks is empty. Any other field type is E330 (R879). `type CsvError = { line: int, col: int, row: int, column: str, reason: CsvReason }` with `CsvReason = Syntax(msg: str) | Header(msg: str) | Mismatch(expected: str, found: str) | Missing(field: str) | Unknown(field: str) | Invalid(msg: str) | Limit()`; `row` 1 is the first data row and 0 the header, and `Show` prints `line L, col C: reason` (R880). Both codecs are checked by round-trip cases on both backends; `std.toml` follows over the same mapping (R881).

**std.encoding and `bytes` (R579 to R585).** `bytes` is an immutable sequence of `u8` with value semantics. Its methods are `len()`, `b[i] -> u8` (panics with `bounds`), `at(i) -> u8 | None`, `slice_exact(start, stop)` (R499), `concat(other)`, `to_list() -> list[u8]`, `starts_with`, `ends_with` and `find(sub) -> int | None`. It is built by `bytes.from_list(xs: list[u8])`, `s.bytes()` and the decoders, has no literal syntax, and implements `Eq`, lexicographic `Ord` and `Hash` (R579). `b.decode_utf8() -> str fail EncodingError` is strict and fails at the first byte of an overlong form, a surrogate or a truncated sequence. `b.decode_utf8_lossy() -> str` replaces each maximal invalid subpart with U+FFFD. `s.bytes()` never fails (R580). `encoding.hex(b) -> str` writes lowercase. `encoding.hex_decode(s) -> bytes fail EncodingError` accepts either case and rejects whitespace, `0x` and odd length (R581). `encoding.base64(b, url=False, pad=True) -> str` uses the RFC 4648 standard alphabet, or the URL-safe alphabet with `url=True`. `encoding.base64_decode(s, url=False) -> bytes fail EncodingError` accepts input with or without padding and rejects whitespace, the other alphabet, padding in the middle and non-zero trailing bits, so each byte string has one accepted encoding per alphabet (R582). `type EncodingError = { at: int, reason: EncodingReason }` with `EncodingReason = Utf8() | Hex() | Base64() | Scalar()` (`Scalar()` from `chr`, R801). `at` is a byte offset for `Utf8` and a char offset otherwise, counting from 0. `Show` prints `invalid <kind> at <at>`. It is the module's only error type (R583). `show(b)` is CPython's repr: `b'...'`, printable ASCII as itself, `\\`, `\'`, `\t`, `\n` and `\r` escaped, and every other byte as lowercase `\xNN` (R584). `bytearray` is a growable mutable buffer. It has `bytearray()`, `bytearray.from_bytes(b)`, `len()`, `b[i]` and `b[i] = x` (both panic with `bounds`), `append(x: u8)`, `extend(b: bytes)`, `pop() -> u8` (panics with `bounds` when empty), `clear()` and `to_bytes() -> bytes` (a copy). It implements `Eq` but not `Ord` or `Hash`, `show` prints `bytearray(b'...')`, and it coerces to `MutView[u8]` when views exist (R585).

**std.path (R587 to R592).** `Path` is an immutable value over a UTF-8 `str`, built by `Path(s)`; `p.text()` returns the string, it implements `Eq`, `Ord` (by `parts()`) and `Hash`, and `show(p)` prints the text (R587). Every operation is lexical and needs no capability. `/` is the only separator on every host, with no drives, `\` or UNC prefixes; the `fs` handler maps a `Path` to the host's native form at the call (R588). `Path(s)` collapses repeated separators, drops `.` segments and a trailing `/` (except on the root), and maps `""` to `.`; it keeps `..`. `p.normalize()` removes `x/..`, maps `/..` to `/` and keeps a leading `..` on a relative path (R589). Methods: `join[P: AsPath](part)` (an absolute `part` replaces the receiver), `parent()` (the parent of `/` is `/`, of `a` is `.`), `name()` (`""` for `/` and `.`), `suffix()` (from the last `.` of the name; `""` when there is none or the name's only `.` is its first char), `stem()`, `with_name(n)` and `with_suffix(s)` (both panic with `value` on a separator, an empty name, or a suffix not starting with `.`), `parts() -> list[str]` (an absolute path's first part is `/`), `is_absolute()`, `relative_to(base) -> Path | None` and `starts_with(base)`, both by parts and adding no `..`. `trait AsPath` has `as_path(self) -> Path` and is implemented by `str` and `Path`; there is no `/` operator on paths (R590). `WindowsPath(s)` is Windows path text as data on any host: it reads `\` and `/`, prints `\`, recognizes a drive, a UNC share and the verbatim prefix `\\?\` (kept as written, unnormalized after it), has the `Path` methods plus `drive()`, `root()` and `anchor()`, is absolute only with both a drive or share and a root, compares parts case-insensitively by Unicode simple lowercase (`show` keeps case), and converts by `to_posix() -> Path | None` only when relative with no drive. It does not implement `AsPath` and never reaches `fs` (R592).

**Bits (R681).** `std.bits` is `core` and needs no capability. Its functions take a fixed-width integer or `int` and work on the two's-complement pattern, called through the module as `bits.count_ones(x)`. `count_ones`, `count_zeros`, `leading_zeros`, `trailing_zeros` (the width when `x` is 0) and `bit_width` (the width minus `leading_zeros`) return `int`. `rotate_left(x, n)` and `rotate_right(x, n)` take `n` modulo the width; they, `swap_bytes`, `reverse_bits` and `wrapping_shl(x, n)` return the type of `x`. `is_power_of_two` is false for 0 and negative values. `bigint` has only `count_ones` and `bit_width`, over the magnitude.

**Rand (R683 to R685).** `type Algorithm = ChaCha8() | Pcg64Dxsm()`. `seeded(seed: uint64, algorithm = ChaCha8())` has one fixed stream per seed and algorithm, versioned with the module (20.5). ChaCha8 takes as key four SplitMix64 outputs of `seed`, little-endian, with nonce and 64-bit block counter at 0, and `next_u64` takes the block words two at a time, low word first: the words of `rand_chacha` 0.9's `ChaCha8Rng::from_seed`. Pcg64Dxsm is the 128-bit LCG with the cheap multiplier and DXSM output (NumPy's `PCG64DXSM`) built from four SplitMix64 outputs `a, b, c, d` as `Lcg128CmDxsm64::new(a << 64 | b, c << 64 | d)` (R683). The derived operations are defined only through `next_u64`, so every handler gives the same values for the same stream: `next_f64()` is `(next_u64() >> 11) * 2**-53`; `below(n)` is Lemire's method on 64 bits and panics with `value` when `n <= 0`; `range(lo, hi)` is `lo + below(hi - lo)` and panics with `value` when `hi <= lo`; `bool()` is the top bit; `choice(xs)` is `xs[below(len(xs))]` and panics with `bounds` on an empty list; `shuffle(var xs)` is Fisher-Yates from the last index down, swapping `i` with `below(i + 1)` (R684). Each task holds a split counter `c`, from 0 (R824). A `par` takes the current `c` and increments it, and its branch `k`, from 0, gets the same algorithm seeded with `splitmix64(parent_seed ^ splitmix64((c << 32 | k) + 1))`, so a branch's stream depends on the task path and consecutive `par` blocks draw independent streams; the parent's stream is unchanged; `os()` splits into independent `os()` handlers (R685). **State (R823).** `state() -> Option[RandState]` is an operation of `Rand` with a default body returning `None`; `seeded` returns `Some` and `os()` `None`, and `crypto_rand` has no state. `RandState` is opaque bytes with `Wire`, `Eq` and `Show`: a version tag, then the algorithm, seed, split counter and position, laid out by the module and versioned with it (20.5). `seeded(state)` restores a state, and `seeded(seed, algorithm=ChaCha8(), at=0)` seeks to `at` bytes of stream, a multiple of 8 or panic `value`: O(1) for ChaCha8 and a jump-ahead for Pcg64Dxsm. There is no `set_state` on a live handler; a resumed run binds a new handler with `with`. `state()` is recorded and journaled like any `rand` operation. The position counts bytes of the stream consumed, 8 per `next_u64`.

**Crypto_rand (R897).** `crypto_rand.fill_bytes(&buf: bytearray) -> None` overwrites every byte of `buf` from the operating system CSPRNG, in place and without resizing it. `crypto_rand.random_bytes(n: int) -> bytes` is `fill_bytes` on a fresh zeroed buffer of `n` bytes, and panics with `value` when `n < 0`. Both panic with `crypto_rand` when the OS refuses. `fake_crypto_rand(data: bytes)` fills by repeating `data` from its start for each call, under `yan test` only; a release run ignores it.

**Env (R686, R687).** `env.args()` is the program's arguments without its name (`yan run f.yag -- a b` gives `["a", "b"]`). `env.var(name)` is `None` for an unset variable or one that is not valid Unicode, `env.vars()` holds every valid-Unicode variable sorted by name, and `env.secret(name)` is `env.var` wrapped in a `Secret`. There is no `set_var`, since the environment is shared. The test handler is `fake_env(args=[], vars={}, zone=TimeZone.utc())` (R686). `Secret[T]` is a built-in opaque type in `std.env` until generic classes let std declare it; its operations are 17.4 (R687).

**Log (R688 to R690).** `log.info(msg, key=value, ...)`, and likewise `debug`, `warn` and `error`, records each keyword argument as a field of its name and `show(value)`, in call order, and lowers to the one trait operation `event(level: Level, msg: str, fields: list[tuple[str, str]])`, which is all a user handler implements. `type Level = DebugLevel() | InfoLevel() | WarnLevel() | ErrorLevel()`, ordered so (R688). `log.span(name, key=value, ...) -> Log` returns a child handler bound with `with log = log.span(...)`; events under it carry the span path, joined with `/`, and the span's fields before their own, and a span emits no event itself. `par` branches inherit the current span (R689). Events print as logfmt, `level=info msg="parsed" span=load rows=3`; a value is quoted when it is empty or holds a space, `=`, `"` or a control character, and `\"`, `\\` and `\n` are escaped inside quotes. `log_stderr(level=InfoLevel())`, the `yan run` default, prefixes `ts=` and the host time as RFC 3339 UTC to the microsecond; `log_stdout(level=DebugLevel())` has no timestamp; `discard_log()` drops every event. Log output under `yan test` never changes a verdict and is shown when the test fails (R690).

**Proc (R691 to R693).** `Command(program: str, args: list[str] = [])` is a built-in value type whose builders return a new `Command`: `.arg(s)`, `.with_args(xs)`, `.env(name, value)`, `.env_clear()`, `.in_dir(p: P: AsPath)` and `.stdin(b: bytes)` (empty by default); `.program()` and `.argv()` read it back, and `show` prints `Command(['echo', 'hi'])`. `program` is `argv[0]`, resolved through `PATH` when it has no `/`; no argument is split or expanded and no shell runs (R691). `proc.run(cmd) -> Output fail ProcError` waits for the child and captures both streams, writing `stdin` from its own thread. `Output` has `code: int | None` (`None` when a signal ended the child), `signal: int | None`, `stdout: bytes`, `stderr: bytes` and `success()`, true only for code 0; a non-zero exit is data, not a failure. `ProcError` has `program`, `reason: ProcReason` (`NotFound() | PermissionDenied() | OsError()`) and `message`, covers only a child that could not start or be read, and shows as `<program>: <message>`. The test handler `fake_proc(outputs: dict[str, Output] = {})` is keyed by program and fails with `NotFound` for any other (R692). `spawn`, piped stdio and scope-owned children wait for `Reader`, `Writer` and scope-owned handles (R693).

**Cli (R694, R695).** `@derive(Cli)` applies to a record. A field without a default is a required positional, in field order; a `list[T]` field without a default takes the remaining positionals, at most one per record; a `bool` without a default or defaulting to `False` is a flag `--name`; any other literal default makes an option `--name VALUE` or `--name=VALUE`; a `T | None` field without a default or defaulting to `None` is an optional option; a sum of unit variants takes its kebab-case variant name as value; and a sum whose variants are records is a subcommand per variant, parsed by the same rules, and must be the last field. Names are kebab-case (`max_depth` is `--max-depth`, `DryRun` is `dry-run`). Value types are `str`, `int`, `float`, `Path`, such unit sums, and `T | None` and `list[T]` of those; another type, a non-literal default or a `bool` defaulting to `True` is E269 at the derive. `--` ends the options, `-h` and `--help` are reserved, and there are no short options. Help text comes from `@help(about="...", field="...", Variant="...")` on the record, since docstrings are hash-neutral (16.5); a key naming neither a field nor a subcommand variant, and `@help` without `@derive(Cli)`, are E269 (R694). `cli.parse[T]()` parses `env.args()` and needs `uses env`; `cli.parse_args[T](args)` is pure. Both return `T fail CliError`, and `T` must derive `Cli` (E201). `CliError` has `message: str` and `help: bool` and shows as `message`. For `-h` or `--help`, `help` is true and `message` is the help text: `usage: <prog> [options] <a> [<rest>...] <command>` with `<prog>` the record name in kebab-case (then the command name inside a subcommand), the `about` text, `arguments:` with each positional and its type, `options:` with each option, its value type, its `@help` text and `(default: <show(default)>)` in field order and then `-h, --help`, and `commands:` with each subcommand and its `@help` text. Otherwise `message` is `error: <problem>` and the usage line, for the first problem in argument order, worded as one of: `unknown option '--x'`, `option '--v' takes no value`, `option '--n' needs a value`, `invalid value 'abc' for '--n': expected int`, `invalid value 'red' for <color>: expected one of dark, light`, `'--n' given twice`, `missing argument <path>`, `missing command`, `unknown command 'x'` and `unexpected argument 'x'` (R695).

**Net (R789 to R791).** `net.tcp_listen(addr: str) -> TcpListener fail NetError` and `net.tcp_connect(addr: str) -> TcpStream fail NetError` take `host:port` strings. `TcpListener` and `TcpStream` are built-in handle types, not `Wire`. `listener.accept() -> TcpStream fail NetError | Timeout`, `listener.addr() -> str`; `stream.send(b: bytes) -> None fail NetError`; `stream.recv(max: int) -> bytes fail NetError | Timeout` returns at most `max` bytes, and empty `bytes` once the peer has closed and every byte is read; `stream.close()` (idempotent), `stream.local()` and `stream.peer()`. `accept` and `recv` fail with `Timeout` at an enclosing deadline (9.4). `NetError { addr: str, reason: NetReason, message: str }` with `NetReason = Refused() | AddrInUse() | Closed() | NotGranted() | OsError()`; `show` prints `<addr>: <message>` (R789). `mem_net()` is one in-memory network per handler value: `tcp_listen` binds exactly and a port of `0` takes the next free port from 49152 up, a bound address is `AddrInUse`, `tcp_connect` with no listener is `Refused` and otherwise queues the connection for `accept` in order, the client's local address is `127.0.0.1:<port>` from the same counter, each direction is an unbounded byte queue, `send` after either end closed is `Closed`, and no operation takes time (R790). `net.only` patterns are an exact `host:port` or `host:*`; an operation no pattern grants fails with `NotGranted` without reaching the handler, and nested layers must all grant (R791).

**Data profile (R826 to R829).** A data file is a `.yag` file that satisfies the data profile; it is not a surface and has no extension or name of its own (R826). It holds top-level `NAME: Type = expr` constants, comments and a module docstring, and nothing else: no imports, functions, types or statements. `expr` is built only from int, float, str, bytes and bool literals, `None`, unary minus on a number, list, dict, set and tuple displays, and record or variant constructors with named arguments. There are no operators, interpolation, comprehensions, function calls or references to other constants. The check is syntactic and linear, so tools read the file without the elaborator; a violation is E144 (R827). `data.parse[T: Wire](s: str, name: str) -> T fail DataError` finds the constant `name`, checks that its annotation names `T`, and decodes the literal tree with the `Wire` decoder (17.4), so unknown fields, duplicate keys and limits behave as in every other codec. Constructor names resolve against the types and variants reachable from `T`, never against scope. `type DataError = { line: int, col: int, reason: DataReason }` with `DataReason = Profile(msg: str) | Missing(name: str) | Mismatch(expected: str, found: str) | Decode(msg: str)`; `line` and `col` start at 1, `col` counts chars, and `Show` prints `line L, col C: reason`. `data.dump[T: Wire](x: T, name: str) -> str` prints `name: T = ...` in `yan fmt` layout with fields in declaration order, so `dump(parse(s))` equals `s` for a formatted file without comments (R828). `package.yag` and its `Lints(...)` field are data files (19.1, R829).

An incompatible redesign of a std module ships as a `.v2` module (`std.rand.v2`); the old one is deprecated and never removed in 1.x (20.5).

**`@yan/rel` (R262).** `rel.program(text)` parses a stratified Datalog program at stage 0, as a comptime string DSL (10.4). It reifies one record type per relation and specialises a semi-naive solver, so nothing is interpreted at run time. Relations are typed, as in `rel edge(a: u32, b: u32)`, with fields that are `Eq + Hash + Ord`. Rules are written `head <- body.`. Negation MUST be stratified, and aggregates (`count`, `sum`, `min`, `max`) may read only lower strata; otherwise it is a stage-0 diagnostic. `!body.` declares an integrity constraint whose violations are rows of a generated `Violation` sum. Stores are sorted `Soa` columns. Join order and indexes are chosen at stage 0, and `@plan` overrides them per rule. Output is sorted by tuple, so results are bit-identical across runs and thread counts. `solve(par: true)` runs the independent rules of a stratum in parallel, with per-rule deltas. `solve(limit: n)` fails with `Budget` instead of diverging. It is a first-party package, not std (R448).

### 17.4 Data safety

**`Wire` decoding (normative).** One `derive(Wire)` drives every codec in std and `@yan`, generating a direct decoder and encoder per type at stage 0. Decoding produces only a statically known type. Sum types use their declared tags, and no tag can select an arbitrary type. No user code runs during decoding except validation and invariant checks after construction. Depth, total size, and collection and string lengths are always limited. Unknown fields and duplicate keys are rejected unless the type opts in. Capability values are never `Wire`. `derive(Wire)` on a type with a field that is not `Wire` (a `Callable`, a capability, a built-in handle, a class without the derive) is E282 at compile time, once per field at its type annotation (R872, R873); a capability field adds a note that capabilities are never `Wire`.

**`Secret[T]`.** `Secret(x)` wraps a value and `s.expose() -> T` unwraps it (R687). `Show` prints `Secret(***)`. It is not `Ord` or `Hash`, and `==` is constant time for `Secret[str]` and `Secret[bytes]`. A secret is not `Wire` until `expose()` is called, is zeroized on drop, compares in constant time, and appears hashed in replay traces. W803 flags an exposed secret flowing into `log`.

**Constant time (R611).** In a function marked `@constant_time`, every value computed from `expose()` is secret-derived. A branch, `match`, index, division or remainder, variable-time intrinsic or early exit that depends on a secret-derived value is E424. std provides `ct_select`, `ct_eq` and `ct_lt`; release code generation lowers them to LLVM's constant-time selection, and Cranelift builds call `yan-rt` helpers.

**`Untrusted[T]` (R451).** An untrusted value has unknown integrity. Every model result is untrusted (R450), as are `py` call results and HTTP bodies read with `body_untrusted()`, and any API may return `Untrusted[T]`. The value is opaque. `u.map(f)` with a pure `f` keeps the label, `u.validate(check)` with `check: Fn(sink T) -> T fail E` removes it, and `u.trust(reason="...")` removes it unchecked and is listed by `yan audit`. A parameter marked `@trusted` rejects an untrusted argument (E325). std marks `proc.Command` arguments, `fs` paths that write or remove, `net.only` grants, and SQL and shell text; `@trusted_input` (17.8) is one case of it. A panic never shows an untrusted value, only its type name (8.3). Formatting an untrusted value into an f-string gives `Untrusted[str]`, and interpolating it into a `Template` keeps its label for the sink's escaper (R452). Branching on an untrusted value needs an unwrap first, so every point where untrusted data steers control flow is visible and audited.

**Model calls (R450).** The first-party package `@yan/model` declares `@capability @shared trait Model` with `generate[T: Wire](prompt: Template) -> Untrusted[T] fail ModelError`, `embed` and `tool_call`. A handler uses the provider's constrained decoding where it exists and otherwise parses against the `Wire` schema; either way decoding follows the rules above, so a model never selects a type. `model.only(models=[...], max_tokens=n, max_cost=m)` attenuates the capability, and package ceilings may carry the same limits (19.2). Tests bind no model by default. `fake_model(...)` and `replay(trace)` are the test handlers, so a test that calls a model is cached like any other, and an `ex` line may bind `model = fake_model(...)`. Model operations are recorded under R305.

**Role-aware calls (R551).** `@yan/model` also declares `generate_chat[T: Wire](messages: List[Message]) -> Untrusted[T] fail ModelError`, with `type Message = { role: Role, content: Template }` and `Role` one of `system`, `user` and `assistant`. `generate(p)` is `generate_chat([Message(user, p)])`. A handler whose provider has no roles renders the messages in order under a fixed role header that the handler documents. `model.only`, `fake_model`, `replay` and recording apply as for `generate`.

**Errors.** Each module that can fail defines one error type (`FsError`, `HttpError`, `JsonError`, ...) as a record or sum with `Show`, `Eq` and `Wire`.

### 17.5 Time

Moving between exact and civil time always names a zone: `i.in_zone(tz)`, `dt.in_zone(tz, disambiguation)`, `z.instant`, `z.plain`. There is no implicit local zone; `env.local_zone()` is the only way to the host's zone. Calendar arithmetic uses `Period`; `Duration` is exact. The representation, range and equality rules are section 11.6, the tzdb rules section 7.5, and literal checks section 14.2.

**Exact time (R593 to R597).** `Duration` is built by `Duration.nanos`, `.micros`, `.millis`, `.seconds`, `.minutes` and `.hours` (each from an `int`; no `days` or `weeks`, which are `Period` units) and read by `nanos() -> int128`, `seconds()` (toward zero) and `as_seconds_float()`. It has `+`, `-` and unary `-`; `d * n`; flooring `d // n` and `d % n`; `d / d -> float`, `d // d -> int` and `d / n` rounded half-even to the nanosecond; `abs()`, `Eq`, `Ord` and `Hash`; and `checked_add`, `checked_sub` and `checked_mul` (R593). `Instant` has `from_unix_seconds`, `from_unix_nanos`, `unix_seconds()` (flooring) and `unix_nanos()`, `Instant - Instant -> Duration` and `Instant ± Duration`, with `Eq`, `Ord` and `Hash`; `MonoInstant` has the same arithmetic, `Eq` and `Ord`, an unspecified epoch, and shows as `MonoInstant(<ns>)` (R594). `show(i)` is RFC 9557 UTC, `2000-01-01T00:00:00Z`, with fractional seconds only when non-zero and trailing zeros dropped. `Instant.parse(s) -> Instant fail TimeError` takes RFC 3339 with `Z` or a numeric offset, ignores a bracketed suffix only when it is `[UTC]`, `[Etc/UTC]` or matches the offset, and rejects lowercase `t` or `z`, a space for `T`, a missing offset, second 60 and more than nine fractional digits. `show(d)` is ISO 8601 in hours, minutes and seconds: `PT1.5S`, `PT0S`, `-PT2H30M` (R595). `TimeError { at: int, reason: TimeReason }` with `TimeReason = Syntax() | Range() | Zone() | Offset()` is the module's only error type; `at` is a char offset, and `show` prints `invalid time at N`, `time out of range at N`, `unknown time zone at N` or `time zone offset mismatch at N` (R596, R604). The `time` handlers are `os`, `fixed_time(i)` (every `now()` returns `i`; `monotonic()` starts at 0 and advances only by `sleep`) and `virtual(start)` (7.3, R396) (R597).

**Civil time (R598 to R603).** `PlainDate(y, m, d)`, `PlainTime(h, mi, s=0, ns=0)` and `PlainDateTime(date, time)` are proleptic Gregorian with no zone. A non-literal invalid field panics with `value`, and `try_new` returns `T | None`. They have `year()`, `month()`, `day()`, `weekday()` (ISO, Monday is 1), `day_of_year()`, `days_in_month()`, `in_leap_year()`, `hour()`, `minute()`, `second()` and `nanosecond()` as applicable, and `date()` and `time()` on `PlainDateTime`. They implement `Eq`, `Ord` and `Hash`. `show` and `parse` use ISO 8601 extended form with seconds always printed (`2024-02-29`, `09:05:00.5`, `2024-02-29T09:05:00`). `PlainTime + Duration` wraps at midnight, and `PlainDateTime ± Duration` is exact (R598). `Period(years=0, months=0, weeks=0, days=0)` panics with `value` on mixed signs. `d + p` adds years, then months (clamping the day to the month's end, so `2024-01-31 + P1M` is `2024-02-29`), then weeks and days; `checked_add` returns `None` outside the range. `a.until(b) -> Period` gives years, months and days with `a + p == b`, and `PlainDateTime.until` gives `(Period, Duration)`. `show` and `parse` use ISO 8601 (`P1Y2M`, `P3W`, `P0D`, `-P1D`) (R599). `TimeZone(id)` resolves an IANA ID in the pinned `std.tzdb`; a literal unknown ID is a compile-time error, and `TimeZone.parse(id)` fails with `Zone`. `TimeZone.utc()`, `TimeZone.fixed(offset_seconds)` (shown as `+05:30`), `tz.id()` and `TzDb.get(id)` complete it, and `Eq` compares IDs (R600). `i.in_zone(tz)` is total; `dt.in_zone(tz, d)` takes a required `Disambiguation`, one of `Compatible()`, `Earlier()` and `Later()`; and `dt.in_zone_exact(tz) -> ZonedDateTime | None` is `None` in a gap or fold. `ZonedDateTime` has `instant`, `plain`, `zone` and `offset_seconds()`. `z + Duration` is exact and `z + Period` adds on the wall clock and resolves again with `Compatible`. `show` is RFC 9557 (`2024-03-10T03:00:00-04:00[America/New_York]`), and `parse` requires the bracketed zone and fails with `Offset` when the offset disagrees (R601). `x.strftime(fmt)` on the civil types, `ZonedDateTime` and `Instant` (in UTC), and `T.strptime(s, fmt) -> T fail TimeError`, use Jiff's directives with English names only; a literal `fmt` is checked against the type (E542), and localized formats are `@yan/i18n` (R602). `env.local_zone()` reads `TZ`, then the platform setting, then UTC under `os`, and is UTC under the test `env` handler unless the test binds a zone (R603).

**Internationalization (R330 to R339).** Accepted 2026-10-31 from the internationalization design (https://claude.ai/artifact/FaTXsnXRwSKtK8fgPH9SDM). R330, R331 and R336 are in 3.3; R338 is in 13.1.

**Locales (R332).** `Locale` in `@yan/i18n` is a Unicode BCP 47 locale identifier with `-u-` extensions, canonicalized on parse (`LocaleError` otherwise); a malformed literal is E550 at stage 0. It is `trivially copyable` when it has no extensions. A locale is a value passed to formatter constructors and never ambient: nothing reads `LANG`, `LC_ALL` or the OS preference implicitly. `env.locales() -> List[Locale]` returns the host's preference list under `env`, and the test handler returns `[Locale("und")]`. `i18n.negotiate(prefs, supported, default)` picks one.

**Locale data (R333).** CLDR data is the first-party data package `@yan/cldr`, pinned in `yan.lock` like `std.tzdb`; 1.0 pins CLDR 49. The manifest field `i18n = I18n(locales=[...], data=[...])` names the shipped locales and data keys, and stage 0 bakes that slice, with its CLDR parents, as static tables. `i18n.load_blob(fs, path)` loads an ICU4X data blob for an open set of locales and is the only i18n call that takes a capability. A locale outside the data falls back along the CLDR parent chain and never fails; `i18n.has_data(loc)` reports exact coverage.

**Engine (R334).** `@yan/i18n` binds ICU4X 2.x through its C ABI as an FFI package with safe wrappers. The interpreter and every native backend load the same library, so every formatter prints identical bytes on all of them. It provides `NumberFormat`, `CurrencyFormat`, `UnitFormat` (over `Quantity`), `PluralRules`, `DateTimeFormat`, `TimeZoneFormat`, `RelativeTimeFormat`, `ListFormat`, `DisplayNames`, `Collator` with `sort_key`, tailored `CaseMapper`, dictionary `Segmenter`, `Bidi`, and `CalendarDate[C]` for the CLDR calendars, convertible to and from `PlainDate`. Every formatter is immutable, `Send + Sync` and `uses none`.

**Messages (R335).** Messages are Unicode MessageFormat 2.0. A record marked `@messages(source="<locale>")` holds the source text as MF2 strings; comptime parses each one, derives each variable's type from its annotation (unannotated is `Str`) and generates a typed method taking a `Locale` and keyword arguments. Translations are `i18n/<locale>.mf2` files, one `key = message` entry per field. `yan build` checks them: a malformed message or unknown function is E551, a key not in the source record E552, an undeclared or mistyped variable E553, a `.match` that misses one of the locale's CLDR plural categories without a `*` arm E554, and unbalanced or unknown markup E555. A key missing from a shipped locale is W841 and formats the source text. Messages compile to per-locale plans at stage 0; custom functions are `@mf2_function` functions, `uses none`. `yan run --pseudo-locale` substitutes `en-XA` and `ar-XB`.

**Localized diagnostics (R337).** English is the normative text of every diagnostic, and the catalogue's MF2 templates (R297) are the translation source. JSON, the patch protocol and MCP always carry `code`, `args` and the English `message`; an optional `message_localized` appears only when a human locale is requested. Terminal output uses `--lang`, then `YAN_LANG`, then English, never `LANG`; a missing translation falls back per message. 1.0 ships English only; translations ship later as data packages `@yan/diag-<locale>` pinned to a toolchain minor.

**Display width (R339).** Diagnostic carets, `std.fmt` tables and the formatter's line-length limit (18.5) count terminal columns with `std.unicode.width` over graphemes.

### 17.6 Networking defaults

- **Authority.** `net.only(connect=..., listen=...)` attenuates `net` by host, port and CIDR. After DNS, loopback, link-local, private and metadata addresses need an explicit grant. Package ceilings may carry the same patterns.
- **Other attenuators (R674).** `fs.only(read=..., write=...)` and `fs.sub(dir)` limit `fs` to directory trees; a path resolves beneath its grant with no `..` above it and no symlink out of it (`openat2` with `RESOLVE_BENEATH` where the OS has it). `proc.only(programs=...)` limits `proc` to named executables and `env.only(vars=...)` limits `env` to named variables. Package ceilings may carry the same patterns (R556).
- **TLS.** Defaults: TLS 1.3, plus TLS 1.2 limited to ECDHE, AEAD and Extended Master Secret; groups X25519MLKEM768, X25519, secp256r1 in that order; ML-DSA certificates accepted; ECH client with GREASE; 0-RTT off; RFC 8879 certificate compression; kTLS opt-in on Linux. Certificate verification can be disabled only by a test handler. TLS, HTTP and crypto security defaults may change in a minor release (20.2). **Profiles (R825).** `tls.Profile` is a closed enum: `tls.compatible` is the default set above and `tls.modern` is TLS 1.3 only with the same groups and certificate rules. A client defaults to `compatible` and a server to `modern`; a server that must serve older clients names `tls.compatible`. `.only(versions=..., groups=..., suites=..., signatures=..., pins=...)` only narrows: the result is the intersection with the profile, an empty result fails at construction, and SPKI pins never replace chain verification. There is no weaker profile and no raw configuration; legacy peers go through FFI. Profile contents tighten under their names (20.2) and 1.0 has no dated names. `yan audit` and `--diff` report the effective profile, literal `.only` arguments and non-literal profiles, and export them to `--policy`. FIPS is a toolchain and target property after 1.0, not a profile.
- **Protocol cores.** DNS, HTTP/1.1, HTTP/2 and QUIC are sans-I/O state machines written in Yan whose parsers are `uses none`. HTTP/1.1 parsing rejects obs-fold, bare CR or LF, Content-Length with Transfer-Encoding, duplicate Content-Length, and whitespace before the colon.
- **HTTP/2** uses RFC 9218 priorities and RFC 8441 extended CONNECT, with default limits against Rapid Reset, MadeYouReset, CONTINUATION floods, HPACK bombs and control-frame floods.
- **QUIC and HTTP/3** (v1 and v2) ship as sans-I/O `@yan/quic` and `@yan/http3` behind the `std.http` `Transport` trait, chosen by Alt-Svc and HTTPS records and raced by Happy Eyeballs v3. CUBIC is the default congestion control, BBR opt-in. `@yan/quic` is a std candidate in M4 after one milestone under the simulator.

### 17.7 Simulation

`std.sim` runs simulated hosts, each with its own `net`, `fs`, `time`, `rand`, `crypto_rand`, `env`, task tree and arena, on one seeded scheduler and virtual clock. It injects network faults, TigerBeetle-style disk faults, crashes and restarts through `fault.maybe(name)` points, supports swarm testing and `check_eventually`, and replays any seed exactly. CI reruns sampled seeds and compares trace hashes.

### 17.8 Python bridge

`py` is a dedicated executor that owns the interpreter. On a GIL build, calls are serialized. On free-threaded CPython 3.14t and later, `py(threads=N)` runs calls in parallel only for modules that declare free-threading support. `Py[T]` handles are reference counted and released on the `py` executor. A Python exception becomes `fail PyErr {type, msg, traceback}`, `KeyboardInterrupt` becomes cancellation, and a Yan panic aborts the process. Unpickling is available only for inputs marked `@trusted_input`. The Python packages a program imports are declared in `python` and locked by the root (19.1, R638). Extensions in the other direction are section 12.7.

**Import (R931).** `yan import --python` reads typed Python 3.12 and prints Yan Agent text. It applies the lenient-reader normalizations that concern Python source (N01, N04, N08, N10, N14 to N23, N33 to N35, N44 to N48) and lists each as a note on standard error. A construct with no normalization stays an error that names the line and the Yan Agent form to write: an unannotated parameter or return, `*args` and `**kwargs`, `global`, `nonlocal`, `del`, `async`, and `try` and `raise` (E120). It is never a bare E200.
