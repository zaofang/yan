## 17. Standard library

The standard library is written in Jian wherever possible, with intrinsics for the rest, and every unsafe block in it is tested under `yong test --ub` (6.9). Names below are in Jian spelling. This is the normative minimum; the full module list, tiers and milestones are the Yong standard library roadmap (https://claude.ai/artifact/HL2DZtHxuCaLofedMN4tT5), whose M1 row is the M1 subset. The implementer MAY add functions but MUST NOT change these signatures without a `SPEC_QUESTIONS.md` entry. Every `pub` std item carries `@since` (20.3).

**Intrinsics (R474).** A std function whose body cannot be written in Jian is declared as `@intrinsic def name(params) -> T: ...`, a full signature with `...` as its body. Each implementation (interpreter, Cranelift, LLVM) supplies the body by the function's Yong path. `@intrinsic` is reserved to the `std` package; anywhere else it is an unknown attribute. The intrinsics form a closed list kept in `yong-std`, and the Yong scalar intrinsics of section 3 (`add_checked_i64`, `eq_f64`, ...) are part of it.

### 17.1 Tiers and placement

| Tier | Contains | Needs |
| --- | --- | --- |
| `core` | scalars, `Option`, `Result`, traits, `View`, iterators, `core.ffi`, atomics, `math`, units, bundled zones and `ZonedDateTime`, formatting into a buffer | nothing |
| `alloc` | `Str`, `List`, `Map`, `Set`, collections, `Rc`, `Arc`, `Soa`, `Pool`, `Buffer`, `Bitmap`, allocators, `Array`, `Table` kernels | the `alloc` capability |
| `std` | OS handlers for every built-in capability, `fs`, `net`, `proc`, `env`, `signals`, `py`, record and replay | a hosted platform |

A module belongs in std only if it is shared vocabulary, a capability handler or needed by the M1 evaluation; if its target is frozen; and if one implementation beats many (security, determinism). Anything else is a first-party `@yong/*` package with its own semver and ceiling, included in ecosystem runs (20.7). First-party packages at 1.0 include `@yong/i18n` (ICU4X), `@yong/parquet`, `@yong/frame`, `@yong/adbc`, `@yong/sql`, `@yong/object_store`, `@yong/ecs`, `@yong/quic`, `@yong/http3`, `@yong/sqlite`, `@yong/postgres`, `@yong/otel`, `@yong/markdown`, `@yong/html`, `@yong/websocket`, `@yong/yaml`, `@yong/cbor`, `@yong/msgpack`, `@yong/protobuf`, `@yong/grpc`, `@yong/fancy_regex`, `@yong/rand_distr`, `@yong/blas`, @yong/rel, @yong/fasthash and the compression codecs.

**Embedded and GPU profiles (R320 to R329).** Accepted 2026-10-31 from the embedded and GPU profiles design (https://claude.ai/artifact/4vauJ4fyd3eUSTWJqXhiTx).

**Profiles (R320).** A profile is a named, closed set of restrictions enforced by the checker over the transitive call graph, like a capability ceiling. A profile MUST NOT change the meaning of any program that passes it. `profile = "embedded"` in `package.jian` applies to the whole program and implies platform `freestanding`, the stack bound of R321, no implicit `alloc` handler and `@forbid(rc)` unless the program binds a heap. `@kernel` on a function applies the `kernel` profile to it and its callees: no capability other than the tile intrinsics, `@forbid(alloc, rc)`, no recursion, no `dyn`, no `extern`, and only GPU-representable types (scalars, `Vec`, records of those, `f16`, `bf16`). A violation is E320, naming the profile and the rule. Profiles add attributes only (`@kernel`, `@interrupt`, `@task`, `@stack`), never keywords. `yong check --profile p` checks a library against a profile without a target.

**Static stack bound (R321).** Under `embedded`, the compiler MUST compute a sound maximum stack depth for every task and report it in `yong build`. The call graph MUST be acyclic except for `become` tail calls (R260). An `extern` function called from embedded code needs `@stack(bytes)`, a trusted claim listed by `yong audit`. A `dyn` call counts the deepest impl that reaches it. Interrupt tasks add their frames only at their own priority level. An unprovable bound is E321; a bound that exceeds the manifest's stack reserve is E322.

**Peripherals and HAL (R322).** A chip package generates its register blocks at stage 0 from the vendor's CMSIS-SVD file read with `embed(path)`. Each register is a `Reg[T, access]` whose operations lower to `read_volatile` and `write_volatile` (6.8). `main` receives one owned `Peripherals` value, and splitting it moves each peripheral out once. Pin modes are typestates. `std.embedded.hal` defines one trait set (digital, SPI with shared-bus devices, I2C, delay, PWM, UART). Its waits go through the bound I/O handler (9.7), so one driver serves blocking and async firmware.

**Embedded scheduling (R323).** `std.embedded` provides two `sched` handlers. `srp` runs hardware tasks bound to interrupt vectors to completion on one stack under the Stack Resource Policy; each `Resource[T]` gets a priority ceiling computed at compile time, and `r.lock()` raises the running priority to that ceiling. `executor` runs `par concurrent` tasks as generator state machines (10.5) in a static arena sized at compile time, idling with WFI or WFE, one instance per priority level. Both may be bound together, with an `executor` as an `srp` task. `@interrupt(VECTOR)` binds a function to a vector and `@task(priority=n)` sets its level. Holding a lock across a suspension point is E323. Accessing a `Resource[T]` from two priority levels shares non-Freeze state between tasks that may run at once and needs `uses nondet` (E709). Under the replay handler, `srp` records task dispatch order with its inputs, so `yong replay` reproduces a firmware trace on the host.

**Abort and logging (R324).** On `freestanding` the program binds an `abort` handler (`reset`, `halt` or `breakpoint`, each optionally logging first); panics still abort (8.3). The `log` capability uses deferred formatting: stage 0 interns each format string into a non-loaded section, the device sends the string's index and binary arguments, and `yong log` decodes them. Transports are RTT, semihosting and UART.

**Embedded atomics (R325).** `Atomic[T]` stays lock-free only (E418). On cores without compare-and-swap, `Atomic[T]` has load and store only. Read-modify-write without hardware support uses the `critical_section` capability, `std.embedded.CsMutex[T]` (interrupt masking on one core, the hardware spinlock across cores) or the explicit type `CsAtomic[T]`.

**Embedded targets (R326).** Tier 1: `thumbv8m.main-none-eabihf` and `riscv32imac-none`. Tier 2: `thumbv7em-none-eabihf` and `thumbv6m-none-eabi`. The reference board is the Raspberry Pi Pico 2 (RP2350, Cortex-M33 and Hazard3 RISC-V). The manifest's `embedded` field gives chip, memory map and stack reserve, and stage 0 generates the linker script. `yong run --target` flashes through a pinned probe-rs and streams `log` over RTT. `--release=size` is the size-optimised release build. CI runs QEMU for both tier-1 targets; hardware-in-the-loop runs are nightly.

**GPU programming model (R327).** A `par for` whose body is `uses none`, and math `Array` operations, run on the device when a `gpu` handler is bound and the data is in a `DeviceArray`. A `@kernel` function computes one output tile per program instance over `Tile[M, N, T]` values with `load`, `store`, elementwise arithmetic, `dot`, `reduce`, `scan` and `where`; tile shapes are `Nat` parameters, and a shape mismatch is E521. The compiler maps tiles to threads, shared memory and tensor cores. Safe code has no thread indices, shared memory or warp operations. Bounds checks stay on; a failed check traps the kernel and the launch fails with `KernelFault` carrying the program id and span.

**GPU determinism (R328).** Without `@fast_math`, kernels use IEEE arithmetic with subnormals kept, no contraction into FMA unless written, the correctly rounded functions of 11.1, and the fixed reduction tree of 9.3 for `reduce` and `dot`; safe kernels have no float atomics. A kernel MUST then give bit-identical results on every `gpu` handler, including `cpu`. `@fast_math`, which requires `nondet` (7.1), permits tensor-core `dot` (TF32, BF16 and FP8 with FP32 accumulate), flush-to-zero, approximate transcendentals and atomic reductions.

**GPU capability and backends (R329).** `gpu` is a capability written in `uses`. Its handlers are `cpu` (always available; the conformance oracle), `metal`, `cuda`, `rocm` and `vulkan`. `DeviceArray[axes..., T]` is an owned buffer from the bound handler. Moving or viewing an array into a launch makes it unusable on the host until the launch completes. Launches are I/O-handler operations and overlap under `par concurrent`. Lowering goes from Yong IR through MLIR (`linalg`, `vector`, `scf`, `gpu`) to NVVM, ROCDL and SPIR-V; `metal` lowers through LLVM IR to AIR. `metal` is the first hardware backend and `cuda` the second; `rocm` and `vulkan` are tier 2.

### 17.2 Method resolution and prelude

**Method resolution (normative).** `x.f(...)` resolves `f` by looking, in order, in the current module, then the module that declares the type of `x`, then the prelude. For a receiver of type Actor\[S\] or Remote\[Actor\[S\]\], the second step also searches the module that declares S, among functions whose first parameter is var self: S, and the call sends a message (R435). The first step that has `f` wins, and lint W819 flags a match that hides a function of the same name at a later step (R348). Two functions of one name at one step are E250, reported at the second definition (R469). This is how `xs.get(i)` on a list and `d.get(k)` on a dict reach different functions without overloading, and why a dependency that adds a function never changes or breaks a call in another package.

**Declaring modules of built-in types (R475).** For the second step, the built-in types are declared in these std modules: `str` and `char` in `std.text`, `list` in `std.list`, `dict` in `std.dict`, `set` in `std.set`, `bytes` in `std.encoding`, the scalars and `bigint` in `std.num`, and `Result` and `Option` in `std.result`. So `s.partition("=")` is `std.text.partition(s, "=")` and `xs.index(2)` is `std.list.index(xs, 2)`.

**Optional values in Yong text (R476).** `T | None` is `Option[T]`, whose variants are spelled `Some { value: v }` and `None` in Yong text, as `Result`'s are `Ok { value: v }` and `Err { error: e }`.

**List append (R477).** The one operation that adds an element at the end of a list is `append`: Jian and Wen write `xs.append(v)`, and Yong text calls `std.list.append[T](inout xs, sink v)`. std has no `push`.

**F-strings in Yong text (R478).** An f-string lowers left to right. Each literal part is a `str` literal. Each `{x}` is `std.fmt.show[T](let x)`, or `x` itself when `T` is `str`. Each `{x:fmt}` is `std.fmt.show_spec[T](let x, "fmt")`, where `fmt` is a stage-0 constant checked against `T` at compile time. The parts are joined by a left-nested chain of `std.text.concat`, which in-place concatenation (R388) keeps linear, and an f-string with no parts is `""`. Wen's `\(x)` and `\(x:spec)` interpolation lowers the same way.

**std.regex (R482 to R486).** The API follows Python's `re` within linear-time matching. `compile(pattern: str) -> Regex fail RegexError` and `escape(s: str) -> str` are free functions. `Regex` has `search`, `match` (anchored at the start) and `fullmatch` (anchored at both ends), each returning `Match | None`, plus `find_all -> list[Match]` (non-overlapping, left to right), `split -> list[str]` and `sub(repl, s) -> str`. `Match` has `text`, `group(i)` and `named(name)`, which return `str | None`, and `start` and `end`. `RegexError` holds `pattern` and `reason`. All results are materialized lists. `find_all` returns `Match` values, not Python's group-dependent strings or tuples (R482). `start` and `end` count chars, as `char_count` does (R483). A `compile` whose argument is a string literal is checked at stage 0, and a rejected pattern (syntax, a backreference or lookaround, or over the size limit) is E545. Such a call cannot fail and needs no `?` or `else`; a non-literal pattern fails with `RegexError` at run time (R484). `sub` takes Python's replacement syntax `\1`, `\g<name>` and `\\` (R485). A compiled automaton may take at most 1 MiB; a larger one is E545 for a literal, or `RegexError` with reason `too large` (R486).

**std.collections (R488 to R493).** `deque[T]` has `append`, `appendleft`, `pop`, `popleft`, `first`, `last`, `extend`, `rotate(n)` (right by n, left when negative), `clear`, `maxlen`, indexing, `len`, `in` and front-to-back iteration. `heap[T: Ord]` has `push`, `pop`, `peek`, `pushpop`, `into_sorted` (`take self`, ascending) and `len`. `sorted_dict[K: Ord, V]` and `sorted_set[T: Ord]` have every `dict` and `set` method with the same names, iterate in ascending order, and add `first`, `last`, `pop_first`, `pop_last`, `floor(k)` (greatest key <= k), `ceiling(k)` (least key >= k) and `range(lo, hi)` (lo <= key < hi, a list); a sorted\_dict query returns `tuple[K, V]`. The constructors `deque()`, `deque(xs)`, `deque(xs, maxlen=n)`, `heap()`, `heap(xs)` (heapify, O(n)), `sorted_dict()`, `sorted_dict(d)`, `sorted_set()` and `sorted_set(xs)` are prelude calls like `list(xs)`, with no literal syntax (R488). `pop`, `popleft` and `heap.pop` panic with `bounds` on an empty collection; `first`, `last`, `peek`, `pop_first` and `pop_last` return `T | None` (R489). A deque built with `maxlen` drops one element from the other end when an append would exceed it, as Python's does (R490). A heap is not iterable, and `str(h)` lists its elements in ascending order, so output does not depend on the heap's layout; a max-heap is `heap[cmp.Reverse[T]]` (R491). Sorted types have no positional indexing in 1.0 (R492). Show formats follow CPython's repr: `deque([1, 2])`, `deque([1, 2], maxlen=3)`, `heap([1, 2, 5])`, `sorted_dict({1: 'a'})`, `sorted_set({1, 2})` and `sorted_set()` (R493).

**List slices and bisect (R494 to R499).** `list[T]` has `insert(i, x)`, `sort()` (stable, ascending, in place, `T: Ord`), `sort_unstable()`, `reverse()` (in place), `bisect_left(x)` and `bisect_right(x)` (each `-> int`), `insort(x)` (inserts at `bisect_right(x)`) and `slice_exact(start, stop) -> list[T]`. They are methods in `std.list`; `std.slices` will carry the same names over `View[T]` and `MutView[T]` when views are implemented (R494). The bisects take Python's names and no `lo` or `hi`; there is no bare `bisect` (R495). `key=` on `sort`, the bisects and `insort` comes with closures, with Python's meaning (R496). Descending order is `sort()` then `reverse()`; `sort` takes no `reverse=` (R497). `insert(i, x)` clamps as Python does: a negative `i` counts from the end, and an index past either end inserts at that end (R498). `slice_exact(start, stop)` panics with `bounds` unless `0 <= start <= stop <= len`, and takes no negative indices (R499).

**std.math (R500 to R507).** The bundled libm is CORE-MATH, whose binary64 functions are proven correctly rounded; `sqrt`, `fma` and the four arithmetic operations are IEEE exact in hardware, and every `std.math` function is tier E (R500). `std.math` covers `float` now: `exp exp2 exp10 expm1 exp2m1 exp10m1 log log2 log10 log1p log2p1 log10p1`, `pow pown powr sqrt cbrt rsqrt hypot`, `sin cos tan sinpi cospi tanpi asin acos atan atan2 asinpi acospi atanpi atan2pi`, `sinh cosh tanh asinh acosh atanh`, `erf erfc lgamma tgamma`, and the exact `add sub mul div fma floor ceil trunc fmod remainder copysign ldexp frexp next_up next_down is_nan is_inf is_finite`. `compound` and `rootn` follow when a correctly rounded binary64 version exists; the C aliases `scalbn`, `nextafter`, `fabs`, `fmin` and `fmax` are left out; the other widths follow their types (R501). Names are the C23 ones, with IEEE 754 `next_up`/`next_down` and snake\_case predicates, called as `math.exp(x)` (R502). A domain error or overflow gives the IEEE result, NaN or an infinity, never a panic (R503). `type Round = NearestEven() | Up() | Down() | TowardZero()` is declared in `std.math` and passed as `round=math.Up()`. The exact operations, `sqrt`, `sum_exact` and `dot_exact` honor all four modes in every implementation; the interpreter runs the libm functions in `NearestEven()` only and reports another mode as not supported until codegen (R504). `sum_exact(xs, round)` and `dot_exact(xs, ys, round)` compute the exact sum and round once, with IEEE 754 zero signs and special values and no intermediate overflow; `dot_exact` panics with `value` when the lengths differ (R505). The constants are `pi`, `e`, `inf` and `nan` (R506). The `grad` family is not part of `std.math`'s first release; it gets its own proposal at M4 (R507).

**std.iter (R508 to R515).** Until user `Iterator` impls exist, `std.iter` provides one built-in lazy type `iter[T]`, the `Iterator` with `Item = T`: single pass, and an exhausted one keeps returning `None`; `for` consumes it, and when associated types arrive `iter[T]` names `dyn Iterator[Item = T]` with no program change (R508). Sources: `xs.iter()` on `list`, `set`, `dict` (keys, insertion order), `str` (chars), `deque` and the sorted types, plus `iter.count(start=0, step=1)`, `iter.repeat(x, n=None)`, `iter.once(x)` and `iter.empty()`; `range` stays a list (R509). Lazy adapters: `map`, `filter`, `take_while`, `drop_while`, `take`, `skip`, `step_by`, `zip` (stops at the shorter), `enumerate`, `flat_map`, `chain`, `windows(n)` and `chunks(n)`, whose items are `list[T]` copies until views exist; `chunks` keeps a short last chunk, and `n < 1` panics with `value` (R510). Consumers: `next`, `collect() -> list[T]`, `fold`, `count`, `any`, `all`, `find`, `min`, `max` (`None` when empty) and `sum` (the reduction order of 9.3); `set`, `dict` and `sorted` take an iterator directly (R511). `list.map`, `list.filter` and `list.fold` stay eager and return lists (R512). `xs.iter()` borrows `xs` and is second-class under the view rule (E414 when stored or returned; mutating `xs` meanwhile is an exclusivity error); the owning sources are first-class; the checks arrive with views (R513). `sorted`, `list.sort`, `sort_unstable`, the bisects, `insort`, `min`, `max` and `iter.min`/`iter.max` take `key: (T) -> K` with `K: Ord`, Python's meaning, calling `key` once per element in the sorts (R514, carrying R496). A pipeline pulls one item at a time from its end, so closure effects interleave per item and a pipeline stops as soon as its consumer is done (R515).

**Prelude** (unqualified in both surfaces; Jian spelling):

- Types: `int`, `bigint`, `float`, `bool`, `str`, `char`, `bytes`, `decimal`, the sized scalars, `list`, `dict`, `set`, `deque`, `heap`, `sorted_dict`, `sorted_set`, `soa`, `tuple`, `Result`, `Ok`, `Err`, `View`, `MutView`, `StrView`, `Rc`, `Arc`, `Weak`, `Array`, `Table`, `Quantity`, `Money`, `Secret`, `PlainDate`, `PlainTime`, `PlainDateTime`, `ZonedDateTime`, `Instant`, `MonoInstant`, `Duration`, `Period`.
- Traits: `Eq`, `Ord`, `Hash`, `Show`, `Default`, `Num`, `Field`, `Pow`, `Bits`, `Concat`, `MatMul`, `Monoid`, `From`, `Wire`, `Share`, `Iterator`, `IntoIter`, `Len`, `Send`, `Sync`, `Freeze`.
- Functions: `len` (not on `str`), `range`, `enumerate`, `zip`, `min`, `max`, `sum`, `any`, `all`, `sorted`, `reversed`, `abs`, `round`, `float`, `int`, `str`, `list` (an owned list from any iterable, R218), `evolve`.

| `test` | `fake_fs(files)`, `fixed_time(instant)`, `virtual(start)`, `seeded(seed)`, `explore(bound)`, `replay(trace)`, a leak-checking allocator, snapshots, benchmarks with warmup and confidence intervals | none |
| `py` | `import_module(name) -> PyModule`, `call`, `to_table`, `from_table` (Arrow C Data Interface) | `py` |

An incompatible redesign of a std module ships as a `.v2` module (`std.rand.v2`); the old one is deprecated and never removed in 1.x (20.5).

**`@yong/rel` (R262).** `rel.program(text)` parses a stratified Datalog program at stage 0, as a comptime string DSL (10.4). It reifies one record type per relation and specialises a semi-naive solver, so nothing is interpreted at run time. Relations are typed, as in `rel edge(a: u32, b: u32)`, with fields that are `Eq + Hash + Ord`. Rules are written `head <- body.`. Negation MUST be stratified, and aggregates (`count`, `sum`, `min`, `max`) may read only lower strata; otherwise it is a stage-0 diagnostic. `!body.` declares an integrity constraint whose violations are rows of a generated `Violation` sum. Stores are sorted `Soa` columns. Join order and indexes are chosen at stage 0, and `@plan` overrides them per rule. Output is sorted by tuple, so results are bit-identical across runs and thread counts. `solve(par: true)` runs the independent rules of a stratum in parallel, with per-rule deltas. `solve(limit: n)` fails with `Budget` instead of diverging. It is a first-party package, not std (R448).

### 17.4 Data safety

**`Wire` decoding (normative).** One `derive(Wire)` drives every codec in std and `@yong`, generating a direct decoder and encoder per type at stage 0. Decoding produces only a statically known type. Sum types use their declared tags, and no tag can select an arbitrary type. No user code runs during decoding except validation and invariant checks after construction. Depth, total size, and collection and string lengths are always limited. Unknown fields and duplicate keys are rejected unless the type opts in. Capability values are never `Wire`.

**`Secret[T]`.** `Show` prints `Secret(***)`. A secret is not `Wire` until `expose()` is called, is zeroized on drop, compares in constant time, and appears hashed in replay traces. W803 flags an exposed secret flowing into `log`.

**`Untrusted[T]` (R451).** An untrusted value has unknown integrity. Every model result is untrusted (R450), as are `py` call results and HTTP bodies read with `body_untrusted()`, and any API may return `Untrusted[T]`. The value is opaque. `u.map(f)` with a pure `f` keeps the label, `u.validate(check)` with `check: Fn(sink T) -> T fail E` removes it, and `u.trust(reason="...")` removes it unchecked and is listed by `yong audit`. A parameter marked `@trusted` rejects an untrusted argument (E325). std marks `proc.Command` arguments, `fs` paths that write or remove, `net.only` grants, and SQL and shell text; `@trusted_input` (17.8) is one case of it. Formatting an untrusted value into an f-string gives `Untrusted[str]`, and interpolating it into a `Template` keeps its label for the sink's escaper (R452). Branching on an untrusted value needs an unwrap first, so every point where untrusted data steers control flow is visible and audited.

**Model calls (R450).** The first-party package `@yong/model` declares `@capability @shared trait Model` with `generate[T: Wire](prompt: Template) -> Untrusted[T] fail ModelError`, `embed` and `tool_call`. A handler uses the provider's constrained decoding where it exists and otherwise parses against the `Wire` schema; either way decoding follows the rules above, so a model never selects a type. `model.only(models=[...], max_tokens=n, max_cost=m)` attenuates the capability, and package ceilings may carry the same limits (19.2). Tests bind no model by default. `fake_model(...)` and `replay(trace)` are the test handlers, so a test that calls a model is cached like any other, and an `ex` line may bind `model = fake_model(...)`. Model operations are recorded under R305.

**Role-aware calls (R551).** `@yong/model` also declares `generate_chat[T: Wire](messages: List[Message]) -> Untrusted[T] fail ModelError`, with `type Message = { role: Role, content: Template }` and `Role` one of `system`, `user` and `assistant`. `generate(p)` is `generate_chat([Message(user, p)])`. A handler whose provider has no roles renders the messages in order under a fixed role header that the handler documents. `model.only`, `fake_model`, `replay` and recording apply as for `generate`.

**Errors.** Each module that can fail defines one error type (`FsError`, `HttpError`, `JsonError`, ...) as a record or sum with `Show`, `Eq` and `Wire`.

### 17.5 Time

Moving between exact and civil time always names a zone: `i.in_zone(tz)`, `dt.in_zone(tz, disambiguation)`, `z.instant`, `z.plain`. There is no implicit local zone; `env.local_zone()` is the only way to the host's zone. Calendar arithmetic uses `Period`; `Duration` is exact. The representation, range and equality rules are section 11.6, the tzdb rules section 7.5, and literal checks section 14.2.

**Internationalization (R330 to R339).** Accepted 2026-10-31 from the internationalization design (https://claude.ai/artifact/FaTXsnXRwSKtK8fgPH9SDM). R330, R331 and R336 are in 3.3; R338 is in 13.1.

**Locales (R332).** `Locale` in `@yong/i18n` is a Unicode BCP 47 locale identifier with `-u-` extensions, canonicalized on parse (`LocaleError` otherwise); a malformed literal is E550 at stage 0. It is `trivially copyable` when it has no extensions. A locale is a value passed to formatter constructors and never ambient: nothing reads `LANG`, `LC_ALL` or the OS preference implicitly. `env.locales() -> List[Locale]` returns the host's preference list under `env`, and the test handler returns `[Locale("und")]`. `i18n.negotiate(prefs, supported, default)` picks one.

**Locale data (R333).** CLDR data is the first-party data package `@yong/cldr`, pinned in `yong.lock` like `std.tzdb`; 1.0 pins CLDR 49. The manifest field `i18n = I18n(locales=[...], data=[...])` names the shipped locales and data keys, and stage 0 bakes that slice, with its CLDR parents, as static tables. `i18n.load_blob(fs, path)` loads an ICU4X data blob for an open set of locales and is the only i18n call that takes a capability. A locale outside the data falls back along the CLDR parent chain and never fails; `i18n.has_data(loc)` reports exact coverage.

**Engine (R334).** `@yong/i18n` binds ICU4X 2.x through its C ABI as an FFI package with safe wrappers. The interpreter and every native backend load the same library, so every formatter prints identical bytes on all of them. It provides `NumberFormat`, `CurrencyFormat`, `UnitFormat` (over `Quantity`), `PluralRules`, `DateTimeFormat`, `TimeZoneFormat`, `RelativeTimeFormat`, `ListFormat`, `DisplayNames`, `Collator` with `sort_key`, tailored `CaseMapper`, dictionary `Segmenter`, `Bidi`, and `CalendarDate[C]` for the CLDR calendars, convertible to and from `PlainDate`. Every formatter is immutable, `Send + Sync` and `uses none`.

**Messages (R335).** Messages are Unicode MessageFormat 2.0. A record marked `@messages(source="<locale>")` holds the source text as MF2 strings; comptime parses each one, derives each variable's type from its annotation (unannotated is `Str`) and generates a typed method taking a `Locale` and keyword arguments. Translations are `i18n/<locale>.mf2` files, one `key = message` entry per field. `yong build` checks them: a malformed message or unknown function is E551, a key not in the source record E552, an undeclared or mistyped variable E553, a `.match` that misses one of the locale's CLDR plural categories without a `*` arm E554, and unbalanced or unknown markup E555. A key missing from a shipped locale is W841 and formats the source text. Messages compile to per-locale plans at stage 0; custom functions are `@mf2_function` functions, `uses none`. `yong run --pseudo-locale` substitutes `en-XA` and `ar-XB`.

**Localized diagnostics (R337).** English is the normative text of every diagnostic, and the catalogue's MF2 templates (R297) are the translation source. JSON, the patch protocol and MCP always carry `code`, `args` and the English `message`; an optional `message_localized` appears only when a human locale is requested. Terminal output uses `--lang`, then `YONG_LANG`, then English, never `LANG`; a missing translation falls back per message. 1.0 ships English only; translations ship later as data packages `@yong/diag-<locale>` pinned to a toolchain minor.

**Display width (R339).** Diagnostic carets, `std.fmt` tables and the formatter's line-length limit (18.5) count terminal columns with `std.unicode.width` over graphemes.

### 17.6 Networking defaults

- **Authority.** `net.only(connect=..., listen=...)` attenuates `net` by host, port and CIDR. After DNS, loopback, link-local, private and metadata addresses need an explicit grant. Package ceilings may carry the same patterns.
- **TLS.** Defaults: TLS 1.3, plus TLS 1.2 limited to ECDHE, AEAD and Extended Master Secret; groups X25519MLKEM768, X25519, secp256r1 in that order; ML-DSA certificates accepted; ECH client with GREASE; 0-RTT off; RFC 8879 certificate compression; kTLS opt-in on Linux. Certificate verification can be disabled only by a test handler. TLS, HTTP and crypto security defaults may change in a minor release (20.2).
- **Protocol cores.** DNS, HTTP/1.1, HTTP/2 and QUIC are sans-I/O state machines written in Yong whose parsers are `uses none`. HTTP/1.1 parsing rejects obs-fold, bare CR or LF, Content-Length with Transfer-Encoding, duplicate Content-Length, and whitespace before the colon.
- **HTTP/2** uses RFC 9218 priorities and RFC 8441 extended CONNECT, with default limits against Rapid Reset, MadeYouReset, CONTINUATION floods, HPACK bombs and control-frame floods.
- **QUIC and HTTP/3** (v1 and v2) ship as sans-I/O `@yong/quic` and `@yong/http3` behind the `std.http` `Transport` trait, chosen by Alt-Svc and HTTPS records and raced by Happy Eyeballs v3. CUBIC is the default congestion control, BBR opt-in. `@yong/quic` is a std candidate in M4 after one milestone under the simulator.

### 17.7 Simulation

`std.sim` runs simulated hosts, each with its own `net`, `fs`, `time`, `rand`, `crypto_rand`, `env`, task tree and arena, on one seeded scheduler and virtual clock. It injects network faults, TigerBeetle-style disk faults, crashes and restarts through `fault.maybe(name)` points, supports swarm testing and `check_eventually`, and replays any seed exactly. CI reruns sampled seeds and compares trace hashes.

### 17.8 Python bridge

`py` is a dedicated executor that owns the interpreter. On a GIL build, calls are serialized. On free-threaded CPython 3.14t and later, `py(threads=N)` runs calls in parallel only for modules that declare free-threading support. `Py[T]` handles are reference counted and released on the `py` executor. A Python exception becomes `fail PyErr {type, msg, traceback}`, `KeyboardInterrupt` becomes cancellation, and a Yong panic aborts the process. Unpickling is available only for inputs marked `@trusted_input`. Extensions in the other direction are section 12.7.
