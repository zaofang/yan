## 9. Yong: concurrency and I/O

All concurrency is structured: every task has a parent scope that outlives it. Races are impossible in safe code (section 6.5), and remote execution is visible in types.

### 9.1 Execution model

There is no language runtime. `par`, `par for` and `par concurrent` lower to calls on the bound `sched` handler. std provides:

| Handler | Behavior |
| --- | --- |
| `sequential` | runs plain par branches to completion in source order on the current thread; runs par concurrent branches and actors cooperatively, switching at blocking operations to the lowest-index runnable task, so it gives concurrent progress deterministically (R390) |
| `seeded(seed)` | deterministic interleavings for tests, uniform or PCT, over baton-passing OS threads |
| `pool` | fork-join over OS threads, one per core (the hosted default) |
| `explore(bound)` | exhaustive model checking in the reference interpreter (6.9) |
| `std.evented` handlers | carriers on stackful coroutines with io\_uring, epoll, kqueue or IOCP (9.7) |

Plain `par` may run its branches in any order or in sequence. Branches that must make progress at the same time, such as the two ends of a channel, use `par concurrent`, which requires a handler that guarantees concurrent progress (E708 otherwise). Code is the same under every handler, and there is no `async`/`await` and no function colouring.

### 9.2 `par` blocks

`par` runs each top-level statement of its block as a child task (a compound statement, or a `let` with an indented block, is one statement) and completes when all have completed.

- Exclusivity (section 4.3) is checked across all branches together. A value borrowed by two branches MUST be Sync (E417). A read in one branch of a place another branch writes is E705.
- Values a branch reads from the enclosing scope are borrowed for the block, with no counting.
- Split capabilities (7.1: `rand`, `fault`, `io`, `log`, `metrics`) give each branch its own handle, and buffered output is committed in source order at the join. In par concurrent and in a streaming par for, output is emitted at once instead, each write atomic and tagged with (task path, sequence number); live sinks show arrival order, test, snapshot and replay sinks sort on the tag, and no result depends on the order (R398). Shared capabilities are used by every branch at once, and an exclusive capability in two branches is E402 (R342).
- A typed failure in branch k cancels only later branches; the lowest failing index wins, independent of schedule (SQ16). The cancelled branches' drops run, and their buffered output of split capabilities is dropped, never committed (R342). A panic in any branch aborts the process.
- **Failure in `par concurrent` (R394).** The rule above holds for plain `par` and `par for`. In `par concurrent`, a typed failure cancels every other branch, earlier and later, and the block returns the lowest-index failure that was not `Cancelled`. The result is deterministic when at most one branch can fail on its own, and otherwise falls in the replay tier (7.7).
- **Sibling waits (R390).** A branch of a plain `par` MUST NOT wait on a sibling: a channel operation whose other end is reachable from another branch of the same block is E713, fixed by `par concurrent`. Waits on I/O, timers, actors and tasks outside the block are allowed.
- Bindings made in a branch are visible after the block. Their values do not depend on scheduling.

### 9.3 `par for` and `par_fold`

`par for x in xs { body }` evaluates the body for each element, possibly concurrently, and returns a `List` in input order. The body may read the enclosing scope but MUST NOT take `inout` access to anything outside its own iteration.

A `par for` whose body has type unit returns unit, streams over its iterator and takes `limit: n` (default: the sched handler's width). Its body MUST NOT fail (E712): each item handles its own failures, so one failing item cannot cancel the stream (R349). With `concurrent` it serves unbounded streams such as accept loops; `listener.incoming(net)` under `par for` with `limit: n` stops accepting at n open connections.

Items of a plain `par for` follow the sibling-wait rule of 9.2 (E713, R390). In a streaming `par for`, `Draining` from the iterator ends the stream normally. Any other iterator failure stops intake, waits for in-flight items and then propagates (R399).

`par_fold(xs, m)` is a std function, not syntax (R446): it reduces `xs` with the `Monoid` instance `m` on the bound `sched` handler. **Reduction order (R382).** Every deterministic fold (`par_fold`, `sum`, `dot`, `ColExpr` reductions and query aggregates) uses one order. The input is cut into blocks of 4096 elements. In each block, element i goes to lane i mod 64, each lane folds left to right from the identity, and the 64 lanes combine by the fixed tree; blocks combine by the fixed tree. The fixed tree splits n at the largest power of two below n, down to single leaves (SQ17). The identity of float `+` is -0.0. Chunks chosen by the `sched` handler MUST be multiples of 4096, so chunking never affects results. The order vectorizes at any width up to 64 lanes and is bit-identical on scalar targets.

**Lanes (R624).** A `par for` whose body is `uses none` MAY run several iterations at once in SIMD lanes, with divergent branches masked (partial control-flow linearization, PLDI 2018). Lanes are separate iterations and no reduction is reordered, so results are identical to scalar execution. In a function marked `@vectorize` (5.7) this is an obligation: each line that prevents it is E900.

**Scans (R628).** `par_scan(xs, m)` returns the inclusive prefix folds of `xs` under the `Monoid` instance `m`, a `List` in input order, on the bound `sched` handler. It follows the R382 order: each block is scanned by lanes, block totals are scanned by the fixed tree, and offsets are folded back, so results do not depend on width or thread count. An affine recurrence `s = a * s + b` scans as pairs, with `(a1, b1)` then `(a2, b2)` composing to `(a2 * a1, a2 * b1 + b2)`. The optimizer MAY run a `for` loop that computes an integer affine recurrence as such a scan when the 8.6 solver proves that no composed coefficient overflows. It MUST NOT do so for floats, whose rounding would change; a float recurrence runs in parallel only through an explicit `par_scan`.

**Lattice cells (R454).** `trait Lattice` declares `bottom() -> Self` and `join(self, other: Self) -> Self`, which MUST be commutative, associative and idempotent. `Lub[L: Lattice]` in `std.sync` is a Sync cell. Inside a `par` block or collecting `par for` that writes it, the only operation is `put(x)`, which joins `x` in. `get()` is legal only after the block, on its success path; a `get()` inside a block that writes the cell is E717. std provides `Max[T: Ord]`, `Min[T: Ord]`, `Or`, `And`, `BitSet`, union over `sorted_set[T]` and pointwise `MapLub[K: Ord, L]`, and `derive(Lattice)` builds products. What a reader observes never depends on write order, so set lattices iterate in sorted order. A hand-written `impl Lattice` is `unsafe impl` (L6) and is listed by `yong audit`, because an unlawful join would break law 7. Joining per-branch partials at the end of the block is always a conforming lowering; `pool` MAY use atomics or a sharded tree instead (6.5).

### 9.4 Cancellation, deadlines and drain

**Cancellation** is cooperative and is delivered only at blocking, fallible capability operations: `sleep`, `sleep_until`, `recv`, `send`, accept, connect, read, write and the other operations that wait. Every such operation's failure type includes `Cancelled`. In a cancelled task it returns `fail Cancelled` (or `fail Timeout` when a deadline expired) through the ordinary failure path, so drops run by ordinary scope exit and nothing unwinds. Non-blocking operations (`print`, `log`, `metrics`, `now`) never cancel, and pure loops are never interrupted; the drain grace period below covers CPU-bound work. Handlers may observe `Cancelled`, and W818 flags an `else` that discards it (R341).

**Deadlines.** `with deadline(t)` and `with timeout(d)` open cancel scopes that nest; the earliest deadline wins. A function whose body opens one always has Timeout in its fail type, even when nothing in the scope can block (R472). A deadline propagates to child tasks, actor calls and `Remote` calls, and lowers to `sleep_until(MonoInstant)`. Expiry is `fail Timeout`, not a panic.

**Default network deadlines.** Network operations without a scope deadline get std defaults: connect 10 s, TLS handshake 10 s, HTTP request head 10 s, no-progress read or write 60 s, keep-alive idle 60 s. Under io\_uring a deadline on a single operation lowers to a linked timeout on CLOCK\_BOOTTIME.

**Drain.** Cancel scopes have a drain phase. The first SIGINT or SIGTERM, or `scope.drain(grace)`, drains the scope: intake operations (accept, new HTTP/2 or QUIC streams) fail `Draining`, in-flight work continues, and after the grace period (default 30 s) or when all tasks finish, the scope is cancelled. Tasks still alive after the cancel grace that follows (default 10 s) abort the process with a task dump, so shutdown takes at most drain grace plus cancel grace (R399). A second signal exits at once. SIGPIPE is ignored, so writes fail with EPIPE. On hosted platforms std owns signal handling.

### 9.5 Channels and select

`Channel[T](capacity)` is bounded only; there are no unbounded channels. It is multi-producer and multi-consumer, with separate `Sender` and `Receiver` handles; payloads MUST be Send. `send` suspends when full; `try_send` returns `Full`. Closing the last sender ends receivers' iteration. `std.chan.select` waits on several channel operations, deadlines and cancellation at once; when several arms are ready, the first in source order wins. `share` of a `Sender` or a `Receiver`, `try_send`, `try_recv` and `select` require `uses nondet` (E709, R342).

**Protocols (R633).** `session.protocol(spec)` in `std.session` is a type function (10.4) whose stage-0 string declares a global protocol among named roles, in the style of Scribble: messages `A -> B: Label(T)`, sequence `;`, a choice made by one role `choice A { ... | ... }`, named recursion `rec X { ... }` and `end`. For example, `type Fetch = session.protocol("client -> server: Get(str); choice server { server -> client: Found(bytes) | server -> client: Missing() }; end")`. The checker projects the protocol onto each role (multiparty session types, POPL 2008). A protocol that cannot be projected, such as a choice that a role taking part in a later step cannot observe, is E728 with the two branches that diverge.

**Endpoints (R634).** `session.connect[P]()` returns one endpoint per role of `P`, as a record with a field per role, each to be moved into its own `par` branch, task or actor. An endpoint type is `@linear` and names its role's current state. `send(ep, Label(x))` and `recv(ep)` take the endpoint by `sink` and return the endpoint of the next state; at a choice, `recv` returns a sum with one variant per label, carrying the payload and the next endpoint, to be matched. `close(ep)` is legal only in the `end` state. Sending a label the current state does not allow is E727, naming the state and the labels it allows, and dropping an endpoint before `end` is E412. A session whose endpoints are all used this way cannot deadlock on itself and never delivers a message its receiver does not expect. When a branch holding an endpoint fails, its session is cancelled and the peers' pending `recv` fails with `SessionClosed`. Session channels are exempt from the sibling-wait rule (E713), because the protocol orders them, and they are deterministic, because each direction has one sender. An implementation MAY let an endpoint send ahead of a receive when asynchronous subtyping allows it (Rumpsteak, PPoPP 2022).

### 9.6 Actors and distribution

Actors, supervision and deadlock detection are std packages in `std.actor`; an actor may keep a session endpoint (R634) in its state, and an endpoint crosses `Remote` when its payloads are Wire; there is no `actor` capability, and sharing a handle needs `nondet` (R442). `Actor[S]` owns a state `S` and processes one message at a time.

- Calling an actor function with an `inout` state parameter sends a message and suspends only the caller. Delivery between a given sender and receiver is FIFO; there is no ordering across senders. An actor handle is like a `Sender` (R391): a second sender exists only through `share` of the handle, which needs `uses nondet` (E709, R442), and a program that shares a handle is in the replay tier of 7.7 (R397). Actors have no capability of their own; they run on the bound `sched`.
- **Non-reentrant by default.** An actor processes one message to completion before taking the next, even across suspensions. A handler marked `@reentrant` may interleave, and is accepted only if it does not mutate actor state across a suspension and no value read from state is live across a suspension (E715, R397).
- **Call deadlines.** Every `call` has a deadline: the enclosing scope's, or 5 seconds by default. The deadline bounds the caller's wait and the message's admission: a message whose deadline passed before dequeue is dropped, and the caller gets Timeout. It is never delivered into a running handler, so a caller's timeout cannot leave state half-updated (R397). Expiry is `fail Timeout`.
- **Bounded mailboxes.** Each actor declares a mailbox capacity (default 1024) and an overflow policy: `block` (the default for `call`), `drop_oldest`, `drop_new` or `fail`.
- **Deadlock detection.** Under the seeded and explore sched handlers, or when an opt-in debug handler is bound, std's actor and channel packages keep a wait-for graph over calls and channel waits. Under pool they keep none, so production pays nothing for it (R349). A cycle produces `fail Deadlock` in the youngest caller and an event in the task viewer. Lint W808 flags call cycles visible statically. Every sched handler, pool included, counts tasks blocked on in-program waits; when every task is blocked and no I/O or timer is pending, the program panics with kind `deadlock` and the wait-for graph or, under pool, the blocked task list. A partial deadlock under pool is not detected and is ended by call and scope deadlines (R396).
- **Supervision.** Each actor has exactly one supervisor. A supervisor spec gives the strategy (`one_for_one`, `one_for_all`, `rest_for_one`), restart type per child (`permanent`, `transient`, `temporary`), restart intensity and period (default 1 restart per 5 seconds), shutdown order and a per-child shutdown timeout. Exceeding the intensity stops the supervisor and escalates. `yong audit` warns when the product of nested intensities exceeds 10. A handle does not keep an actor alive. Actors are children of the scope that binds their supervisor (with supervisor(spec)); cancelling or draining that scope stops them in shutdown order (R397).
- **Distribution.** Placement is chosen by the `sched` handler and the placement policies of 9.6.1. A call that may cross a machine boundary requires `uses cluster` (R400) and adds `RemoteError` to the failure type; `Remote[Actor[S]]` is a different type from `Actor[S]`. Values crossing a machine boundary MUST implement `Wire`, checked when the actor is shared as `Remote` (E720). Distribution is M4; until then the `cluster` capability MAY be bound only to its `sim` handler, but the types MUST exist. The full model is 9.6.1.
- **Moved messages (R264).** Sending moves the message payload into the mailbox. No deep copy is made, and the sender cannot use the payload afterwards.
- **Reproducible actors (R264).** Under `sched = sequential` or `seeded(seed)`, an actor program is deterministic: the same seed gives the same interleaving and the same results, so its tests are cached like other deterministic tests (18.4). This holds only when every shared capability it uses has a deterministic handler, such as virtual time or std.sim (R397).

#### 9.6.1 Distributed compute (R400 to R419)

Distribution is one capability and the std package `std.dist` over it. A program that does not bind `cluster` pays nothing for it. Design: https://claude.ai/artifact/1bHS11teg1PxvwVqXzCfqP.

- **Capability (R400).** `cluster` is a built-in capability. Its handler is built from `net`, `tls` and the node's key; code using `cluster` never holds raw `net`. Every `cluster` operation is a `nondet` point and is logged under R305. Operations: `nodes`, `self_node`, `view`, `spawn(e, placement=)`, `call_remote`, `monitor`, `demonitor`, `entity`, `group`.
- **Addresses (R401).** `Remote[Actor[S]]` is location-transparent: a handle call through it behaves the same for a local or remote actor, apart from `RemoteError`. `share` coerces `Actor[S]` to `Remote[Actor[S]]` only when every handler of `S` has `Wire` parameters, result and failure (E720). A remote message is the identity hash (R348) of the handler's signature (name, parameter types, result, failure; not its body) plus the encoded arguments.
- **Local equivalence (R402).** A local delivery through `Remote` MUST be observably equal to encoding then decoding, including `Wire` limits and NaN canonicalization. Checked mode and `std.sim` always encode; release MAY move the value when the round trip is proven to be the identity.
- **Identity (R403).** A node id is the first 128 bits of BLAKE3 over its TLS certificate's SubjectPublicKeyInfo. A pid is 44 bytes: node id (128 bits), incarnation (32, new on every boot), slot and generation (32 + 32), and a 128-bit unguessable token. A node MUST drop a message whose token does not match; holding a pid is the authority to send to it.
- **Transport (R404).** Peers use QUIC with mutual TLS 1.3: one unidirectional stream per ordered actor pair, opened lazily; one control stream for membership and schema exchange; datagrams for heartbeats. A TLS-over-TCP handler carries the same frames where UDP is blocked.
- **Encoding (R405).** Frames carry the canonical binary `Wire` encoding. A stream's first frame carries the handler table and schema hashes; later frames carry a handler index, a call id, a length and the body.
- **Schema evolution (R406).** A `Wire` type's schema hash is the identity hash of its structure. Equal hashes decode directly. Unequal hashes use a converter generated at stage 0 from a version pinned in `.yong/schemas/` under the rules of section 20; with no converter the call fails `SchemaMismatch` before user code runs. `yong schema pin` records schemas; `yong schema check --against REV` reports breaking changes to pinned schemas (E724).
- **Remote code (R407).** Closures never cross a machine. `call_remote` and off-node spawns name a top-level item marked `@remote` (E721), which is called by its signature hash. Capabilities never travel: a `@remote` item runs with the receiving node's capabilities, within its role's ceiling in the release manifest; a `@remote` item whose `uses` exceeds every exporting role's ceiling is E722 at `yong release`.
- **Delivery (R408).** At most once; FIFO per ordered actor pair; no order across senders. `RemoteError` extends `ActorError` with `Stopped{reason}` (reason `Normal`, `Shutdown`, `NodeDown` or the handler's `Wire` failure), `Unreachable`, `Rejected` (bad token or unknown handler) and `SchemaMismatch`. The call deadline of 9.6 crosses the wire as the remaining budget; cancelling the caller cancels the callee's handler at its next suspension point.
- **Membership (R409).** The cluster moves through numbered views agreed by every member: each node is watched by K observers (default 10) with phi-accrual detectors on heartbeats, a change is proposed when enough observers agree, and one consensus round installs it (Rapid). Above about 200 nodes, messages use a HyParView partial-view overlay; views stay consistent.
- **Partitions (R410).** A new view needs a majority of the previous one. A node that cannot reach a majority for `minority_timeout` (default twice the detection time) stops its actors with `Stopped{NodeDown}` and exits with status 75. A two-node cluster binds a `lease` handler as tiebreaker.
- **Supervision (R411).** `monitor(pid)` delivers one `Down{reason}` when the target stops or its node leaves the view. A supervisor and its children may be on different nodes; a departed node's children exit with `NodeDown`, and a restart re-evaluates placement. A child spec names a top-level function and `Wire` arguments, never a closure; each start receives its capabilities from the scope that binds the supervisor (R397), or, off-node, from the hosting node's ceiling, where the function MUST be `@remote`. W843 flags a `permanent` child placed `on(node)`. A panic aborts its node (R5); peers observe `NodeDown`.
- **Placement (R412).** `placement=` takes `local` (default), `on(node)`, `spread`, `by_key(k)` (rendezvous hashing over the view) or `near(pid)`.
- **Entities (R413).** `Entity[K, S]` is addressed by key; the first message activates it on the key's owner in the current view, it passivates after `idle` (default 10 minutes), and state is loaded and saved through a bound store capability. Each view has exactly one owner per key; on a view change the old owner finishes its current message, saves state and forwards its queue before the new owner activates. `K` MUST be `Wire + Hash` and `S` `Wire` (E726).
- **Groups (R414).** `Group[A]`: `join`, `leave`, `members`, eventually consistent within a view. There is no global lock-based registry; a single named actor is an entity.
- **Upgrades (R415).** A running system is upgraded by image migration: a new image (an exec'd successor receiving the sockets, or another node) joins, each actor is moved at a message boundary with its state and queue, and the old pid forwards for a grace window (default 30 s). A state whose schema changed needs an `@upgrade` function from the pinned version, which MUST be `uses none` (E723). Production builds never swap code inside a process; the debug jump table of 18.4 stays debug-only.
- **Durable functions (R416).** `@durable` lives in the package `@yong/durable`: it journals capability results in the R305 entry format and resumes by replay. It may use only journaling capabilities, no unjournaled nondeterminism and no views across operations (E725).
- **Durable resume and versions (R453).** `durable.resume(store, key)` replays the journal and then continues on live handlers from its end. This replay-then-live mode is the one exception to R305's rule that only output capabilities may be live under replay. Resumed code that diverges fails with `ReplayDiverged`, and the run is parked, never continued. `durable.version(name, max)` records a choice point, so runs started on old code keep their old branch. `yong replay --against REV` over stored journals is the deploy check that every in-flight run survives a change. Each journaled operation carries an idempotency key, the hash of key, task path and op index, which a handler may send to the remote side. W850 flags an operation on a shared capability whose handler declares no idempotency support.
- **Durable timers (R552).** `@yong/durable` provides a journaling `timer` capability with `sleep(d)` and `sleep_until(t)`. The first execution journals the absolute deadline; on resume a passed deadline returns at once and a pending one waits for the remainder. The store persists pending wake-ups and resumes the run when one falls due, so the process may exit while a run sleeps. `timer` is how an `@durable` function waits.
- **Testing (R417).** The `cluster` handler has a `sim` implementation in which every node is a `std.sim` host; seeded runs are deterministic and `explore` covers message orders. the one `check_linearizable` of 18.4 (R304) checks the recorded node histories against the machine's sequential model. A node's trace replays alone; `yong replay --merge` orders node traces by Lamport stamp.
- **Security (R418).** Mutual TLS only; a node joins when its certificate chains to the manifest's cluster CA or its SPKI hash is allowlisted. Only `@remote` items and handlers of held pids can run. Per-peer limits apply before decoding. `yong audit` lists `@remote` items, their `uses` sets and admitting roles. `yong attach` gives introspection through an `introspect` capability and cannot evaluate code; `@admin` items are callable only with operator certificates.
- **Delivery plan (R419).** Frozen at 1.0: `Remote`, `RemoteError`, `Wire` schema hashes, `@remote`, `@upgrade` and the `cluster` interface. M1: the `sim` handler, schema tooling and E720 to E726. M4: QUIC and TCP handlers, views, entities, groups and migration in `std.dist` (preview until stable), and `@yong/durable`. Choreographies are a post-1.0 study (`@yong/choreo`).

### 9.7 I/O operation model

- **Completion-shaped operations.** `net`, `io` and `fs` operations each take their buffer and return their result. Readiness backends emulate this by retrying the non-blocking call after EAGAIN.
- **Borrowed buffers.** I/O operations take `View` or `MutView` buffers. Cancelling an in-flight operation waits, masked, for its final completion; `fail Cancelled` and `fail Timeout` carry `transferred`, the bytes moved before the stop.
- **Buffer pools.** `std.net` provides `BufPool` (registered and provided buffers), owned `Lease` values from `recv_pooled`, and `send_zc`. Every handler implements them; outside io\_uring they are plain memory.
- **Backpressure.** `stream.split()` gives owned `ReadHalf` and `WriteHalf` for `par concurrent`. HTTP/2 and QUIC credit flow-control windows only as the body `Reader` is consumed.
- **Blocking calls.** Every FFI and `py` call is blocking unless declared `nonblocking`; there is no `@blocking` attribute (R447). Under `pool` a blocking call occupies its thread; under `std.evented` it runs on that package's blocking pool, which adds a compensating carrier when one stays blocked longer than 10 ms.
- **Evented backends.** `std.evented` provides io\_uring (kernel 6.1 floor, later features probed at start) with automatic epoll fallback when io\_uring is denied, kqueue on macOS and BSD, and IOCP on Windows. It runs one carrier thread per core, each owning its ring, timer wheel and buffer-pool slice; a started task stays on its carrier, and only unstarted tasks are stolen. A coroutine whose call graph has no recursion, `dyn` call or FFI gets an exact compiler-computed stack; others get 256 KiB reserved, committed on touch, with a guard page.
- **Stability.** The `net`, `io`, `fs` and `BufPool` interfaces and their cancellation rules are stable at 1.0 under every handler; only `std.evented`'s handler implementations are `@preview("evented")` until M4.
