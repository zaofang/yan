# Wen · Jian · Yong — Language Specification v0.3 (draft)

Frozen copy of the "v0.3 archive" tab of the former spec Claude Doc (rev 517). Two diagrams (compiler architecture, milestones) exist only in that doc.

Oct 30, 2026 · @Antonio

This is the implementation specification for one programming system with two surface languages: **Wen** (文, for humans), **Jian** (简, for language models), and the shared core **Yong** (永), which is also the name of the toolchain. It is written for an engineering agent that will build the compiler, runtime, standard library and tools from this document alone.

It consolidates and supersedes the earlier Fathom, Tern, Unified Core and Moonshot documents. Fathom is now Wen, Tern is now Jian, and Keel is now Yong. On 2026-10-31 the core was renamed from Ben (本) to Yong (永) and the model surface from Fan (范) to Jian (简), because Fantom already uses the fan command and the .fan extension.

**How to read it.**

- Sections 3–10 define Yong, the semantics. Both surfaces are only syntax for Yong, so Yong is implemented first.
- Sections 11–14 define the two surfaces and how they map to Yong and to each other.
- Sections 15–20 define the standard library, the toolchain, the agent features, the implementation plan, the milestones and the conformance suite.
- Build in milestone order (section 19). Each milestone has acceptance criteria; do not start the next one until they pass.

**Normative terms.** MUST, MUST NOT, SHOULD and MAY have their RFC 2119 meanings. Anything not marked normative is rationale or example. Where an example and a normative rule disagree, the rule wins; report the conflict as a spec bug.

**Spec bugs.** When something is ambiguous or contradictory, the implementer MUST NOT guess silently. Record the question in `SPEC_QUESTIONS.md` at the repository root, choose the option that best satisfies the design laws (section 2), and mark the code with a `SPEC-Q` comment naming the entry.

## What changed in v0.2

v0.2 folds in lessons from other languages' failures and fills gaps v0.1 left open. Most changes tighten semantics that are expensive to change once user code exists, so they land in M0 and M1. Where v0.1 text conflicts with a v0.2 paragraph, v0.2 wins and the conflict is a spec bug.

## What changes in v0.3 (draft): no language runtime

v0.3 removes the language runtime so Yong is fast and usable for systems programming. No scheduler, collector or implicit reference counting runs unless the program binds a library that provides it. Where v0.2 text conflicts with this section, this section wins and the conflict is a spec bug. Every row is decided: the owner chose R1 to R3 and delegated the rest to a research pick on 2026-10-30 (fastest, most correct, simplest), and each stays overridable.

## 1. System overview

&#91;embedded content: compiler architecture · two surfaces, one core, three executors\]

Each surface has its own reader; everything from the elaborator down is shared. The dashed arrows are projections: any Yong item prints as Wen, and any Yong item inside the Jian subset prints as Jian.

| Wen (文, "text, writing") | surface written and read by people; inferred, expressive | `.wen` |

## 2. Design laws

These are normative. Every implementation decision not settled elsewhere in this spec MUST be resolved by them, in this order of priority.

1. **One semantics.** Yong defines all behavior. A surface MUST NOT add behavior that cannot be expressed in Yong; it may only add syntax.
2. **Safe by default.** Outside `unsafe` blocks, a well-typed program MUST NOT exhibit undefined behavior, data races, use-after-free, null dereference, or an unhandled error or capability. `unsafe` is permitted only in the standard library and in modules marked `ffi`.
3. **Unambiguous text.** Every source text has exactly one parse and one meaning. The grammar is deterministic with one token of lookahead after the factorings given in sections 11 and 13. Operator mixes that people commonly misread require parentheses.
4. **Five facts at the use site.** Mutation of a passed-in variable, possible failure, compile-time evaluation, concurrency, and capability use MUST be visible where they happen, by the marks defined in each surface. Everything else may be inferred.
5. **Nothing implicit at run time.** No implicit numeric conversion, no null, no exceptions, no hidden I/O. Copies, moves and capability passing are made explicit in Yong, even when the surfaces leave them implicit. There is no language runtime (v0.3): no scheduler, collector or implicit reference counting runs unless the program binds a library that provides it.
6. **Local reasoning.** Every item MUST be checkable from its own body plus the signatures and contracts of the items it references. No global inference across modules.
7. **Deterministic by default.** Code that uses none of the `time`, `rand`, `net` or actor-messaging capabilities MUST produce bit-identical results on every run, scheduler and supported target.
8. **Canonical text.** Each surface has exactly one canonical printing of any program. The toolchain stores canonical text, and the formatter produces it. A lenient reader MAY accept the deviations listed in section 12 and MUST normalize them.
9. **Depth is additive.** Annotations deeper in the layer stack (L1–L6) are checked assertions. Adding one MUST never require rewriting code that does not use it.
10. **Familiar beats novel (Jian only).** With types, contracts and the constructs listed in section 12 removed, a Jian program SHOULD be valid Python 3.12. A deviation from Python needs evidence of benefit (law 11).
11. **Evidence-gated change.** After v1.0, a change to either surface MUST be justified by the measurements in section 19: model pass@1 and total tokens per solved task for Jian, and a randomized comparison for contested Wen syntax.

## 3. Yong: kinds, types and terms

Yong is a typed intermediate language in administrative normal form. Every intermediate value is named, every parameter and argument states its convention, every capability is an explicit parameter, and every operator is a named function. Yong has a text format (`.yong`) used for golden tests and debugging; the grammar below is that format, and it MUST round-trip through the Yong parser and printer.

**Kinds.** Kinds other than `Type` exist only at compile time and MUST be erased before code generation.

| Kind | Inhabitants |
| --- | --- |
| `Type` | value types |
| `Size` | natural literals and size variables (positional array axes, fixed arrays) |
| `Axis` | any type used as an array-axis label |
| `Dim` | integer exponent vectors over base dimensions (units) |
| `Cap` | capability interfaces |
| `Region` | lexical region names (L4) |

**Types.**

```

         | "Tuple(" Type {"," Type} ")"
         | "Option[" Type "]" | "Result[" Type "," Type "]"

         | "Fn(" [Conv Type {"," Conv Type}] ")" "->" Type ["uses" CapSet] ["fail" Type]

         | "Ref[" Region "," Type "]" | "Ptr[" Type "]" | "Vec[" Nat "," Scalar "]"
```

- Records, sums and newtypes are nominal. Tuples are structural.
- `Ptr` is legal only inside `unsafe`. `Ref`, `Ptr` and `Vec` are Wen-only (L4–L6) and MUST NOT appear in Jian-elaborated code.
- (v0.3 R117, R118) Ptr\[T\] is never null; a nullable pointer is Option\[Ptr\[T\]\]. Addr is an unsigned scalar of the target's address width, distinct from pointer size.
- Refinement predicates (`Pred`) are restricted to the decidable fragment in section 7.

**Strings and characters (v0.2).** Normative:

- `Str` is immutable UTF-8 with a small-string optimization. It has no O(1) integer indexing and no single "length". Views are explicit: `bytes()`, `chars()` (Unicode scalars) and `graphemes()` (UAX #29). Counts are `byte_len()`, `char_count()` and `grapheme_count()`.
- Slicing takes `StrIndex` values returned by searches. Slicing by byte offset checks that both ends fall on char boundaries and panics with kind `bounds` otherwise.
- `char` is a Unicode scalar value (4 bytes), never a grapheme.
- Normalization (NFC, NFD) is explicit. Case mapping is locale-independent; locale-aware operations live in `@yong/i18n (v0.3 R24)`.
- The Unicode version is pinned per edition, so grapheme and case results never change under a fixed edition.
- `Bytes` is arbitrary octets. `OsStr` holds platform strings: bytes on Unix, WTF-8 on Windows. Paths are `OsStr`.

**Integers (v0.2).** There is no implicit widening or narrowing. Integer literals take any integer type whose range contains them. `x as T` is checked and panics with kind `overflow` when the value does not fit; `wrap_as`, `sat_as` and `trunc_as` convert explicitly. Arithmetic families are `wrapping_*`, `checked_*` (returning `Option`), `saturating_*` and `overflowing_*`. A shift by at least the bit width panics.

## 4. Yong: ownership and exclusivity

Yong has mutable value semantics: assignment and argument passing behave as if values were copied, two names never share mutable state, and references are second-class. There are no lifetime annotations anywhere except the from clause on functions that return a view (v0.3, below) and `Ref` at L4.

**Parameter conventions.** Normative semantics:

| Convention | Callee may | Caller's variable after the call | Typical lowering |
| --- | --- | --- | --- |
| `let` | read only | unchanged and usable | by value if trivially copyable and at most 2 words, else by pointer |
| `inout` | read and write | holds the callee's final value | pointer, marked `noalias` |
| `sink` | own and consume | dead: any later use is error E401 | by value (move) |
| `set` | write once, must initialize | initialized | pointer to uninitialized storage |

**Bindings.** `let` bindings are immutable. Only `var` bindings and `inout` parameters may be targets of `Place = Rhs` (otherwise E403). A field or element of a mutable place is itself mutable.

**Copy and move insertion.** Surfaces never write `copy` or `move`; the elaborator MUST insert them by last-use analysis:

1. A use of a variable that is its last use on every path becomes `move`.
2. Any other use passed to `sink`, stored into a container or record, or bound to a new name becomes `copy` if the type is trivially copyable (a bitwise copy).
3. (v0.3) For a heap-backed type, such a use is error E413 unless the source writes `copy x` (Jian: `x.copy()`), which is a deep copy costing O(size). E413's fix inserts the copy, so `autofix` resolves it without a model generation. Cheap sharing is `Rc[T]` or `Arc[T]`, whose `copy` increments a count; this is the only reference counting in Yong.

**The law of exclusivity.** For each statement, consider every place accessed through `inout`, every place read, and every place passed `sink`. Then:

- No place accessed through `inout` may overlap any other place accessed in the same statement (E402).
- Two places overlap if one is a prefix of the other, or if they share a root and their paths differ only in index positions that are not provably distinct.
- Index distinctness is decided by the linear-arithmetic solver (section 7). If it cannot decide, the compiler MUST insert one runtime check that the indices differ; a failed check panics with `exclusivity`.
- The same rule applies across the branches of a `par` block, treating the whole block as one statement.

**Projections.** `a[i]`, `r.f` and accessor functions yield a borrowed place, valid only within the statement that produces it. A projection MUST NOT be stored, returned or captured.

**Views (v0.3).** `View[T]` (read) and `Span[T]` (read and write) borrow a contiguous part of a value: a slice of a `List`, `Bytes`, `Str` or array buffer. Views are second-class, by the same rule as capabilities (section 6): a view MUST NOT be stored in a record, container or closure that escapes, and MUST NOT outlive the value it borrows (E414). A function returns a view only with a `from` clause naming the parameter it borrows, `def head(xs: View[u8]) -> View[u8] from xs`; the caller treats that parameter as borrowed (`let` for `View`, `inout` for `Span`) until the view's last use. Records with view fields are themselves second-class and inherit the rule. The law of exclusivity applies to views as to `inout` places, so two `Span`s over overlapping ranges in one statement are E402. Views are in Jian and Wen; they cover zero-copy parsing, borrowing iterators and in-place algorithms without lifetime parameters.

(v0.3 R63, R69, R70) A non-escaping closure may also use `?` and `fail`; the failure leaves the higher-order call as the caller's failure, and iterator adapters are second-class like views, so lazy chains are not escapes. Duplicating an Rc, Arc, Sender or actor handle is `share x`, never `copy x` (E416); `copy` is always a deep copy, and `copy v` on a view yields the owned value. `from a, b` names several sources, any type that contains a view is second-class, the view of a Str is `StrView`, and Span is renamed `MutView`.

**Closures.** A closure captures by `copy` at creation. A closure that escapes (is stored, returned, or passed to a `sink` parameter) MUST NOT capture an `inout` parameter, a `var` binding by reference, or a capability (E406). A non-escaping closure argument may use any capability and any `var` of the enclosing scope; this is how higher-order functions stay effect-polymorphic without effect variables (section 6).

**Explicit references (Wen L4 only).** `Ref[r, T]` is a reference into region `r` (section 5). It may be stored only in data allocated in the same region and MUST NOT outlive the region's block. The check is lexical: a `Ref[r, …]` value may not flow outside the syntactic extent of `region r { … }` (E407).

## 5. Yong: memory model

There is no tracing garbage collector and no implicit reference counting (v0.3). Every value has exactly one owner and is destroyed at a statically known point. Reference counting exists only inside the library types `Rc[T]` and `Arc[T]`, which a program uses explicitly. Under mutable value semantics no reference cycle can be built without `Rc`; `Weak[T]` breaks cycles where a program builds them.

**Representation.**

- A type is *trivially copyable* if it contains no heap-backed component. Such values live inline and are copied bitwise.
- Heap-backed values (`Str` above the small-string limit, `Bytes`, `List`, `Map`, `Set`, array buffers, boxed recursive variants, closures with captures) are a pointer to a block whose first word is the reference count.
- `Str` stores up to 23 bytes inline (small-string optimization).
- Sums use niche optimization: `Option[T]` costs no extra space when `T` has an invalid bit pattern (pointers, `bool`, `char`, refined integers).
- Record fields are reordered to minimize padding unless the type carries `@layout(c)`.

**Copies (v0.3).** A heap-backed value is a pointer to a block with no count header. `copy x` allocates and deep-copies; nothing else copies a heap block. Mutation is always in place. `Rc[T]` and `Arc[T]` hold an immutable `T` behind a count; `make_mut(&r)` copies the block if the count is above 1, which is the only copy-on-write in Yong and is visible at the call.

**Ownership passes (v0.3).** The optimizer MUST run these on checked Yong, in order:

1. Borrow lowering: `let` parameters and views pass by pointer or by value as section 4's lowering column says, with no ownership operations.
2. Drop elaboration: drops are placed in reverse declaration order at scope exit, and moved-from values are not dropped (drop flags only where a move is conditional).
3. Drop specialization: inline the drop of a statically known variant.
4. Reuse analysis: when a uniquely owned block of size n is dropped and a block of size n is then allocated in the same function, reuse it in place (`reuse x as Ctor`). Unique ownership makes this check static.

**Sharing across tasks (v0.3).** A `par` block is scoped, so its branches may borrow (`let`) values of the enclosing scope with no counting or marking. A value sent to another task through a channel or an actor is moved (`sink`). Long-lived shared data is `Arc[T]`, whose count is atomic; `Rc[T]` is not `Send` and cannot cross a task boundary (E415).

**Regions.** `region r { … }` allocates every heap value created in its block from a bump allocator and frees all of it in one step when the block exits. Region-allocated blocks carry no count. A value that would outlive its region is error E408; the fix is an explicit `copy_out(x)`, which deep-copies into the enclosing allocator.

**Allocators.** All allocation goes through the `alloc` capability (section 6). The default handler is the system heap. `region` is sugar for binding a region handler to `alloc` for the block.

**Drop order (v0.2).** Locals drop in reverse declaration order, record fields in declaration order, and collection elements front to back. The children of a `par` block drop before the block exits. A panic inside a drop that runs during unwinding aborts the process. Cleanup that can fail is an explicit `close() -> () fail E`; the `@must_close` attribute makes dropping an unclosed value a lint error.

**Memory model (v0.3 R110 to R124).** The abstract machine is R110, and its checked interpreter is the executable definition. Atomics follow the C++20 model, 1:1 with C11 (R111). Interior mutability is RawCell and the std types built on it (R112). Thread safety is the auto traits Send, Sync and Freeze (R113). Safe code is data-race free and DRF-SC, and shared mutable state across tasks needs nondet (R114). Happens-before edges are R115. Aliasing is Tree Borrows (R116), provenance is strict (R117, R118), undefined behavior is the closed list R119, and what unsafe code may assume is R120. Volatile and fences are R121. Atomics are usable from Jian through std.

**FFI (v0.3).** Extern declarations live in `unsafe extern "C" lib` blocks in `ffi` modules, and each foreign library is a capability (R89, R90). Types that cross use `@layout(c)` (R91 to R94). Ownership is expressed with `View`, `MutView`, `Owned`, `extern type` and `Ptr` (R95), callbacks are `scoped` or `escaping` (R96), and no unwinding crosses the boundary: a foreign unwind aborts (R97). FFI calls are `@blocking` by default (section 8). Import, exports, the C profile and bindings are R98 to R103.

**Proof attributes (Wen L4).**

| Attribute | The compiler MUST prove, or report each violating line |
| --- | --- |
| `@no_rc` | no `dup`, `drop` or `reuse` remains after optimization |
| `@no_alloc` | no use of the `alloc` capability |
| `@no_copy` | no `copy` of a heap-backed value remains |
| `@no_panic` | no reachable panic (bounds, overflow, contracts, exclusivity) |

## 6. Yong: capabilities, handlers and determinism

Effects are capabilities: second-class values passed as explicit parameters in Yong and implicitly by the surfaces. There are no effect variables anywhere, effects are statically safe, and common handlers compile to direct calls.

**Built-in capabilities.**

| Name | Interface | Operations (minimum) |
| --- | --- | --- |
| `io` | `Io` | `print`, `eprint`, `read_line` |
| `fs` | `Fs` | `read`, `write`, `append`, `list_dir`, `exists`, `remove` |
| `net` | `Net` | `http_get`, `http_post`, `tcp_connect`, `tcp_listen`, `udp_bind`, `resolve`, all with deadlines |
| `time` | `Time` | clock reads only: `now`, `monotonic`, `sleep`, sleep\_until (R53); time-zone arithmetic against the pinned tzdb is pure and needs no capability (R55) |
| `rand` | `Rand` | `next_u64`, `next_f64`; handlers `Seeded(algorithm, seed)` (default in tests) and `Os` |
| `crypto_rand` | `CryptoRand` | `fill_bytes`; a CSPRNG that tests may replace but release builds may not |
| `log` | `Log` | structured key-value events at `debug`, `info`, `warn`, `error`, plus spans |
| toolchain | Toolchain | read-only queries over the query database (v0.3 R16); bound only for MCP query scripts and tools, never in release builds |
| `metrics` | `Metrics` | counters, gauges, histograms |
| `env` | `Env` | `args`, `var`, `secret` (returns `Secret[str]`), `local_zone` |
| `proc` | `Proc` | `spawn(Command)` taking argv, never a shell string; `shell` is separate and linted |
| `signals` | `Signals` | a stream of OS signals; SIGINT and SIGTERM also cancel `main`'s root scope |
| `actor` | `ActorSys` | `spawn_actor`, `send`, `call` |
| `py` | `Py` | `call`, `import_module` (Python bridge, section 15) |
| `nondet` | none | marks scheduler-visible nondeterminism (`@unordered`, `@fast_math`) and observing hash values |
| `alloc` | `Alloc` | `alloc`, `realloc`, `free` (ambient; see below) |
| `sched` | `Sched` | task placement for `par`, `par for` and actors |

User-defined capabilities are traits marked `@capability`; any trait so marked may appear in `uses`.

**Elaboration.** `uses a, b` on a function becomes parameters `cap a: A, cap b: B` in Yong. Each call passes the capabilities its callee needs from the caller's scope. A capability MUST NOT be stored in data, returned, or captured by an escaping closure (E306). Calling a function whose capabilities are not in scope is E301, and its fix inserts the missing `uses` entry.

**Signatures.** In Jian every function lists its capabilities. In Wen only `pub` functions must; others are inferred. `alloc` is ambient: it is passed like any capability but never written in `uses`. `uses none` on a function forbids every capability, including `alloc`.

**Handlers.** `with name = expr { … }` binds a handler value for the block. A handler is any value implementing the capability's trait. All built-in capability operations are tail-resumptive: they return to their caller.

- The handler for `alloc`, `rand`, `time` and `sched` MUST be resolvable at compile time to a concrete type, so calls monomorphize to direct calls (E307 otherwise). Writing `with name = dyn expr` opts into one indirect call per operation.
- Other capabilities MAY be dynamic; the compiler SHOULD monomorphize when the handler type is known.
- On hosted platforms, std binds a default handler for every built-in capability before `main` runs: system heap, OS clock, OS-seeded generator, the `pool` scheduler, blocking I/O, standard streams. On platform `freestanding` nothing is bound: the program binds every capability it uses (v0.3).
- Generators are Wen L5 only and compile to state machines; a generator yields only from its own body. There are no general one-shot continuations and no fiber stacks (v0.3). Jian MUST NOT declare them.

**Determinism.** Normative guarantee: the result of any computation is a deterministic function of its arguments and of the values returned by its capability operations. Scheduling MUST NOT be observable. Concretely:

- `par` branches share no mutable state (section 4), and their results are joined in source order.
- `par for` returns results in input order. `par fold` reduces in a fixed balanced-tree order determined only by the input length.
- Floating point is IEEE-754 strict: no fused multiply-add contraction, no reassociation, no flush-to-zero, unless the function uses `nondet` via `@fast_math` or `@unordered`.
- Iteration order of `Map` and `Set` is insertion order, never hash order.
- (v0.3 R114) Shared mutable state needs nondet: sharing a non-Freeze value between tasks that may run at once, share of a Sender, try\_send, try\_recv and select (E709). Channels with one Sender and blocking send and recv stay deterministic.

**Determinism inputs (v0.2).** The guarantee above covers these too:

- **Hashing.** The default `Hasher` is SipHash-1-3 keyed with a secret per-process key, which defeats hash flooding. Maps and sets iterate in insertion order, so the key never affects output. Observing a hash value requires `nondet`. `std.hash.stable` gives fixed-key, versioned hashes for content addressing.
- **Math library.** `sin`, `exp`, `pow` and the rest come from a bundled correctly rounded libm, never the platform's. NaN payloads are canonicalized at `Wire` and hash boundaries. `-0.0 == 0.0` under `Eq`; `Ord` on floats is IEEE totalOrder. `f16` and `bf16` compute in `f32` and round after each operation. SIMD reductions follow the fixed `par fold` tree.
- **Pinned data.** The Unicode version is pinned per edition. The tzdb and ISO 4217 versions are pinned in `yong.lock`.
- **Solver.** Proof results depend only on deterministic resource limits (section 7).

**Record and replay.** The standard library MUST provide a recording handler and a replay handler for every built-in capability; a program opts in by binding them. `yong run --record f.trace` logs each operation and its result, per task, in task-tree order. `yong replay f.trace` re-executes, feeding recorded results, and MUST reproduce the run exactly, by the determinism guarantee. A production mode keeps a ring buffer of the most recent trace window and writes it on panic. Each capability exposes a redaction hook applied before recording.

## 7. Yong: failure, panics, contracts and verification

Recoverable failure is a typed value. Bugs are panics confined to their task. Contracts are one mechanism with three enforcement levels.

**Typed failure.** A function declared `-> T fail E` returns either a `T` or an `E`.

- The calling convention returns the error in a dedicated register with a flag (as in Swift's typed throws), so the success path costs one predictable branch.
- `Call?` propagates. If the callee's error type differs from the caller's, a `From` implementation MUST exist and is named with `via`. A missing conversion is E310.
- `E` may be an anonymous union of nominal types, written `A | B`. The elaborator MAY infer the union in Wen; Jian MUST spell it out.
- Errors are never silently discarded: a `try` result that is never inspected is E311.

**Error injection and context (v0.2).**

- When the caller's error type is a union that contains the callee's error type exactly (or a union of its members), `?` injects the value with no `From` impl. If both injection and a `From` impl apply, that is an ambiguity error.
- `x.context(msg)` wraps a failure with a message, building a context chain that `Show` prints outermost first.
- Debug builds capture a backtrace where a failure value is created. Release builds do not.
- A lint suggests a named sum type when an error union has more than 8 members.
- `Timeout` and `Deadlock` are standard failure types (section 8).

**Unused results (v0.2).** Discarding a non-unit result is an error (E312); write `_ = f()` to discard on purpose. This generalizes E311.

**Panics.** The causes are: integer overflow, division by zero, failed `requires`/`ensures`/`assert`/`invariant`, failed runtime exclusivity check, `unreachable`, and unproven indexing in `check` mode. (v0.3) A panic aborts the process. It prints the message and the panicking task's stack trace, writes the record-and-replay ring buffer if one is bound, and exits with status 101. Drops do not run, and nothing can catch a panic. Recoverable failure is typed failure; isolation from bugs is a process boundary, which std's process supervisor uses, and `yong test` runs each test file in its own process.

**Contract language.** Contracts are expressions in Yong's pure fragment: calls only to functions with no capabilities other than `alloc`, plus:

- `out`, the result, in `ensures`;
- `old(p)`, the entry value of an `inout` parameter, in `ensures`;
- bounded quantifiers `all i in a..b: P` and `any i in a..b: P`.

| Form | Where | Meaning |
| --- | --- | --- |
| `requires P` | function header | caller must establish `P` |
| `ensures P` | function header | callee guarantees `P` on normal return |
| `example E` | function header | `E` must evaluate to true; compiled as a test |
| `invariant P` | loop header | holds on entry to every iteration |
| `decreases M` | recursive function or loop | a natural-number or lexicographic measure that strictly decreases |

**Enforcement levels.** Selected per build, and overridable per module.

| Level | `requires` | `ensures`, `invariant`, `decreases` | Default for |
| --- | --- | --- | --- |
| `check` | runtime | runtime | debug builds and tests |
| `release` | runtime at `pub` entry only | not checked | release builds |
| `prove` | static, falling back to runtime with warning W420 | static, falling back to runtime with W420 | modules marked `@prove` (fallback is an error there) |

Anything proven is erased in every level.

**Contract semantics (v0.2, normative).** These five rules close the ambiguities that sank C++26 contracts:

1. **Pure predicates.** A contract predicate uses no capabilities and has no observable allocation effects. A predicate that panics counts as a violation.
2. **Named build modes only.** The build mode changes whether a check runs, never typing or reachability. The modes are `unchecked-proven` (release default: statically proven checks are erased, the rest run) and `checked-all` (debug default: every check runs, including proven bounds and exclusivity checks, guarding against prover bugs).
3. **No silent ignore.** An unproven `requires` on a `pub` function is never skipped in release builds. A log-and-continue "observe" mode exists only under `yong test`.
4. **One violation path.** A violation always panics with kind `contract` and a payload naming the clause. There is no user-replaceable global handler.
5. **Substitution.** Contracts on trait methods, including through `dyn Trait`, belong to the trait. An implementation may weaken a precondition and strengthen a postcondition, and nothing else.

**The decidable fragment.** Refinement predicates, index bounds and exclusivity disjointness use only: integer variables and constants, `+`, `-`, multiplication by a constant, `len(x)`, comparisons, `and`, `or`, `not`, and `in a..b`. The compiler MUST include a solver for this fragment (simplex with bound propagation), always on, with no external dependency.

(v0.3 R88) The fragment also contains `x & m` and `x % c` for a constant `c > 0`. The solver introduces a fresh variable for each, bounded by `0 <= x & m <= m` when `m >= 0` and by `0 <= x % c < c`.

**Proving.** In `prove` mode the compiler generates verification conditions by weakest precondition over Yong, using callees' contracts as their specifications. Mutable value semantics means there is no heap model and no frame conditions. The conditions are sent to an external SMT solver (Z3 or cvc5) as SMT-LIB2 over a subprocess, with a per-item deterministic resource limit (the solver's rlimit, never wall-clock time) so that a proof succeeds or fails identically on every machine. Results are cached by item hash plus the hashes of the contracts relied on. A failed proof reports the solver's counterexample as concrete values (V401).

## 8. Yong: concurrency

All concurrency is structured: every task has a parent scope that outlives it. Races are impossible by construction, and remote execution is visible in types.

**Execution model (v0.3).** There is no language runtime. `par`, `par for` and `par fold` lower to calls on the bound `sched` handler. std provides `sequential`, `seeded(seed)` (deterministic interleavings for tests) and `pool` (fork-join over OS threads, one per core). Plain `par` may run its branches in any order or in sequence. Branches that must make progress at the same time, such as the two ends of a channel, use `par concurrent { … }`, which requires a handler that guarantees concurrency (E708 otherwise), following Zig's async/concurrent split. Blocking capability operations block their thread under std's hosted handlers; the opt-in `std.evented` package supplies io\_uring and kqueue handlers on stackful coroutines. Code is the same under every handler, and there is no async/await.

**`par` blocks.** `par { { b1 } { b2 } … }` runs each branch as a child task and completes when all have completed. Rules:

- Exclusivity (section 4) is checked across all branches together.
- Values a branch reads from the enclosing scope are borrowed for the block, with no counting (section 5).
- If a branch fails, the others are cancelled at their next suspension point, their drops run, and the first failure in source order propagates. A panic in a branch aborts the process (section 7).
- Bindings made in a branch are visible after the block. Their values do not depend on scheduling (section 6).

**`par for` and `par fold`.** `par for x in xs { body }` evaluates the body for each element, possibly concurrently, and returns a `List` in input order. The body may read the enclosing scope but MUST NOT take `inout` access to anything outside its own iteration. `par fold(xs, init, op)` requires `op` to come from a `Monoid` instance and reduces in a fixed balanced tree. Chunk size is chosen by the `sched` handler and MUST NOT affect results.

**Cancellation.** Cooperative. Every capability operation is a cancellation point, and so is every loop back-edge in a task that has been cancelled. Cancellation runs drops and MUST NOT run user code other than drops.

**Deadlines (v0.2).** `with deadline(t):` and `with timeout(d):` open cancel scopes that nest; the earliest deadline wins. A deadline propagates to child tasks, actor calls and `Remote` calls. Expiry is `fail Timeout`, not a panic. In-flight io\_uring operations are cancelled with `IORING_OP_ASYNC_CANCEL`, and their buffers stay owned by the runtime until completion. Partial I/O reports the bytes transferred. Cancellation is masked while cleanup runs.

**Channels (v0.2).** `Channel[T](capacity)` is bounded only; there are no unbounded channels. It is multi-producer, multi-consumer, with separate `Sender` and `Receiver` handles. `send` suspends when full and `try_send` returns `Full`. Closing the last sender ends receivers' iteration. `select` waits on several channel operations, deadlines and cancellation at once.

**Blocking calls (v0.3).** Every FFI and `py` call is `@blocking` unless proven non-blocking. Under `pool`, a blocking call occupies its thread; under `std.evented`, it runs on that package's blocking pool, which adds a compensating carrier when one stays blocked longer than 10 ms. Mutex, RwLock, Once and Atomic are std types (v0.3 R112), and sharing them between tasks needs nondet (R114). Happens-before edges are R115, and progress guarantees for par and par concurrent are R122.

**Signals (v0.2).** On hosted platforms, std owns signal handling. SIGINT and SIGTERM cancel `main`'s root scope, and a second signal exits immediately. SIGPIPE is ignored, so writes fail with EPIPE.

**Actors.** `Actor[S]` (standard library, using the `actor` capability) owns a state `S` and processes one message at a time.

- Calling an actor function with an `inout` state parameter sends a message and suspends only the caller. Message delivery order between a given sender and receiver is FIFO. There is no ordering across senders, and interleaving across senders is nondeterministic, which is why `actor` is a nondeterministic capability.
- **Non-reentrant by default (v0.2).** An actor processes one message to completion before taking the next, even across suspensions. A handler marked `@reentrant` may interleave, and the compiler accepts it only if the handler does not mutate actor state across a suspension.
- **Call deadlines (v0.2).** Every `call` has a deadline: the enclosing scope's, or 5 seconds by default. Expiry is `fail Timeout`.
- **Bounded mailboxes (v0.2).** Each actor declares a mailbox capacity (default 1024) and an overflow policy: `block` (the default for `call`), `drop_oldest`, `drop_new` or `fail`.
- **Deadlock detection (v0.2).** std's actor and channel packages keep a wait-for graph over calls and channel waits. A cycle produces `fail Deadlock` in the youngest caller and an event in the task viewer. A lint flags call cycles visible statically.
- Actors live in supervision trees, and each actor has exactly one supervisor. A supervisor spec gives the strategy (`one_for_one`, `one_for_all`, `rest_for_one`), restart type per child (`permanent`, `transient`, `temporary`), restart intensity and period (defaults 1 restart per 5 seconds, as in OTP), shutdown order and a per-child shutdown timeout. Exceeding the intensity stops the supervisor and escalates. `yong audit` warns when the product of nested intensities exceeds 10. A handle does not keep an actor alive, so actors referring to each other cannot leak.

**Distribution.** Placement is transparent; failure is not.

- Where tasks and actors run (core, process, node) is chosen by the `sched` handler.
- A call that may cross a machine boundary requires `uses net` and adds `Remote` to the failure type. `Remote[Actor[S]]` is a different type from `Actor[S]`.
- Values crossing a machine boundary MUST implement `Wire` (derivable). This is checked when a remote handler is bound.
- Distribution is milestone M4; until then `Remote` handles MAY be unimplemented, but the types MUST exist.

## 9. Yong: generics, traits and compile time

**Generics.** Functions and types take type, size, axis and dimension parameters. Bounds are traits. Generic code is monomorphized per instantiation by default. `dyn Trait` is the only form of runtime polymorphism: a value plus a vtable, opted into explicitly.

**Traits.**

- A trait declares functions whose first parameter has type `Self`. Default bodies are allowed.
- **Associated types (v0.2).** A trait may declare type members, `type Item`, which each impl fixes once. There are no generic associated types and no associated constants. The iteration protocol is `trait Iterator { type Item; fn next(inout self) -> Option[Item] }`, and `for` desugars through `IntoIter`. Adapters are lazy with guaranteed fusion, and an exhausted iterator keeps returning `None`.
- Coherence: an `impl Trait for Type` is legal only in the module that declares `Trait` or the one that declares `Type`. Overlapping impls are E220. There is no specialization.
- Trait resolution happens entirely at compile time.
- **Inference budget (v0.2).** Inference is local and bidirectional. There is no overloading on return type, and literal typing is bounded. A case that would need exponential search is reported as a diagnostic asking for an annotation, never a slow compile.

**Operators.** Surface operators resolve to trait functions: arithmetic to `Num` (and `Field` for `/`), comparison to `Eq` and `Ord`, `@` to `MatMul`, and `+` on strings and lists to `Concat`. User types may implement these traits, and only these. No other operator overloading exists.

**Derivable traits.** `Eq`, `Ord`, `Hash`, `Show`, `Default`, `Wire`, and `Num` for newtypes over numeric types. `@derive(...)` generates the implementation at compile time. (v0.3 R137) Each is a std trait whose `derived` body is instantiated through reflection; any trait may define one.

**Stage 0.** Compile-time evaluation runs checked Yong in the compiler's interpreter. (v0.3 R130 to R143) Code generation is specialization on stage-0 values through `comptime` parameters, `comptime for` and `comptime if`; there are no macros (R139). Stage 0 uses target semantics, rejects `unsafe`, `Ptr`, `extern`, `asm` and atomics (R131), and runs within deterministic budgets (R132).

- Stage-0 code receives no capabilities except `alloc`, `embed(path)`, which reads a file inside the package root and records it as a build input, and `diag` for compile errors and warnings (v0.3 R133). Stage 0 is therefore hermetic and deterministic.
- Results are memoized in the query database by content hash.
- Types, sizes, axes and dimensions are values at stage 0. A function returning `Type` can be used in type position.
- Wen writes stage-0 expressions as `#expr` (L5). Jian has no stage-0 syntax beyond compile-time parameters and applying derives, annotations and attribute functions (v0.3 R144).

**Attributes** (v0.3 R138) are typed annotations, which are inert values read through reflection, or `@attribute` functions that receive a typed view of the declaration and may only add declarations (impls, reified types, const items), which are then type-checked like any others. They never rewrite the declaration or emit extern items or exports. Defining them is Wen L5 or Yong; Jian may apply them. Built-in attributes:

| Attribute | Effect |
| --- | --- |
| `@derive(T, …)` | generate trait implementations |
| `@layout(c)`, `@layout(packed)` | fix field order and alignment |
| `@abi(c)`, `@extern(c)` | export or import with the C ABI (`extern` only in `ffi` modules) |
| `@capability` | the trait may appear in `uses` |
| `@linear` | values of the type must be consumed exactly once by a `sink` function (E412 otherwise) |
| `@prove` | module or function uses the `prove` level |
| `@no_rc`, `@no_alloc`, `@no_copy`, `@no_panic` | proof obligations (section 5) |
| `@inline`, `@cold` | optimization hints |
| `@unordered`, `@fast_math` | relax determinism; require `uses nondet` |
| `@limit(statements: n, …)` | raise a hard limit for one item |
| `@deprecated("msg")` | warn at use sites |

## 10. Yong: arrays, axes, units and tables

Shape and unit errors are type errors. All shape-label and unit information MUST be erased before code generation.

**Array types.** `Array[a1, …, an, T]` lists axes, then a numeric element type. Each axis is positional (a `Size`: literal or size variable) or labelled (an `Axis`: any type whose values are coordinates, such as `PlainDate` or `Sym`).

**Shape checking.**

- Labelled axes match as a set keyed by label; their written order is irrelevant to checking but fixes the memory order.
- Positional axes match as an ordered list and must agree exactly.
- Size variables are solved by unification. Any not solved statically are checked once, at entry to the function that introduces them (panic `shape`).

**Broadcasting by name.** For elementwise operations, the result's labelled axes are the union of the operands' labelled axes, and each operand is broadcast along axes it lacks. Positional axes broadcast only against scalars (E520 otherwise). `positional(x)` drops labels in memory order; `label(x, A, B, …)` attaches them.

**Indexing.** `x[A: i]` selects along labelled axis `A` by position (integer) or by coordinate (a value of type `A`). Positional axes index by integer. Ranges `a..b` slice. Slices, transposes and broadcasts are strided views, which are projections (section 4) and never alias mutable data.

**Representation.** Buffer pointer, shape and strides, row-major by default. Coordinates of a labelled axis are stored once as an index array beside the buffer.

**Fusion.** Within one statement, elementwise operations and the reductions consuming them MUST be fused into a single loop nest. Loops whose body has no capabilities SHOULD be vectorized.

**Units.** `Quantity[T, D]` pairs a numeric type with a dimension.

- A dimension is an integer exponent vector over base dimensions. Base dimensions: `length`, `mass`, `time`, `current`, `temperature`, `amount`, `luminosity`, `information` (bytes), plus one per declared currency.
- A unit is a dimension plus a compile-time rational scale. Units MUST be declared (`unit km = 1000 * m`); the standard library declares SI units, data sizes, `percent`, `bp` (0.0001) and durations from `ns` to `day`.
- Addition and comparison require equal dimensions (E530). Multiplication and division combine dimensions. Conversion between units of one dimension is explicit (`to(x, km_per_h)`); the scale factor is folded at compile time.
- Each currency is its own base dimension; converting between currencies requires an explicit rate of type `Quantity[float, eur / usd]`.
- `Duration` is `Quantity[i128, ns]` and exact. `Instant` is built on it. The calendar types `PlainDate`, `PlainTime`, `PlainDateTime` and `ZonedDateTime`, and the calendar `Period`, live in `std.time` (section 15).

**Decimal and money (v0.2).** `dec128` is IEEE 754-2008 decimal128. Rounding defaults to half-even, and division and `quantize` take an explicit `RoundingMode`. Decimal literals are exact, and there is no implicit conversion between floats and decimals. `Money` is `Quantity[dec128, Currency]`: amounts in different currencies do not add, and conversion takes an explicit rate. ISO 4217 minor units come from a table pinned in `yong.lock`.

**Tables.** `Table[R]` stores record type `R` column by column in the Apache Arrow columnar layout. Operations (`filter`, `select`, `group_by`, `agg`, `join`, `pivot`, `sort`) build a logical plan; the standard library's optimizer applies predicate pushdown, projection pruning and fusion, and executes under `sched`. `explain_plan(t)` returns the plan. `pivot` produces a labelled `Array` whose axes are the types of the pivot columns. `List[R]` stores the same records row by row, with the same operations available as eager functions.

**Schema-generated tables (v0.2).** `yong schema gen data.parquet` writes the row record type as ordinary Jian source plus the schema's hash. The output is checked in, and compilation never reads data files or the network to resolve a type. At run time, a file whose Arrow schema differs from the generated one is `fail SchemaMismatch`, carrying a column-level diff.

## 11. Jian: lexical rules and grammar

Jian is the surface written by language models. It is shaped like typed Python 3.12, it covers layers L0–L3 plus contracts, and every signature is explicit. Files use the extension `.jian`.

### 11.1 Lexical rules

- **Encoding.** UTF-8. Identifiers are ASCII; Unicode may appear only in strings and comments.
- **Value names** (variables, functions, fields, modules): lowercase words joined by single underscores, matching `[a-z][a-z0-9]*(_[a-z0-9]+)*`. No leading, trailing or doubled underscore (E110). Longer than 32 characters is warning W111.
- **Type names**: PascalCase matching `[A-Z][a-z0-9]*([A-Z][a-z0-9]*)*`, with no two consecutive capitals, so `HttpError`, not `HTTPError` (E112, auto-fixable). This makes every name a well-defined word list (section 14).
- **Comments** run from `#` to end of line. A string literal as the first statement of a module, function or class is its docstring.
- **Layout.** Python's INDENT/DEDENT rules. Canonical indentation is 4 spaces. Newlines inside brackets are joined. Backslash continuation and `;` are errors (E103).
- **Literals.** Integers in decimal, `0x`, `0o` and `0b`, with `_` separators. Floats with `.` or exponent. Strings `"…"`, raw `r"…"`, bytes `b"…"`, triple-quoted `"""…"""`, and f-strings `f"…{expr}…{expr:fmt}…"`. Single-quoted strings are accepted by the lenient reader and printed double-quoted. `True`, `False`, `None`.

**Lexical safety (v0.2).** The lexer rejects bidirectional control characters, zero-width characters and Unicode tag characters (U+E0000–U+E007F) anywhere outside string literals (E105), which closes the "Trojan Source" class. `yong fmt` prints any such character inside a literal as an escape. Identifiers are ASCII only; W801 flags confusable names. A `char` literal is `c'a'`; a plain `'a'` stays a `str`, as in Python.

**Watch expressions (v0.3 R21).** A comment line starting `#>` holds an expression that tools evaluate and display, such as the language server and the notebook. The compiler ignores it, and it does not affect item hashes.

**Keywords.** Python's keywords that Jian uses, plus Jian's own. All are reserved.

| Group | Keywords |
| --- | --- |

### 11.2 Grammar

Notation: `{x}` is zero or more, `[x]` is optional, quoted text is literal. NEWLINE, INDENT and DEDENT come from the layout rules.

**Precedence** is Python's, tightest first: postfix, `**`, unary sign, multiplicative, additive, comparison, `not`, `and`, `or`, conditional, fallback `else`.

**Mixes that require parentheses** (E101, auto-fixable):

- `and` and `or` in one expression without parentheses;
- unary minus applied to a `**` operand (`-x ** 2`);
- `%` combined with `*`, `/` or `//`;
- a conditional expression used as either side of a fallback `else`.

(v0.3 R65) A bitwise operator mixed with comparison, arithmetic or a different bitwise operator also requires parentheses (E101). The bitwise levels sit between comparison and additive, as in Python.

Chained comparisons (`a < b < c`) are E104. A comprehension has exactly one `for` clause (E107); nested iteration uses statements.

## 12. Jian: semantics, canonical form and lenient reader

### 12.1 Remaining nonterminals

```
target  = NAME | NAME "," NAME {"," NAME}
kv      = expr ":" expr
slice   = [expr] ":" [expr]
axis    = INT | NAME | path          # literal size, size variable, or label type
dim     = NAME {("*" | "/") NAME} ["**" INT]
```

### 12.2 Semantics (normative mapping to Yong)

**Bindings.** The first `x = e` in a function binds an immutable `x`. `var x = e` binds a mutable one. A later `x = e` is reassignment and requires `x` to be `var` (E403). Rebinding a name already bound in the function is E230: Jian has no shadowing. Unused bindings and parameters are E231 (prefix `_` is not an escape; delete the binding).

**Functions.** Every parameter and the return type MUST be annotated (E240). `-> None` may be omitted. A function returning `None` may fall off its end. `var p: T` is `inout`; `take p: T` is `sink`. A call passes a `var` parameter as `&place` (E404 if missing, E405 if not allowed).

**Calls.** `x.f(a)` and `f(x, a)` are the same call. If `f`'s first parameter is `var`, the receiver form is allowed only when `x` is a mutable place, and no `&` is written. If any two parameters of the callee share a type, every argument must be passed by keyword (E210). The same rule applies to record constructors.

**Records.** `class C:` with annotated fields declares a record. Records have no methods: functions taking the record first serve that role through the dot form. Fields may have defaults. Every record automatically derives `Eq`, `Hash` and `Show`, as Python dataclasses do. Records are constructed with keyword arguments (`C(a=1, b=2)`) and are immutable unless bound with `var`. `evolve(c, a=3)` returns a copy with fields changed.

**Sums.** `type S = A | B | …` declares a sum when each alternative is a class declared in the same module, or when there are at least two alternatives and the rest are fresh PascalCase names, which become field-less variants. Each class may belong to at most one sum. Constructing a variant class yields a value of the sum type. Otherwise `type N = T` declares a newtype: a distinct type with no implicit conversion, built with `N(v)` and unwrapped with `.value`.

**Match.** `match` must be exhaustive (E503). On a sum type, `case _` is forbidden (E502), so adding a variant breaks every match that should handle it. On scalars and strings, `case _` is required unless the cases are provably exhaustive.

**None and narrowing.** `T | None` is `Option[T]`. `x is None` and `x is not None` narrow an immutable binding's type in the branch they guard, as in mypy. `x else y` unwraps or falls back. `x?` propagates `None` when the function returns an optional type.

**Results.** `-> Result[T, E]` is Yong's `-> T fail E`. `return v` returns success; `fail e` returns failure; `Ok(v)` and `Err(e)` construct and match explicitly. `x?` propagates through a `From` implementation if the error types differ (E310). `x else y` handles both `None` and `Err`, and `x else return` or `x else fail e` exits.

**Indexing.** `xs[i]` on a list compiles only when the bounds solver proves `0 <= i < len(xs)` (E501; fix: `xs.get(i)`). `d[k]` on a dict compiles only when `k in d` is established on every path (E501; fix: `d.get(k)`). `.get` returns `T | None`. Assigning d\[k\] = v always compiles; it inserts or replaces. Slices clamp, as in Python, and never panic.

**v0.3 additions (R63, R64, R65, R69, R70, R77, R83).** A non-escaping lambda argument may use `?`; the failure propagates out of the call (R63). `x else err -> h` binds the failure in the fallback (R64). Bitwise operators work on integer types through `Bits` (R65), replacing `bits.band` and its siblings. `x.share()` aliases an Rc, Arc, Sender or actor handle, and `x.copy()` on one is E416 (R69). Views follow R70: `from a, b`, the types `StrView` and `MutView`, and `v.copy()` for an owned copy. Parameters before `/` are positional-only and exempt from E210 (R77). A user capability is named by the snake\_case form of its trait (R83).

**Numbers.** `int` is a 64-bit checked integer; overflow panics. `/` on integers produces a `float`. `//` and `%` floor, as in Python. `bool` is not a number. Conversions are explicit: `float(x)`, `int(x)` (truncates toward zero, panics on NaN or out of range), `round(x)`. `+` on `str` and on `list` concatenates (trait `Concat`).

**Strings (v0.2).** Jian has no `len(s)` on `str` and no `s[i]`, because both are ambiguous over UTF-8 (section 3). Use `s.byte_len()`, `s.char_count()` or `s.grapheme_count()`, and iterate with `s.chars()`, `s.bytes()` or `s.graphemes()`. The lenient reader rewrites `s[i]` to `s.char_at(i)` with a note that it costs O(n); strict mode reports E504 and suggests the views.

**Big integers and slices (v0.2).** `bigint` is in the prelude, and an `int` overflow panic message suggests it. Slices still clamp as in Python, but a lint flags a constant slice proven out of range, and `xs.slice_exact(a, b) -> list[T] | None` refuses to clamp.

**Effects.** Every function lists its capabilities in `uses`, except `alloc` (section 6). `print` is `io.print`.

**Contracts.** `pre`, `post`, `ex` and `decreases` lines come first in a body, after the docstring. In `post`, `out` is the result and `old(p)` is a `var` parameter's entry value. Every `pub` function except `main` MUST have at least one `ex` (E601). A recursive function MUST have `decreases` (E602), except where the lenient reader infers it (below).

**Tests.** A top-level function named `test_…` with no return annotation is a test; its `assert`s must hold. If it has parameters, it is a property test: inputs are generated from the parameter types, and failures are shrunk to a minimal case. Tests may bind fake handlers with `with`.

**Concurrency.** In `par:`, each top-level statement is one branch. A branch may not read a binding made by another branch in the same block (E705). `par [e for x in xs]` is `par for`. `?` inside a `par` branch or comprehension propagates the first failure in source order, after cancelling the others. Actors come from `std.actor`.

**Deadlines (v0.2).** `with deadline(t):` and `with timeout(d):` are Jian's spelling of section 8's cancel scopes. A function using them needs no extra capability: expiry surfaces as `Timeout` in its failure type.

**Test isolation (v0.2).** Tests run with default handlers: an in-memory `fs`, seeded `rand`, virtual (R54) `time` and no `net`. A test that needs a real capability says so with `with`. Snapshot tests compare against stored output; `yong test --update` rewrites the snapshots as a patch for review.

**Test caching (v0.3 R19).** A test that binds no real capability is a pure function of the hashes of every item it reaches, its handler bindings, its generator seed and the toolchain hash. `yong test` MAY reuse a stored verdict for an unchanged key and MUST mark it cached; `--no-cache` forces a run. A test that binds a real capability with `with` is never cached.

### 12.3 Canonical form

The printer MUST produce exactly one text for a given Jian tree:

- 4-space indentation, LF line endings, no trailing whitespace, one final newline.
- One blank line between top-level items; none inside function bodies.
- Items in author order. Patches append new items at the end of the module.
- Double-quoted strings, choosing f-strings where the source used them.
- Minimal parentheses, plus those required by E101.
- Lines over 100 characters are wrapped inside brackets with one argument per line and a trailing comma.
- Contracts in the order `pre`, `post`, `ex`, `decreases`.

### 12.4 Lenient reader

The lenient reader accepts these deviations and normalizes them, reporting a note (N-code) instead of an error. `yong check --strict` disables it.

| Code | Accepted input | Normalized to |
| --- | --- | --- |
| N01 | `import m`, `from m import a` | removed; uses of `a` become `m.a` |
| N02 | any consistent indentation, including tabs | 4 spaces |
| N03 | single-quoted strings | double-quoted |
| N04 | `Optional[T]`, `List[T]`, `Dict[K, V]`, `Set[T]`, `Tuple[…]`, `Union[A, B]` (error position) | `T \| None`, `list`, `dict`, `set`, `tuple`, `A \| B` |
| N05 | missing `decreases` on structural recursion over a sum or list | inferred measure |
| N06 | `a + b * c`, `a and b or c` and other mixes covered by E101 | parentheses inserted by standard Python precedence |
| N07 | `HTTPError`-style names | `HttpError`, renamed throughout the module |
| N08 | `@dataclass` on a class | removed |
| N09 | methods with `self` inside a class body | lifted to top-level functions with first parameter `self: C` |
| N10 | `x == None`, `x != None` | `x is None`, `x is not None` |
| N11 | CRLF, trailing whitespace, missing final newline | canonical |

**v0.2 additions.** N12 rewrites `s[i]` on a `str` to `s.char_at(i)` and emits a note. The reader never inserts `_ =` before an unused result, because that would hide the bug E312 exists to catch; it emits a note with a machine-applicable fix instead.

`raise`, `try` and `except` are not normalized: they are errors (E120) with a suggested rewrite, because their semantics differ from `Result`.

### 12.5 Complete example

```
"""Fetch quotes concurrently and value a portfolio."""

class Position:
    sym: str
    qty: int

class Quote:
    sym: str
    px: float

class MissingQuote:
    sym: str

class Fetch:
    msg: str

type PortErr = MissingQuote | Fetch

impl From[net.HttpError] for PortErr:
    def convert(e: net.HttpError) -> PortErr:
        return Fetch(msg=e.msg)

def fetch_quote(sym: str) -> Result[Quote, PortErr] uses net:
    body = net.http_get(f"https://px.example/{sym}")?
    px = json.parse_float(body) else fail Fetch(msg=f"bad price: {sym}")
    return Quote(sym=sym, px=px)

pub def value(ps: list[Position], qs: dict[str, Quote]) -> Result[float, PortErr]:
    pre len(ps) > 0
    ex value([Position(sym="A", qty=2)], {"A": Quote(sym="A", px=10.0)}) == Ok(20.0)
    var total = 0.0
    for p in ps:
        q = qs.get(p.sym) else fail MissingQuote(sym=p.sym)
        total += float(p.qty) * q.px
    return total

pub def main() -> Result[None, PortErr] uses io, net:
    ps = [Position(sym="SPX", qty=10), Position(sym="NDX", qty=5)]
    quotes = par [fetch_quote(p.sym)? for p in ps]
    qs = {q.sym: q for q in quotes}
    total = value(ps, qs)?
    io.print(f"portfolio value: {total}")

def test_missing_quote_fails():
    assert value([Position(sym="X", qty=1)], {}) == Err(MissingQuote(sym="X"))

def test_value_scales_with_qty(n: int):
    assert value([Position(sym="A", qty=n)], {"A": Quote(sym="A", px=1.0)}) == Ok(float(n))
```

## 13. Wen: the human surface

Wen is the surface people write and read. It covers layers L0 to L6, files use the extension `.wen`, and it is built in milestone M3; until then its text is produced only by `yong view --as wen`. Wen infers what R68 allows: the return type of a single-expression body, and `uses` and `fail` on non-pub items. Everything else is written. Every Wen tree has exactly one printing (R61), so the formatter and the projection are the same printer. This section was rewritten on 2026-10-31 for rows R61 to R84.

### 13.1 Lexical rules

- **Encoding and safety.** As Jian (11.1): UTF-8, ASCII identifiers, and the lexical safety rules (E105).
- **Names.** Value names are snake\_case and type names PascalCase, exactly as in Jian (E110, E112), so both surfaces spell every name identically. Backticks quote foreign names only (section 14, R81).
- **Comments.** ` --  ` (with the space) runs to end of line; `--` anywhere else is E132. ` ---  ` starts a Markdown doc comment. A line starting ` -->  ` holds a watch expression (R21, R79). Examples are `ex` clauses, not doc-comment lines (R73).
- **Layout.** Blocks are indentation only, 2 spaces; tabs are E133. Newlines inside brackets are joined. A line whose first token is `.` or a binary operator continues the previous line (R67). There is no `;` outside grid literals.
- **Literals.** Integers, floats, `True`, `False` and `None` as in Jian. Strings `"..."`, raw `r"..."`, bytes `b"..."` and triple-quoted strings; non-raw strings interpolate `\(expr)` and `\(expr:spec)`, and braces are literal (R76). A char is `c'a'`. A symbol (Sym) is `'SPX` (R81).
- **Units, dates and grids.** Unit-suffixed numbers such as `150ms`, `64MB`, `2.5bp` and `5pct`, where the suffix must be a declared unit. A date is `2026-10-30` (PlainDate), an instant is `2026-10-30T09:00:00Z`, and a zoned time is `2026-10-30T09:00[America/Chicago]`; there is no implicit local zone. Grid literals separate elements by spaces and rows by newlines or `;`: `[1 2; 3 4]`. Inside a grid, unary minus must attach (`[1 -2]` is two elements), and `a -b` is E134. Display widths count graphemes.
- **Keywords.** `let var mut take pub type trait impl dyn const use as uses fail try if then else match is for in while loop break continue return par concurrent spawn with region deadline timeout unsafe pre post ex invariant decreases and or not copy share from self assert unreachable` gen yield select asm. All are reserved.

```
base      = TYPENAME ["[" targ {"," targ} "]"] | scalar | "dyn" TYPENAME ["[" type {"," type} "]"]
          | "(" type "," type {"," type} ")" | "{" field {"," field} "}"
targ      = type | NAT
scalar    = "i8" | "i16" | "i32" | "i64" | "i128" | "u8" | "u16" | "u32" | "u64" | "u128"
          | "f16" | "bf16" | "f32" | "f64" | "f128" | "int" | "float" | "bool" | "char" | "str"   -- R80
```

**Precedence** is Python's, tightest first: postfix, `as`, `**`, unary, multiplicative, additive, shifts, `&`, `^`, `|`, comparison and `is`, `not`, `and`, `or`, conditional, fallback `else`, lambda. **Mixes that require parentheses** (E101, auto-fixable): `and` with `or`; unary minus on a `**` operand; `%` with `*`, `/` or `//`; a bitwise operator with comparison, arithmetic or a different bitwise operator; and a conditional as either side of a fallback `else`. Chained comparisons are E104. A `sum` with one alternative must give it fields, otherwise `type N = T` is a newtype.

```
expr     += "asm" "(" STRING {"," asmarg} ")"                           -- only inside unsafe; R86
```

### 13.3 Semantics (normative mapping to Yong)

**Bindings.** `let x = e` binds an immutable name and `var x = e` a mutable one. Only `var` bindings and `mut` parameters may be assigned (E403). There is no shadowing (E230, R61). An unused binding is lint W812 (R77).

**Functions.** Parameters are always annotated (R68). A single-expression body `= e` may omit `-> T`; a block body declares `-> T` unless it returns unit, and its last expression is the result. A non-unit last expression in a unit body is E312. `pub` functions write `fail` and `uses` in full; others may omit them, and the elaborator infers both per strongly connected component. `mut p: T` is inout, `take p: T` is sink and a plain parameter is let. A `self` parameter has type Self.

**Calls.** `x.f(a)` and `f(x, a)` are one call, resolved by 15's method rules. An inout argument is written `&place` (E404 missing, E405 extra); a receiver that is a mutable place takes no mark (SQ29, R66). If two parameters share a type, arguments are passed by label (`name: e`) unless they are positional-only (E210, R77). `name:` alone passes the variable of that name (R82).

**Records, sums and newtypes.** `type R = { a: A, b: B = d }` declares a record, built as `R(a: 1, b: 2)` and immutable unless bound with `var`; `evolve(r, a: 3)` returns a changed copy. Records derive Eq, Hash and Show, as in Jian. `type S = A(x: X) | B` declares a sum whose variants are introduced here, and constructing a variant yields an `S`. `type N = T` declares a newtype, built with `N(v)` and unwrapped with `.value`.

**Optional values.** `T?` is `Option[T]`. `x is None` and `x is not None` narrow as in Jian. `x?` propagates None in a function returning an optional type, and `x else y` falls back.

**Failure.** `-> T fail E` is Yong's `-> T fail E` (R64). `fail e` returns a failure. `x?` propagates, injecting into a union or converting through `From` (E310, E313). `x else y` handles None and failure; `x else err -> h` binds the failure; `x else return` and `x else fail e` exit. `try x` gives `Result[T, E]` for `match`. `.context(msg)` wraps a failure. Closures passed to non-escaping parameters may use `?`, and the failure propagates out of the higher-order call (R63).

**Lambdas and the implicit subject.** `x -> e` and `(a, b) -> e` are closures, capturing by copy (section 4). `.field` in argument position becomes a closure or a column expression by the expected type (R67), and implicit-subject closures may not nest (E135).

**Copies, sharing and views.** The elaborator inserts moves at last use (section 4). Storing a heap-backed value that is still used needs `copy x`, a deep copy (E413). `share x` makes an O(1) alias of an Rc, Arc, Sender or actor handle, and `copy` on such a value is E416 (R69). `View[T]`, `MutView[T]` and `StrView` are second-class borrows; a function returns one with `-> V from p` or `from p, q`, and any type that contains a view is second-class (R70). `copy v` on a view gives the owned value.

**Indexing and strings.** Unlike Jian, Wen accepts `xs[i]` that cannot be proven in bounds, inserting one runtime check that the editor shows as a hint; `@no_panic` forbids such checks. Slices clamp as in Jian. Strings follow Jian: no `len` and no integer indexing on `str` (E504).

**Match.** `match` must be exhaustive (E503). On a sum, `_` is lint W811 rather than E502 (R71). `e is P` and `let P = e else exit` bind as R71 says.

**Effects and handlers.** `uses` lists capabilities, never failure. `alloc` is ambient. A user capability binds by the snake\_case form of its trait name, or by `uses name: Trait` (R83). `with name = e` binds a handler for the block and `with name = dyn e` makes it dynamic (section 6). `region r` binds `Arena[r]` (R40, R84).

**Concurrency.** `par` runs each top-level statement of its block as a branch; `par for x in xs` collects a List in input order, or streams when its body is unit, with `limit:` (R74). `par concurrent` requires a handler that guarantees progress (E708). `log` and `metrics` split per branch automatically; `io` needs `io.split`. `deadline t` and `timeout d` blocks are section 8's cancel scopes. `spawn` creates actors only, and `@reentrant` marks an actor handler.

**Contracts and tests.** `pre`, `post`, `ex`, `decreases` and loop `invariant` lines open a body, in that order. In `post`, `out` is the result and `old(p)` a `mut` parameter's entry value. A pub item without `ex` is lint W813 (R77). A top-level function named `test_...` is a test, as in Jian.

**Numbers and operators.** As Jian 12.2: `int` is a checked i64, `/` on integers gives a float, and `//` and `%` floor. The sized scalars use R80's names, and `as`, `wrap_as`, `sat_as` and `trunc_as` convert (section 3). Operators are R65's, shared with Jian.

**Layers.** L4: `region`, `Ref`, `@layout` and the proof attributes. L5: `#expr`, user attributes, the reflection API and generators (`gen`, `yield`; R85). L6: `unsafe`, `Ptr`, `Vec` and `asm` (R86). None of these may appear in Jian. `select` (R87) is L3.

### 13.4 Canonical form

The printer produces exactly one text for a Wen tree, and wen(elaborate(W)) == fmt(W) (R61):

- 2-space indentation, LF line endings, no trailing whitespace, one final newline.
- One blank line between top-level items; none inside bodies.
- Items in author order; patches append new items at the end of the module.
- Signature clauses in the order `-> T from p`, `fail E`, `uses`. Clauses the author left to inference are not printed.
- Contracts in the order `pre`, `post`, `ex`, `decreases`.
- Double-quoted strings, minimal parentheses plus those E101 requires, and nothing aligned.
- Lines over 100 characters wrap inside brackets, one element per line with a trailing comma. Method chains wrap with one leading-`.` call per line.
- A lambda whose body is a field-access chain on its parameter prints as the implicit subject.

### 13.5 Example

The Jian program from 12.5, in Wen:

```
--- Fetch quotes concurrently and value a portfolio.

type Position = { sym: str, qty: int }
type Quote = { sym: str, px: float }
type PortErr = MissingQuote(sym: str) | Fetch(msg: str)

impl From[net.HttpError] for PortErr
  convert(e: net.HttpError) -> PortErr = Fetch(msg: copy e.msg)

fetch_quote(sym: str) -> Quote =
  let body = net.http_get("https://px.example/\(sym)")?
  let px = json.parse_float(body) else fail Fetch(msg: "bad price: \(sym)")
  Quote(sym: copy sym, px:)

pub value(ps: List[Position], qs: Map[str, Quote]) -> float fail PortErr =
  pre ps.len() > 0
  ex try value([Position(sym: "A", qty: 2)], {"A": Quote(sym: "A", px: 10.0)}) == Ok(20.0)
  var total = 0.0
  for p in ps
    let q = qs.get(p.sym) else fail MissingQuote(sym: copy p.sym)
    total += float(p.qty) * q.px
  total

pub main() -> () fail PortErr uses io, net =
  let ps = [Position(sym: "SPX", qty: 10), Position(sym: "NDX", qty: 5)]
  let quotes = par for p in ps
    fetch_quote(p.sym)?
  let qs = quotes.index_by(.sym)
  io.print("portfolio value: \(value(ps, qs)?)")
```

## 14. Names, projection and round-trip

**Names are word lists.** Yong stores every identifier as a sequence of lowercase ASCII words plus a class: `value` or `type`. Printing rules:

| Class | Jian | Wen | Yong text |
| --- | --- | --- | --- |
| value | words joined by `_` | words joined by `_` | words joined by `_` |
| type | PascalCase | PascalCase | PascalCase |

PascalCase is split into words at each capital letter, which is why consecutive capitals are forbidden (E112). Digits attach to the preceding word.

**Foreign names.** Names that come from outside (C symbols, SQL columns, JSON keys, Python attributes) are stored verbatim with the flag `foreign` and printed unchanged by both surfaces. They are introduced only by `@extern`, schema declarations and the Python bridge. Within Wen, a foreign name that is not a valid Wen name is written in backticks.

**Surface-specific names (v0.2).** Some library names differ by surface on purpose, so each reads natively. The projection table records them, and the round-trip laws hold through it.

| Yong | Jian | Wen |
| --- | --- | --- |
| `List` | `list` | `List` |
| `Map` (insertion-ordered) | `dict` | `Map` |
| `Set` (insertion-ordered) | `set` | `Set` |
| `Deque` | `deque` | `Deque` |
| `Heap` (min-heap) | `heap` | `Heap` |
| `SortedMap`, `SortedSet` | `sorted_dict`, `sorted_set` | `SortedMap`, `SortedSet` |
| `BigInt` | `bigint` | `BigInt` |
| `Str.char_count` | `str.char_count` | `Str.char_count` |

v0.3 surface pairs (R64, R66, R69, R76, R80, R85):

| Yong | Jian | Wen |
| --- | --- | --- |
| inout parameter | `var p: T` | `mut p: T` |
| failure in a signature | `-> Result[T, E]` | `-> T fail E` |
| reify a failure | the call itself (it returns `Result`) | `try f(x)` |
| deep copy, alias | `x.copy()`, `x.share()` | `copy x`, `share x` |
| interpolation | `f"{x:.2f}"` | `"\(x:.2f)"` |
| i8 ... i128, u8 ... u128 | `int8` ... `int128`, `uint8` ... `uint128` | `i8` ... `i128`, `u8` ... `u128` |
| f16, bf16, f32, f64, f128 | `float16`, `bfloat16`, `float32`, `float64`, `float128` | `f16`, `bf16`, `f32`, `f64`, `f128` |
| closure | `lambda x: e` | `x -> e` |
| generator | none (Jian has no generators) | `gen f(...) -> T` |

**Projection operations.**

| Command | Input | Output |
| --- | --- | --- |
| `yong view --as wen F` | a Jian module | idiomatic Wen: `let` added, implicit-subject lambdas where a lambda is a single field access chain, contracts and examples kept |
| `yong view --as jian W` | a Wen module | canonical Jian, for every item within the Jian subset |
| `yong elaborate X` | either surface | Yong text |

Items outside the Jian subset are reported, not dropped. The report names the first construct that excludes each item (for example "uses `region` (L4)").

**Shadowing.** Neither surface allows shadowing (E230; Wen since R61), so projection renames nothing.

**Round-trip properties.** These MUST hold and MUST be tested on every conformance program (section 20):

1. For any canonical Jian module `F`: `jian(elaborate(F)) == F`, byte for byte.
2. For any canonical Jian module `F`: `jian(wen(F)) == F`, byte for byte.
3. For any Wen module `W` within the Jian subset: `elaborate(jian(W)) == elaborate(W)` as Yong, compared by item hash.
4. For any module `X` in either surface: the item hashes of `elaborate(X)` do not depend on formatting, comments or item order.

(v0.3 R61) For any Wen module W: wen(elaborate(W)) == fmt(W), byte for byte, comments kept at their items. This MUST be tested on every conformance program too.

**Item identity.** An item's hash is the BLAKE3 hash of its canonical Yong text, excluding comments and docstrings, with references to other items replaced by their hashes. Two items with the same hash are the same item, whichever surface they came from.

## 15. Standard library

The standard library is written in Jian wherever possible, with runtime intrinsics for the rest. Names below are given in Jian spelling. This is the minimum for v0.2; the implementer MAY add functions but MUST NOT change these signatures without a `SPEC_QUESTIONS.md` entry.

**Method resolution (normative).** `x.f(…)` resolves `f` by looking, in order, in the module that declares the type of `x`, then the prelude, then the current module. A std module may get a `v2` successor (`std.rand.v2`) rather than change incompatibly within an edition.

**`Wire` decoding (v0.2, normative).** Decoding produces only a statically known type. Sum types use their declared tags, and no tag can select an arbitrary type. No user code runs during decoding except validation and invariant checks after construction. Depth, total size, and collection and string lengths are always limited. Unknown fields are rejected unless the type opts in, and so are duplicate keys (v0.3 R26). Capability values are never `Wire`.

**`Secret[T]` (v0.2).** `Show` prints `Secret(***)`. A secret is not `Wire` until `expose()` is called, is zeroized on drop, compares in constant time, and appears hashed in replay traces. A lint flags an exposed secret flowing into `log`.

**Python bridge modes (v0.2).** `py` is a dedicated executor that owns the interpreter. On a GIL build, calls are serialized. On free-threaded CPython 3.14t and later, `py(threads=N)` runs calls in parallel only for modules that declare free-threading support. `Py[T]` handles are reference counted and released on the `py` executor. A Python exception becomes `fail PyErr {type, msg, traceback}`, `KeyboardInterrupt` becomes cancellation, and a Yong panic aborts the process (v0.3 R5, R102) instead of reaching Python as `YongPanic`. Unpickling is available only for inputs marked `@trusted_input`.

**Errors.** Each module that can fail defines one error type (`FsError`, `HttpError`, `JsonError`, …) as a record or sum with `Show`, `Eq` and `Wire`.

- `yong test --update`: rewrites snapshot files as a reviewable patch.

Lints are reported by `yong check` (R15); single-file scripts run with `yong run` (R20).

**Package manifest.** `package.jian` is a Jian module evaluated at compile time. It defines `name`, `version`, `dependencies` (name to version requirement), `allow_ffi` (a list of package names) and `capabilities` (the maximum set the package may use). Versions resolve by minimal version selection, recorded in `yong.lock`.

**Manifest additions (v0.2).**

- `edition` names the language edition. Packages from different editions link into one build, and only the newest edition is ever printed.
- `capabilities` is a ceiling enforced transitively: using a capability the package did not declare is an error, including through dependencies. A dependency that gains a capability (computed by the registry, R199) or changes publisher identity (R198) in a new version blocks the update until a human signs an approval (R200) with `yong audit --diff`.
- `platform` names a capability bundle with default handlers (`cli`, `service`, `job`, `wasm`), so a whole application is sandboxed in one word. It sets the ceiling; it does not replace `uses`.
- `yong.lock` also records each package's attestation identity and the pinned tzdb, Unicode and ISO 4217 versions.


Renderings from the same record:

- **Line** (default for Jian, and for `--format line`): `E501 src/pricing.jian:14:9 index may be out of bounds | fix: use xs.get(i)`
- **Prose** (default for Wen): a heading, the source excerpt with the span underlined, the message, notes, and the fix, in the style of Elm's compiler.
- **JSON** (`--format json`, and always over MCP).

Rules:

- Report root causes only. Suppress diagnostics caused by an earlier error in the same item.
- At most 10 errors per run by default (`--max-errors`).
- Codes are stable forever. A code may be retired, never reused.
- Every error with a mechanical fix MUST include it in `fixes`.

### 16.2 Patch protocol

Models and tools change code only through patches. A patch is JSON:

```
{
  "module": "app.pricing",
  "base": {"value": "b3:9f2c…", "main": "b3:41aa…"},
  "replace": ["def value(…) -> …:\n    …"],
  "add": ["def vwap(…) -> …:\n    …"],
  "delete": ["old_value"],
  "edits": [{"item": "main", "search": "qty=10", "replace": "qty=20"}]
}
```

Semantics (normative):

1. A patch is atomic: all of it applies, or none.
2. `base` maps item names to the hashes the author saw. If any differs from the current hash, the patch is rejected with P001, and the response includes the current text of those items.
3. `replace` entries are complete items, matched to existing items by name (P004 if absent). `add` entries must not exist yet (P005) and are appended to the module. `delete` names must exist.
4. `edits` apply exact string replacement inside the named item only. The search text must match exactly once within that item (P002 otherwise).
5. The result is printed canonically. With `--check`, the patch is rejected (P003) if it introduces any error in a touched item or its dependents, and the diagnostics are returned.
6. A plain Jian source file containing only whole items is also accepted as a patch: each item replaces the item of the same name, or is added if new.

**Protected targets (v0.2).** `check_patch` rejects a patch that touches any of the following unless it carries a human confirmation token: test functions, `pre`, `post`, `ex`, `invariant` and `decreases` clauses, `package.jian` capabilities, `yong.lock`, and agent configuration files. An implement-step patch never carries one (section 17.1).

### 16.3 Registry and supply chain (v0.2)

The registry design is fixed in M1 and built in M2. Normative:

- **No install-time code.** Packages have no install scripts or build scripts; stage-0 evaluation is hermetic.
- **Source of truth.** The registry rebuilds each package from a tagged source commit, or verifies that the upload equals that source. An uploaded tarball is never authoritative. Binary test fixtures are declared and invisible to builds.
- **Publishing.** Only short-lived OIDC trusted publishing, never stored tokens. Publishers of popular packages need two-factor authentication. (v0.3 R194: no API tokens exist; namespace administration needs a passkey.)
- **Attestations.** Every version carries a Sigstore attestation. Installs verify it by default, and a mismatch is a hard error. (v0.3 R191 to R193: witnessed log, registry-built archive, SLSA Build L3 provenance.)
- **Names.** Packages are namespaced (`@org/name`) with ASCII-only names. A new name within edit distance 2 of a top-1000 name needs review.
- **Selection.** A new version of a popular package waits through a configurable cool-off window before version selection picks it. A yanked version still resolves from existing lockfiles but is never newly selected; legal deletion is separate. (v0.3 R197: the cool-off applies to every package, default 3 days. R203 adds malicious-version marks.)
- **Builds.** Builds are reproducible and independent of paths and timestamps, and record the linker version in provenance. (v0.3 R204: all C sources compile with the toolchain's pinned clang; R205 adds independent rebuilders.)

## 17. Agent features

These features make Jian cheap and reliable for models to write. They are toolchain features, not language features, and all of them read from the same query database.

### 17.1 The spec gate

Generation happens in two phases, enforced by `yong mcp` and available to any agent.

1. **Spec.** The model submits an item with a body of `...`: signature, `uses`, docstring, `pre`, `post`, `ex`. The tool checks that types resolve; that each `ex` is well-typed; that each `ex` satisfies `pre`; that each `ex`'s expected result satisfies `post`, where that can be evaluated; and that `pre` is satisfiable, by the bounds solver or SMT when available. Problems are returned as diagnostics.
2. **Body.** The model submits the body against the frozen spec. Changing any spec line reopens phase 1.

Human review of model-written code starts with the spec, which is short and readable.

**Spec freeze (v0.2, normative).** Coding agents rewrite tests to pass when they can: ImpossibleBench (ICLR 2026) measured a 93% test-hacking rate in one configuration. So the tests and contracts produced by the spec step are frozen once a human accepts them. An implement-step patch may not touch test functions or `pre`, `post`, `ex`, `invariant` and `decreases` clauses; `check_patch` enforces this (section 16.2). If the agent believes a frozen test is wrong, it stops and reports instead of editing. A lint flags code that special-cases the literal inputs of `ex` clauses.

### 17.2 Typed holes

`_` in expression position is a typed hole (Jian and Wen).

- `yong check` reports each hole as H701 with its expected type.
- In development builds, a program with holes runs: a hole evaluates to an indeterminate value, operations on it propagate indeterminacy, and evaluation continues around it, as in Hazel. Release builds reject holes (E702).
- The `hole_context` query returns, for one hole: expected type, in-scope bindings with types, the enclosing function's contracts, nearby examples, and the top five `search_type` results. The output MUST fit in 400 tokens.

### 17.3 Constrained decoding

The compiler exposes, for any prefix of an item being generated, the set of valid continuations:

- **Grammar.** The Jian grammar as a token-aligned grammar for llguidance and XGrammar, and as GBNF for llama.cpp. It ships with the toolchain and is versioned with it.
- **Names and types.** At each identifier position: the in-scope names whose types can fit the expected type.
- **Effects and mutability.** Calls needing a capability the function does not declare, and `&` arguments to non-`var` places, are excluded.

Masks apply only to the code being generated, never to the model's reasoning. Jian MUST remain fully usable without any constraint, because hosted model APIs may not expose masks.

### 17.4 Agent server (`yong mcp`)

A Model Context Protocol server over stdio. Every tool returns JSON; diagnostics use the schema in 16.1.

| Tool | Input | Output |
| --- | --- | --- |
| `check` | module or item name | diagnostics |
| `check_patch` | patch (16.2) | diagnostics, or success with new hashes; nothing is written |
| `apply_patch` | patch | as `check_patch`, then writes |
| `autofix` | item name | the patch produced by applying every machine-applicable fix |
| `sig` | module name, optional budget | signatures, contracts, examples |
| `pack_context` | task description, budget in tokens | the most relevant signatures, contracts and examples, ranked by dependency distance from the items named in the task |
| `search_type` | a type, e.g. `Callable[[Table[Trade]], Array[Sym, float]]` | matching functions with signatures, best first |
| `type_at` | file, line, column | inferred type and capabilities |
| `hole_context` | file, line, column | as 17.2 |
| `spec_check` | an item with body `...` | phase-1 results (17.1) |
| `run_tests` | filter | results, with counterexamples for property tests |
| `explain` | code | long-form text |
| query | a Jian body using only the toolchain capability; step and token budgets | the body's return value as JSON, or its diagnostics (v0.3 R16) |
| undo | number of operations, default 1 | the reverted operations and new hashes (v0.3 R16) |

**Autofix loop.** An agent SHOULD call `autofix` before asking the model to repair anything. Errors whose only fix is mechanical (missing `uses`, keyword arguments, parentheses, `&` marks, lenient normalizations) never cost a model generation.

**Untrusted content (v0.2, normative).** Repository text is an attack surface: 2025 brought prompt-injection CVEs in Copilot, Cursor, Amazon Q and Claude Code through comments, READMEs and rules files. So:

- `pack_context` and `hole_context` emit comments, docstrings and string literals in a fenced channel marked untrusted, and strip or flag zero-width, bidirectional and tag characters.
- `yong mcp` never applies a patch to a protected target (section 16.2) without a human confirmation token.
- No repository-defined code or configuration runs before the user has trusted the repository.

**Why-shared tool (v0.2).** The `why_shared` MCP tool, the editor hint and `yong bench` all report where a value is deep-copied or shared through Rc or Arc, with the site, so an agent can fix a hot path.

### 17.5 Provenance

Each item MAY carry provenance stored in `.yong/provenance.jsonl`, keyed by item hash: author type (`human` or `model`), model identifier, prompt hash, timestamp, and verification status (`checked`, `tested`, `proven`). `yong audit` reports model-authored changes to `ffi` modules and to any item whose capability set grew. It also lists every extern block, safe extern item and uses none claim (v0.3 R104).

In v0.2 each record is an in-toto statement: `{item_hash, author: human | model(id, version), prompt_hash?, tool_calls_hash, base_hashes, time}`, optionally signed. `yong audit` reports model-authored code no human has reviewed.

### 17.6 Evaluation harness (v0.2)

The M1 gate is measured with a harness specified here, so the result can be trusted:

- Held-out tests the model never sees, on fresh tasks that resist training-data contamination, in a versioned task set.
- End-to-end token counts, including retries and tool calls, against a typed-Python baseline on the same tasks.
- pass@1 at temperature 0 and at the deployment temperature.
- An ImpossibleBench-style cheating rate: tasks whose tests contradict the spec, where any pass counts as cheating.
- Results stored with the toolchain hash and the model identifier.

**Linking (v0.2).** M1 uses the system linker, as Rust does. M2 bundles `lld` (`lld-link` on Windows with MinGW or UCRT import libraries) and target libc stubs, which make cross-compilation work without a platform toolchain. Yong bundles no C compiler; a package with C sources uses the user's `cc`.

**Debugging and profiling (v0.2).** Cranelift output carries DWARF line tables and variable locations, with GDB and LLDB pretty-printers for `Option`, `Result`, `Str`, `Array` and `Table`. The interpreter serves the Debug Adapter Protocol. Backtraces follow tasks and actors to their ancestors. Symbol mangling is specified and demanglable. The profiler samples per task, writes flamegraphs and perf maps, and reports copy, Rc and Arc events per site (v0.3 R17).

**Front end.** Hand-written lexers and recursive-descent parsers, with precedence climbing for expressions. Parsers MUST produce lossless syntax trees (every byte, including comments and whitespace, is recoverable), because the formatter, the lenient reader and patch application all depend on them. Parse errors MUST recover at item boundaries, so one broken item never hides diagnostics in others.

**Comments through Yong.** Comments and docstrings are attached as trivia to the nearest following statement or item and carried through Yong as non-hashed metadata, so the round-trip properties in section 14 hold byte for byte.

**Elaboration order** per item: resolve names, check the signature, infer and check the body bidirectionally, insert capability arguments, insert copies and moves by last-use analysis, and lower to Yong. Yong is then validated by `yong-core`'s validator (every `let` typed, every argument's convention explicit) before any checking pass runs. A validator failure is an internal compiler error, never a user diagnostic.

**Check order** on Yong: exhaustiveness, then ownership and exclusivity, then bounds and refinements, then units and shapes, then contracts (at the selected level).

**Runtime.** (v0.3) There is no language runtime. `yong-rt` holds std's support code: the `pool` scheduler (fork-join over OS threads), the default `alloc` handler (mimalloc), blocking platform I/O, record and replay, and the panic hook, which prints, writes any replay buffer and aborts. Ordinary values carry no header; `Rc` and `Arc` keep their count in their block. `std.evented` adds stackful coroutines and io\_uring/kqueue. Generated code has no landing pads; the interpreter aborts the same way.

**Testing strategy.**

- Snapshot tests for the parser, printer, elaborator and Yong output.
- Fuzzing of both parsers and of the patch applier, with the property "never panics; round-trip holds on accepted input".
- Differential testing: every conformance program runs on the interpreter and on each code generator, and outputs MUST match exactly. This also exercises the determinism guarantee.
- Property tests for the round-trip laws in section 14.

**Working rules for the implementing agent.**

1. Follow the milestones in order. Do not start a milestone until the previous one's acceptance criteria pass.
2. Propose each feature's conformance tests (section 20) for the spec owner's approval before implementing it. Approved tests, conformance files and the spec are read-only to agents: CI rejects any agent patch that touches tests/, conformance/ or spec/.
3. Keep `SPEC_QUESTIONS.md` current; never resolve an ambiguity silently.
4. Keep the compiler's own diagnostics in the 16.1 format from the first commit, because the agent loop depends on them.

## 20. Conformance suite and diagnostic codes

The conformance suite is the executable form of this spec. It lives in `conformance/` and MUST grow with every feature.

### 20.1 Layout and test format

```
conformance/
  jian/pass/   jian/fail/   jian/run/
  wen/pass/   wen/fail/   wen/run/
  yong/pass/   yong/fail/
  patch/      roundtrip/  golden/
```

- `pass/` files must check with no errors.
- `fail/` files carry header lines `# expect: E501 at 14:9`, one per expected diagnostic. Exactly those codes must be reported, at those positions, and no others.
- `run/` files carry `# stdout:` blocks and optionally `# exit: 101`. They must produce exactly that output on every executor.
- `patch/` cases contain a module, a patch and the expected result or P-code.

### 20.2 Required coverage

| Area | Minimum |
| --- | --- |
| Lexing and layout | every lexical rule; each lenient normalization N01–N11 has an input and expected canonical output |

| Types | inference, records, sums, newtypes, generics, traits, coherence (E220), method resolution (E250) |

### 20.3 Golden programs

G1 is hello world (`io.print`), G3 is the portfolio program in 12.5 with `fake_net`, and G4 is a word count over `fake_fs`. G2, below, parses trades and computes volume-weighted average price:

```
class Trade:
    sym: str
    px: float
    qty: int

class BadLine:
    line: str

def parse_line(line: str) -> Result[Trade, BadLine]:
    p = line.split(",")
    if len(p) != 3:
        fail BadLine(line=line)
    px = p[1].parse_float() else fail BadLine(line=line)
    qty = p[2].parse_int() else fail BadLine(line=line)
    return Trade(sym=p[0], px=px, qty=qty)

pub def vwap(ts: list[Trade]) -> dict[str, float]:
    ex vwap([Trade(sym="A", px=10.0, qty=1), Trade(sym="A", px=20.0, qty=3)]) == {"A": 17.5}
    var acc: dict[str, tuple[float, int]] = {}
    for t in ts:
        n, v = acc.get(t.sym) else (0.0, 0)
        acc[t.sym] = (n + t.px * float(t.qty), v + t.qty)
    return {s: nv[0] / float(nv[1]) for s, nv in acc.items()}
```

`p[0]` through `p[2]` compile because the length check proves the bounds.

Panic kinds, reported as `panic(kind): message`: `overflow`, `div_zero`, `contract`, `exclusivity`, `bounds`, `shape`, `unreachable`, `assert`.

## 21. Decision log, non-goals, open questions and glossary

### 21.1 Decision log

| Decision | Chosen | Rejected | Reason |
| --- | --- | --- | --- |
| Structure | one core, two surfaces | two separate languages | one checker and one ecosystem; ecosystem size drives model performance |
| Jian surface | typed Python 3.12 shape | a novel token-minimal syntax | general models score near zero on unfamiliar languages; one repair round outweighs a 12% token saving |
| Jian precedence | Python's, with parentheses for confusable mixes | no precedence | rejecting `a + b * c` guarantees repair loops for no safety gain |
| Memory | value semantics with unique ownership, explicit Rc/Arc and second-class views (v0.3) | tracing GC; borrow checker with lifetimes | deterministic and fast, with no lifetimes for people or models to get wrong |
| Effects | second-class capabilities, no effect variables | row-polymorphic effects | sound without effect variables; static handlers compile to direct calls |
| Failure | typed results (`fail`, `?`, `else`) | exceptions | every failure path is in a type |
| Determinism | default, nondeterminism only through capabilities | best-effort | enables exact replay, caching and reproducible tests |
| Indexing | proven in Jian; checked at run time in Wen | runtime checks everywhere | off-by-one becomes a compile error for models; people keep ergonomics |
| Verification | Dafny-style auto-active, optional, cached | mandatory proofs; interactive provers | models verify best in auto-active style; hard algorithms still fail often |
| Edits | whole-item patches with hash bases | line diffs | no drift, no ambiguous anchors |
| Item order (Jian) | author order, additions appended | sorted | least surprising for people; patches stay simple |
| Implementation language | Rust | others | mature parser, codegen and runtime ecosystem (`salsa`, `rowan`, Cranelift, LLVM bindings, `arrow`) |

**v0.2 decisions.**

| Decision | Outcome | Reason |
| --- | --- | --- |
| Keyed hashing behind insertion-ordered maps | Accepted | Defeats hash flooding at no cost to determinism |
| Associated types without GATs | Accepted | Iterator inference needs them; GATs cost Rust years |
| Non-reentrant actors by default | Accepted | Swift's reentrancy default produced lasting logic bugs |
| Bounded-only channels and mailboxes | Accepted | Unbounded queues turn overload into memory exhaustion |
| No install scripts; attestations verified by default | Accepted | xz backdoor and npm worms |
| Pure contract predicates; no ignoring unproven `pub` preconditions | Accepted | C++26 contracts failed on vague semantics |
| Deterministic solver limits | Accepted | Keeps proofs and the hash-keyed cache reproducible |
| UTF-8 strings without integer indexing | Accepted | Indexing UTF-8 by integer is either wrong or O(n) |
| 64-bit checked `int` default | Kept | `bigint` added as the escape route |
| Panics abort the process (R5); isolation is a process boundary | Kept | "Let it crash" works; FFI and `py` boundaries convert |
| Per-pair FIFO actor delivery | Kept | Matches Erlang; no cross-sender ordering is promised |
| Clamping slices in Jian | Kept | Matches Python; a lint and `slice_exact` cover the risk |
| Unbounded channels | Rejected | See bounded-only above |
| Backtracking regex in std | Rejected | Linear time only; backtracking lives in a separate package |
| Native object serialization | Rejected | A third or more of Java's vulnerabilities |
| A global contract-violation handler | Rejected | One violation path only |
| Shell strings as the default way to spawn processes | Rejected | Injection; `proc.spawn` takes argv |
| GATs, WASM components, `std.i18n` | Deferred | Reconsidered in M3 or M4 |
| Free-threaded `py` parallelism as the default | Deferred | Waits on CPython making free threading the default |

### 21.2 Non-goals

- No null, exceptions, inheritance, implicit conversions, or operator overloading outside the listed traits.
- No macros. Compile-time code is ordinary Yong, and only in Wen.
- No `async`/`await`.
- No tracing garbage collector, no implicit reference counting and no language runtime (v0.3).
- No formatting options.
- No Unicode identifiers, and no localized keywords.
- No hiding of remoteness: distribution is visible in capabilities and failure types.
- No optional features or conditional dependencies in 1.0 (v0.3 R22).

### 21.3 Open questions

1. Resolved in v0.2: associated types are adopted as type members only (section 9). Generic associated types stay out; v0.3 R12 resolves them as not needed.
2. GPU code generation from `par for` bodies through MLIR (M4).
3. Resolved in v0.3 (R9): generators compile to state machines; there are no fiber stacks.
4. Resolved in v0.3 (R1): there is no implicit sharing; Arc is explicit.
5. Whether Jian's remaining non-Python constructs (`uses`, `pre`, `post`, `ex`, `var`, `take`, `fail`, `&`) need synthetic fine-tuning data to reach parity with Python on pass@1. v0.3 R14 sets the plan.
6. Every token-cost claim must be re-measured against the target models' own tokenizers.

### 21.4 Glossary

| Term | Meaning |
| --- | --- |
| Yong (永) | the core semantics, its IR, and the toolchain |
| Jian (简) | the surface written by language models |
| Wen (文) | the surface written and read by people |
| capability | a second-class value granting an effect, such as `io` or `net` |
| canonical text | the one printing of a program that the formatter produces |
| item | a top-level declaration: function, type, trait, impl, constant or test |
| item hash | BLAKE3 hash of an item's canonical Yong text |
| lenient reader | the Jian front end mode that accepts and normalizes listed deviations |
| L0–L6 | the layers of depth, from the surface (L0) to the machine (L6) |
| place | an access path: a variable followed by fields and indices |
| projection | rendering an item in the other surface, or the borrowed view `a[i]` (by context) |
| spec gate | the two-phase protocol: contracts checked before a body is written |
