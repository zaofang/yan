# R567 lowering candidates answered 2026-11-04

Answered by Antonio on question cards for `docs/reports/r567-lowering-candidates.md`. No spec rows yet; rows are allocated in the PR that implements each.

1. A one-character string literal types as `char` when the other side is `char` (literal-only, like integer literals in 3.4). Variables stay strict. `float * int` stays an error. Appending a `char` is `str.push(c)`.
2. `"a" in xs` with `xs: list[char]` or `iter[char]` is E201, as `==` is. Done together with item 1.
3. `xs = []` without annotation stays E241; the diagnostic gains the fix `xs: list[T] = []`. No new inference.
4. E210 is relaxed: positional arguments are allowed when a function has exactly two same-typed parameters. Changes 14.1 and 15.3. This was not the recommendation (keep and document in the primer). Rows: R800.
5. W806 stays an error. Audit it on base cases (`n == 0`, empty list) that no `ex` names; a false positive there is a checker bug.
6. Add free prelude functions `ord(c) -> int` and `chr(n) -> char fail`, plus `divmod` and `pow(a, b)` over `//`, `%` and `**`. Needs a row in 17.2. Rows: R801.
7. A tuple whose fields share one type may be iterated, as `list[T]` in order. Heterogeneous tuples stay an error.
8. `iter[T]` stays non-indexable. The diagnostic says an `iter` is not indexable and to use `.collect()`.
9. Add `str.count(part)` and `char.is_digit()` if missing. E200 points `re` / `regex` at `std.regex` and prelude `map` at `list.map` / `iter.map`; the `iter.len` error says `.count()`. Untyped-lambda E017 cases (candidate 9) resolve with this.
