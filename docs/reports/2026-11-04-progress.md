# Progress report, 2026-11-04

Read against main `5bfd39c` (#175). Numbers marked "measured" were produced for this report from a
release build of that commit; everything marked "estimate" is a judgement.

## Summary

- **Pace.** The project is six calendar days old (spec v0.3 frozen 2026-10-30, first commit the same
  day). Main has 282 commits and 175 PR numbers. The 1.0 Roadmap placed M0 at months 3 to 12 and M1
  at months 12 to 21. M0 conformance is green and M1 conformance is at 88%, so against the calendar
  the project is far ahead.
- **The central bet is not yet won.** The M1 gate (R567) asks that Yan Agent beat typed Python on
  pass@1 and on tokens. The one probe run so far (one model family, Sonnet 5.5, 50 dev tasks) ends
  with Yan Agent green on 26/50 (0-shot) and 29/50 (5-shot) against Python's 50/50, and with token
  ratios of 1.02x to 1.29x Python on the jointly green tasks. The gate needs both ratios below 1.0.
  The benchmark harness the gate is defined on (MultiPL-E or LiveCodeBench, three families) is not
  built.
- **On track?** Estimate: on track for the implementation milestones up to M1b in shape, off track on
  the gate, and at risk on scope. The spec doubled in five days (229 KB to 466 KB, 446 new rows), while
  three conformance families (semver, pkg, ub) pass almost nothing.

## Risks (estimate)

- **Gate risk.** The token claim is the product. Current data says Yan Agent costs 2% to 29% more
  tokens than Python on the tasks both solve, from one family and n=26 to 29.
- **Spec outpacing code.** 446 rows and 17 named surfaces in five days for one part-time developer.
  Every accepted RFC adds conformance work only Antonio can write.
- **Silent gaps.** `yan check` once exited 0 on unsupported constructs; E017 (R649) now reports them,
  but `law 1` fails 63 cases and native code leaks.
- **CI gates M0 only**, so M1 and M3 regressions are not caught automatically.
- **Single runner.** CI runs on one self-hosted Mac (#150 cut its load).
